# Corilo 可里产品设计

v0.14 · 2026-10-21 · 个人记忆与行动助手方向。当前是目标设计，实施状态见技术设计。

## 定位

帮助个人记住资料、结合背景思考、形成待办并安排提醒的云端助手。笔记是资料载体，不是全部产品。用户在桌面、Android 和 iPhone 浏览器登录，编辑同一份服务端知识库，也可让 Agent 阅读、整理、追加和改写资料。手机无需安装 Node、Termux 或启动本地服务。

核心原则是“用起来简单，离开也容易”：不要求用户搭建分类、数据库和工作流；已保存资料可查看、纠正并完整带走。

核心体验保持“说清目的，Agent 完成文件操作，再打开结果继续编辑”。完整 Files.md 编辑器与 Pi 默认工具继续复用；不要求用户先选分类、目录和处理模式。普通讨论不自动保存成笔记。

## 首期范围

| 能力 | 首期选择 |
|---|---|
| 开放范围 | 邀请制小范围使用，每个账号一个独立知识库，不开放公共注册 |
| 笔记 | 普通 Markdown 与附件，完整编辑器、文件浏览和搜索；支持导入、导出 |
| 对话 | 服务端 Pi、在线模型初期 DeepSeek、工具进度、停止、跨设备查看和继续会话 |
| 记忆与行动 | 分阶段实现可追溯、可纠正的记忆，待办和一次性提醒；外部日历与周期调度后置 |
| 多设备 | 登录后访问同一份云端文件；版本检查保护同时编辑，不做实时协同编辑 |
| 客户端 | 响应式网页；桌面 Chrome、Android Chrome、iPhone Safari 为首期验收对象 |
| 运行环境 | Linux 服务端执行 Pi；用户执行环境相互隔离，任务按需启动并有额度限制 |
| 数据保护 | 云端版本历史、独立备份、用户导出；GitHub 不再是使用前提 |
| 离线 | 首期在线使用；未确认保存的当前页面草稿保留，不承诺完整离线编辑与同步 |

平台范围是计划，不能据网页存在就声称移动端体验通过。PWA 安装体验可后补，不阻塞浏览器使用。

## 保留与改变

保留 Files.md、Pi 原生模型配置与工具、原话保存、文件结果卡、普通文件格式。配置由服务端管理，用户不需要在手机运行 Pi `/login`；不新增用户密钥或模型管理表单。

暂停桌面启动器、Android 内置运行时和 APK 交付。原代码保留为历史实现，不自动删除用户已有目录或迁移知识库。GitHub 双向同步退出首期主流程，后续可作为可选导出或备份集成，不能把它当多设备访问机制。

## 取舍

不在首期加入公开注册、团队共享、多人实时协作、支付、插件市场或不受控后台自主任务循环。保留上游 checklist/Later 等基础编辑能力，不恢复旧 Bot 与 Worker。待办、一次性提醒和日程属于新方向，按阶段建设，不再永久排除。

仍不改造 Pi 默认文件工具为逐文件审批或事务框架。提示词约束行为，执行环境负责隔离用户和限制资源；这两者用途不同。服务商可以读取云端知识库，没有端到端加密；用户发起 AI 请求时相关对话和工具读取内容发送给模型供应商。

商业化前需实测活跃任务成本、恢复能力和用户隔离，核对实际依赖许可。初期邀请制验证使用价值，不预设免费无限 AI。

行为规则与验收只在 [PRODUCT-SPEC.md](PRODUCT-SPEC.md) 维护。
