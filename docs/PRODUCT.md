## 1. 产品定位与哲学

**可里是一个本地优先的个人知识与行动助手。像给自己发消息一样留下想法，助手帮助找回背景、整理知识、安排下一步；内容始终是自己的 Markdown 文件。**

产品解决的不是“笔记软件还缺哪些功能”，而是用户需要亲自维持“新信息—当前理解—下一步行动”的连续性：信息存了找不到，想法没有沉淀，事情没有安排，使用 AI 又要搬运材料、重复解释背景。

沿用原用户确认哲学：**你负责自然表达，助手负责理解、归拢和安排。具体工作交给专业工具，知识与决定始终由你掌控。**

核心标准不变：**信息可以越来越多，需要你操心的事情应该越来越少。**

Files.md 是体验与实现复用的参考，不是可里的功能总表。可里不是“给 Files.md 加一个日历”，而是补上能利用个人资料的文字助手，以及与知识相连、本机可工作的行动安排。上游可确认事实和差距见技术稿第 2 节。

首个用户仍是产品作者本人，先以技术学习、研究和个人项目验证。其他人群需求、持续使用意愿和付费意愿尚待真实使用；不以“所有人的第二大脑”作为首版实现范围。

## 2. 产品模型与内容自主权

用户只需要理解自己的内容和要做的事。内部仍由 **Agent + Skill + 本地上下文** 支撑；Skill 是助手完成一类工作的可复用方法，不是要求用户配置的工作流平台。

| 组成 | 产品责任 |
|---|---|
| 自然输入与对话 | 接住原话，回答问题，承接调整，反馈真实结果 |
| 本地知识库 | 保存资料、想法、理解、决定及明确任务属性；普通 Markdown 也能直接使用 |
| 文字助手 | 在允许范围内查找、解释、比较、总结、局部改写，并把选定结果写回 |
| 行动安排 | 管理同一任务的状态、计划日期、截止、一次提醒与来源；Today 帮助查看 |
| 可选同步 | 让设备交换已保存的内容；不成为本地编辑、搜索或提醒的前提 |

Markdown 是真实内容，不是退出产品时临时生成的摘要。任务、来源、日期和状态有公开可读的表达，索引和业务视图不能另存一份用户无法理解的真相。普通笔记不因接入应用就被要求填写大量属性；只有需要稳定身份、来源关系或行动能力时才补必要标记，并让用户看到变更。

本地使用不需要可里同步账号。关闭 AI、不开同步或网络中断时，仍能阅读、编辑、查找、处理任务和使用已支持的本机提醒。远程模型是否可用取决于其自身网络与认证，不因内容本地保存就承诺离线推理。

同步、AI、通知分别授权。用户可以只用本地文件，也可以开启同步；可以不开同步而调用远程模型，也可以开同步却不开 AI。退出同步账号不删除本地文件或本机有效提醒。

## 3. 核心体验

### 3.1 先接住表达，不先要求整理

打开应用进入自然输入与助手对话。用户可留一句话、粘贴文字或 URL，手机可接收系统分享。无需先选目录、项目、类型或 Skill；仅保存的轻量操作仍可用，不因为页面叫“对话”就每次调用模型。

同一个入口不代表所有输入具有同一种保存含义：普通问题留在会话；明确记录保存原文；知识结论在用户要求时写回；有明确行动时才形成任务。只有影响正确执行的歧义才需要追问。不自动把每条聊天变成 Markdown 复选项，也不要求用户先选“聊天/笔记/任务”模式。

### 3.2 找回已有背景，再继续思考

用户可以问“上次为什么没选方案 A”。助手查看允许使用的资料，给出可打开的依据，区分记录的事实、当时的判断与本次推断。资料冲突并列说明，资料不足不编造；只有 URL 就不能假称读过全文。

用户可以直接打开引用继续手改，再回到同一段对话。下一次请求使用更新后的本地内容，不把旧上下文当成当前事实。

### 3.3 把知识与下一步行动接起来

用户说：“把今天实验的结论补进方案比较；明天验证内存占用，明天下午三点提醒。”

助手保留原始交代，找到相关内容，提出需要核对的改写和行动。用户可以只保留笔记、只保留任务，或保留全部。一组被选中的结果可靠地本地保存后，再同步和安排本机通知。

示例回执使用已经消歧的绝对日期和日程时区：

> 已更新《方案比较》，并保存“验证内存占用”任务。计划为 2026-09-18，提醒为当日 15:00（Asia/Taipei）。本地已保存；云端待同步；本机提醒已安排。

这是产品行为示例，不是已执行结果。没有成功安排通知时就必须改写对应状态。

### 3.4 让事情适时出现，不让用户搬运它

任务在笔记、全部任务、Today 和项目中保持同一身份。到期靠查询和提醒呈现，不将任务移出原处或复制回聊天。完成后保留背景并清理提醒；普通笔记不因提到日期就进入 Today。

需要安排的是“什么时候做、最晚什么时候完成、什么时候提醒”，不是首版就建立时间块、排程算法和完整日历系统。任务内容本身可独立存在，没有日期也成立。

### 3.5 随时接管，轻量而完整

常规侧边栏提供目录、笔记、搜索、任务与今天。手动编辑不依赖模型；操作后回到原对话，不增加“手动模式”按钮。可以保留 Files.md 的简洁页面与编辑体验，不要求为了新品牌先换框架或全面重画。

## 4. 首版范围与交付形态

| 能力 | M0 必须交付 | 明确不自动带入 |
|---|---|---|
| 输入 | 文字、URL、备注、本地持久接收与系统分享 | 图片、附件、语音识别、网页全文抓取 |
| 笔记 | 普通 Markdown 导入、阅读编辑、目录、新建、重命名、移动、删除 | 完整 Obsidian 插件兼容、图谱、多编辑器并发协作 |
| 组织找回 | 关键词搜索、笔记链接、反向链接、简单标签、轻量项目关系 | 强制分类体系、通用知识图谱、必须向量化全库 |
| 助手 | 跨笔记问答、解释比较、局部修改、选定结论写回、多行动提取；四类内置方法 | 多 Agent 编排、技能市场、任意 shell、后台自主改写 |
| 行动 | 未完成/完成/取消/恢复，计划、截止、一次提醒，Today、全部任务、来源 | 重复任务、估时、优先级、子任务、时间块、冲突排程 |
| 本地与同步 | 无账号本地完整使用；一种可选同步服务；冲突保留和删除传播 | 强制云端主库、多同步后端、任意外部云盘并发写入保证 |
| 自主与恢复 | 可查看修改前内容、可核对变更、可靠保存与完整导出 | 完整版本历史、回收站、跨对象一键撤销 |
| 多端 | 同一响应式 Web 应用，由桌面和手机容器承载 | 独立 RN 业务 UI、首次启动必须加载远程网站 |

桌面与所选手机平台共同验证完整流程。Android 仍是优先验证候选，实际首发平台、支持版本和分发方式在原型验证后冻结，不能以一个移动画面宣称已支持某平台。容器框架是技术选择，不改变“一套页面”的产品要求。

纯浏览器分发、系统日历联动及重复安排可作为后续方向；本轮不把它们列为 M0 承诺。Files.md 的习惯、媒体、Bot 和重复安排等能力不因源码存在就自动成为可里需求。

**原型不是缩水后冒称完成的 M0。** 可以先验证本地输入—知识更新—行动安排；完整 M0 仍需通过可选同步、目标容器和通知的全部相关验收。

## 5. 产品原则

**同一份内容，两种操作方式。** 用户手动与助手操作遵守同一保存、身份和关系规则。

**明确意图，适量确认。** 简单、明确、已授权的小操作直接给出结果；正文改写、推断安排、批量整理和删除先核对，已确认的具体内容不反复批准。

**先保护内容，再优化流畅度。** 不丢原话、不隐藏半组写入、不静默覆盖、不重复创建。来源可查看，修改前内容可找回。

**知识与行动各自成立。** 不把所有想法任务化，不为了生成数量补任务，也不为了列表整齐删除背景。

**轻的是用户负担，不是安全要求。** 不把运行步骤、Skill 数量、审批中心、同步细节堆到首屏；错误和风险在需要时明确出现。

## 6. 成功标准

用真实技术学习或项目资料持续使用至少两周，与直接手工完成同一流程比较：记录、查找、等待、核对、改写、搬运任务与纠错的总成本是否下降；数日后能否找回当前结论和未完成行动，而不重新解释背景。

保留少量“问题—使用资料—实际操作—后续复用”的样例，并完成一次本机完整导出核对。额外比较 Files.md 基础体验与新增助手后的收益，不能以新增功能数量证明派生开发值得。

不以聊天轮次、生成字数、任务数量、连续签到或 Inbox 清空率衡量成功。任何内容丢失、越权、虚构来源、静默覆盖、不可恢复误改都先修复，再考虑增加功能。

## 7. 路线与本轮变化

已明确的产品方向是本地优先、可选同步、自然输入优先与统一 Web UI。本轮据 Files.md 讨论进一步收敛“轻量工作区＋受控文字助手＋本地行动安排”。

实现建议是先基于 Files.md 做隔离的小范围派生原型，尽量复用页面与编辑器，再决定长期维护 fork 还是提取局部模块。没有要求先重写成 React、重做 Go 服务或同时接入多个 Agent。此为实施路线，不是上游已满足规格的证明。

英文名 Corilo、中文名「可里」已由用户确认；开源范围、发布许可、收费与同步提供商、最终模型、完整外部 Vault 兼容和系统日历集成仍待另行决定。技术比较和阶段任务只在技术稿维护，不散落为多个产品版本。
