# Corilo 可里产品方案

v0.34 · 2026-11-11（Asia/Taipei）。本轮恢复独立任务与日程产品方向。下述为目标设计；运行代码仍是 notes 0.7.0 与 todos 0.5.2，日期、日历和提醒尚未实现。细则与验收唯一来源为 [业务规格](PRODUCT-SPEC.md)。

## 定位与体验

Corilo 是个人自部署的笔记、任务与日程助手。用户在 Linux 小主机保存资料，用电脑或手机浏览器安排每天要做的事，也可以让 Harness 原生 Agent 操作相同资料。日常记录和安排不需要模型。

采用一个 Harness、两个业务插件：Files.md 工作区负责笔记、资料、收集和日记；独立任务与日程插件负责行动、截止、日历安排及后续提醒。保留 Files.md 的完整菜单和清单能力，同时提供专门的任务管理界面。个人任务不会因 Agent 的内部执行计划而自动生成。

用户应能从一条会议笔记建立“周五前提交方案”的任务，在周四下午安排一个准备时间块，并在周五的会议日程中关联同一笔记。任务完成、安排时间和会议结束各有自己的含义。

## 核心对象

| 对象 | 用户问题 | 示例 | 权威数据 |
|---|---|---|---|
| 笔记 | 我要保存什么资料 | 会议纪要、想法、参考附件 | Markdown 与普通文件 |
| 任务 | 我要完成什么 | 提交方案，可有截止但不必有时间 | 任务插件 SQLite |
| 日程 | 什么时间有安排 | 周五 14:00–15:00 评审会 | 任务插件 SQLite |
| 任务时间块 | 什么时候做这个任务 | 周四 15:00–16:00 准备方案 | 日历条目关联任务 |

Markdown 复选框继续作为文档内容，不默认复制到任务数据库。用户明确选择“建立任务”才形成关联。两个存储各有职责，不做双向全文同步；用户可以导出结构化数据与日历数据。

## 首个可用版本

目标不是恢复一个只能勾选的小列表，而是交付完整的个人安排流程：

- 独立任务入口：收集箱、今天、未来、全部任务及完成／取消记录；快速新增、搜索、详情编辑、完成和重新打开。
- 计划日期与截止日期分开；可将任务安排到日历，支持一项任务多个时间块。
- 日历支持月、周、日和议程列表；定时事件、全天事件、时间冲突提示、拖动改期及键盘／表单等价操作。
- 笔记与任务／日程关联；从笔记创建任务时保留来源，返回笔记不丢失未保存输入。
- Harness Agent 能查询任务与日程、按明确指令新建及调整；普通界面操作零模型调用。
- 旧 SQLite 保留、升级显式执行，Markdown 清单不自动迁入；提供结构化导出和升级回退路径。

首版不显示“可靠通知已启用”。重复事项、持久提醒中心、跨设备推送分后续阶段做完整，不能用内存计时器或浏览器弹窗充数。

## 参考项目与复用决策

| 参考 | 借鉴重点 | 本方案选择 |
|---|---|---|
| [Vikunja](https://github.com/go-vikunja/vikunja) | 完整任务详情、日期、筛选与多视图组织 | 借鉴任务体验，不引入其整套后端与独立账号 |
| [Super Productivity](https://github.com/johannesjo/super-productivity) | 今日计划、任务安排到一天中的体验 | 借鉴个人规划，不在首期增加工时统计和番茄钟 |
| [Nextcloud Calendar](https://github.com/nextcloud/calendar) 与 [Tasks](https://github.com/nextcloud/tasks) | 事件与任务区分、日历互通 | 用作后续 CalDAV 兼容参考，不依赖 Nextcloud 部署 |
| [Tasks.org](https://github.com/tasks/tasks) | 移动端任务编辑与提醒表达 | 借鉴手机交互，不引入 Android 原生客户端作为首期依赖 |

这是交互与架构参考，不表示已经复用其代码。当前已有 Harness 认证、插件界面和 SQLite 服务，继续扩展比同时维护第二套服务更适合个人自部署。开源组件的具体版本、许可与兼容性在实现前核对并锁定。

## 交付顺序与成功标准

| 阶段 | 交付 | 完成后用户能做什么 |
|---|---|---|
| A 任务与日历 | 双插件入口、任务日期、日历与时间块、关联、Agent、导出、显式升级 | 完整安排一周并在手机查看修改 |
| B 重复与提醒中心 | 简单重复系列、单次例外、持久站内提醒、重启补偿 | 维护例行事项，回到应用能查看到期提醒 |
| C 设备与互通 | 经选择的通知渠道、真实设备验收、ICS 与后续 CalDAV | 在支持的设备收到通知，与外部日历交换资料 |

阶段按可验收结果推进，不把阶段 A 的日历称为阶段 B／C 已交付。完整验收包括并发编辑、断线回执、时区边界和升级保留资料。首期不做团队协作、公共注册、复杂项目依赖、甘特图、自动排程、外部订阅服务或重写 Agent。

主机使用本地磁盘，NAS 先作备份；远程访问、真实设备部署和通知渠道仍需对应环境验收。具体阶段细则见业务规格，模块与迁移设计见 [技术方案](TECHNICAL_DESIGN.md)。
