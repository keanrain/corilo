## 当前决策

- 桌面、Android、iPhone 使用同一响应式网页；无需本地 Agent 或独立启动服务。
- 每个受邀账号独立知识库；普通 Markdown 和附件保存在云端持久目录。
- 保留完整 Files.md、Pi 默认工具/配置和在线模型；初期 DeepSeek。
- 多设备登录访问同一云端内容，使用版本检查处理同时编辑；GitHub 不再负责客户端同步。
- 用户执行环境隔离、任务和用量受限；不另造逐文件审批或 Agent 文件事务。
- 首期不做公开注册、团队协作、支付、完整离线模式或原生客户端；记忆、待办与一次性提醒分阶段加入，外部日历后置。

## 本轮设计细化

[技术设计第 12–16 节](TECHNICAL_DESIGN.md#12-四项设计的共同边界) 汇总四路审查：默认 Pi bash 经普通 CLI 调用领域 API、可追溯记忆模型、一次性事项/提醒调度、完整资料包与空库恢复。对应业务行为见 [规格第 6 节](PRODUCT-SPEC.md#6-简单使用与资料自主)，界面状态见 [交互设计](DESIGN.md#记忆与事项交互细化)。

这些是方案，不是新增功能或已通过验收。本人邮件与明确委托优先的记忆策略是建议；未开通服务、发送通知或选择付费套餐。技术实现仍先完成文件基础和隔离 Pi，不因设计补齐跳过这些前置条件。

## 成熟组件选型

[技术设计第 17 节](TECHNICAL_DESIGN.md#17-成熟组件选型与接入边界2026-10-21) 汇总四路并行复核：身份操作复用 Supabase 官方 SDK、保留当前 HttpOnly 应用会话；首期保留 Runs/PostgreSQL，不叠加通用队列；Docker 为首个执行后端，后续验证 gVisor；部署选 Caddy/Compose，备份选 restic + S3 兼容存储。R2、Resend 和监控服务属于候选，未开通或承诺免费额度。

这些是选型与待接入方案，本轮没有安装新依赖、迁移会话或部署服务。内部 worker 的启动/停止与文件写入协调已有实现和实际容器检查，模型出口及任务额度已有内部实现，已通过单任务 socket 连接 worker；邀请开通、认证邮件和备份恢复仍须分别验证。
