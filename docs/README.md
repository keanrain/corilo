## 当前决策

- 桌面、Android、iPhone 使用同一响应式网页；无需本地 Agent 或独立启动服务。
- 每个受邀账号独立知识库；普通 Markdown 和附件保存在云端持久目录。
- 保留完整 Files.md、Pi 默认工具/配置和在线模型；初期 DeepSeek。
- 多设备登录访问同一云端内容，使用版本检查处理同时编辑；GitHub 不再负责客户端同步。
- 用户执行环境隔离、任务和用量受限；不另造逐文件审批或 Agent 文件事务。
- 首期不做公开注册、团队协作、支付、完整离线模式或原生客户端；记忆、待办与一次性提醒分阶段加入，外部日历后置。

## 当前实现

`app/host/` 保留完整 Files.md + 本机 Node/Pi/Git 开发链路；`app/cloud/` 新增邀请制文件服务，详见下方最新实现记录。方向切换时已更新正式设计与开发边界，并把 Android Actions 改为仅手动触发；当时没有实现云端登录、隔离或部署。阶段完成条件见技术设计第 8 节，最新进度见第 11 节。

云端验收使用 N01–N19。旧本地 C01–C21、Android 检查、原型和模型替身的测试结果不能自动转为新方向验收。

[v0.12 完整基线与历史证据](https://github.com/keanrain/corilo/tree/e25edb9/docs) 保留在 Git 历史。`android/`、`prototype/`、`p0/` 和旧同步实现不删除，但不继续扩展为当前主路线。根 [README](../README.md) 中开发命令仍只运行旧本机链路。

最新实现：现有开发页支持知识库 ZIP 导出，包含普通文件、附件、空目录及校验清单，不含对话/任务/日程或凭据；不是完整账号备份。云端登录、记忆与提醒尚未实现。

云端阶段 1 已接入邀请兑换、持久会话与按账号路由的文件服务，入口与限制见 [云端说明](../app/cloud/README.md)。真实 PostgreSQL 和 Chromium 链路通过，Supabase 使用响应替身，未部署；Pi 执行隔离、账号自助开通与完整生命周期未完成，不能据此宣称云端全验收通过。
