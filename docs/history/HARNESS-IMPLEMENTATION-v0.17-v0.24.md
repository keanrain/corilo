v0.24 · 2026-11-08。用户决定以 DeepSeek Harness 为主体，Corilo 开发笔记、事项/日程插件，优先个人自部署。产品规则唯一来源为 [PRODUCT-SPEC.md](../PRODUCT-SPEC.md)。此文件保留各轮当时的状态、判断和测试证据；后轮可能替代前轮的限制。当前模块职责见 [技术设计](../TECHNICAL_DESIGN.md)。

## 当前架构

```text
桌面 / 手机浏览器（IndexedDB/idb 保存按知识库隔离的恢复草稿）
    → DeepSeek Harness Web（会话、模型设置、默认 Agent 与工具）
        → Corilo 笔记插件：普通 Markdown、原话保存、版本检查
        → Corilo 待办插件：个人 todo、SQLite、版本/幂等保护
        → 后续日程/提醒：event/reminder、持久调度与通知
        → 后续记忆插件：来源、纠正、遗忘
常开主机本地 Markdown 工作目录 + Harness 自有状态
    + 知识库外的 Corilo stateRoot/history.git（本机历史/回收站）
    → restic 笔记级独立备份（本地合成恢复已测；NAS/完整实例待验收）
```

不叠加第二个 Pi loop、Corilo 模型配置页、云端队列/租约或逐文件审批。外部插件通过 Cordis 配置与公开服务扩展；Harness 默认工具、会话、安全策略由底座提供。插件管理的文件版本检查不覆盖默认 bash 或任意外部写入，不宣称跨进程文件事务。

## 首轮插件与依赖

独立包位于 plugins/notes，依赖与锁文件隔离于旧根 package.json，避免把旧应用升级为另一套运行时。采用 Harness 0.2.2-rc.1 公开包 API；上游为开发者预览，npm dist-tag 不作为兼容性保证。外部插件可加载不代表未来版本无破坏变更。具体安装/挂载方式及真实执行证据见插件 README 与测试。

首个服务提供配置目录内的 Markdown 列表、读取、带版本保存和原话捕获；工具层复用同一服务。原话捕获直接写文件，调用服务本身不请求模型。上游普通文件工具继续保留。接口拒绝越界/隐藏路径、链接、特殊文件和超限；不新增 Pi 风格的文件保护框架。笔记 Web 页面已通过公共客户端扩展点接入，同一插件实例的页面与工具共用一个 NotesStore。

现有 app/host、app/cloud、Files.md vendor、Pi 会话、PostgreSQL 状态和 Android 代码保留。普通文件可以由用户显式选择为插件知识库；不自动上传、迁移凭据、重放旧任务或将 Pi 会话当 Harness 会话。旧公共任务入口仍禁用。

## 笔记页面实现与证据（2026-11-08）

`plugins/notes/package.json` 声明 `dsh.client` 与 `./client` 导出；固定 esbuild 0.25.12 生成与 Harness 0.2.2-rc.1 匹配的 lazy-CJS factory bundle。React 和草稿 store 使用宿主平台模块，不打包第二份运行时。客户端通过公开的 `main` 与 `sidebar.panellist` slot 增加笔记页面，不修改 Harness 源码或 CSP。`npm test`、`npm pack` 自动构建，直接启动前执行插件 `npm run build`。

宿主通过 `ctx.connection.fetch.register` 注册四个 `/api/corilo-notes/*` 精确 POST 路由，沿用 Connection 的认证、Host/Origin 和 owner 校验。浏览器同源 Fetch 传递 JSON，文件读写由宿主服务执行，四个工具与页面闭包共用同一 NotesStore。未添加模型调用、账号、密钥输入、第二套权限或 Agent loop。

页面提供列表/文件名搜索、读取、新建/编辑、仅保存原话，显示未保存/保存中/已保存/失败/冲突。冲突预览不会覆盖草稿；可另存，或明确放弃草稿并采用读到的版本，后续保存仍检查版本。请求失败不自动重试，丢失响应可能意味着文件已提交，提示先核对。首轮草稿仅页面内存保留；现已由下一节的 IndexedDB 持久恢复机制替代。浏览器 textarea 的换行规范化不等于逐字节文件编辑；存储 API 的 BOM/CRLF 精确保留保证继续有效。当前仅中文页面与文件名搜索，不宣称全文搜索。

实际通过：独立插件原 6 项 Node 检查、旧应用 59 项 Node 检查、三套旧应用浏览器回归。新增 `plugins/notes/test/browser.py` 在隔离临时 HOME/XDG_CONFIG_HOME/DSH_HOME 与虚构资料下启动发布版 `dsh web`，用真实 Chromium 操作外部插件页面，验证原话直接落盘、编辑保存和 pending、外部版本冲突预览/另存、路径错误和网络失败草稿保留、切换面板保留草稿、两个页面访问同一文件、重载恢复、390px 窄屏布局与中文编辑、认证与 Host/Origin 拒绝和非法参数。没有任何模型或外部网络请求。新增浏览器 CI 步骤；本地通过不代表远端 Actions 通过。

## 并行可靠性与独立分发（v0.18，2026-11-08）

这轮只推进笔记可靠性与分发，不展开事项、提醒或记忆。复用固定版 Harness、idb 8.0.3、系统 Git 和 npm；未创建第二套 Agent loop、编辑器框架、账号服务或任务调度底座。

- **持久草稿**：通过 idb 使用 IndexedDB，按宿主知识库身份和独立页面 ID 隔离。重新加载后明确恢复/丢弃，不自动写回文件；恢复保留原 expected 版本。离开笔记到其他 Harness 面板后仍有未保存离开警告。身份未确认或根已切换时阻止旧页面继续操作；浏览器存储失败时明显提示，可在身份已确认后直接保存文件。恢复副本仍受浏览器站点数据、设备与 origin 限制，不是独立备份。
- **本机恢复**：可选 stateRoot 必须与正文目录分开且不能互相包含，通过根绑定标记防止串库。Git ≥2.36 的独立 bare 仓库保存检查点及回收站引用，不修改用户 .git、不联网、不执行 hooks、不读取用户 Git 配置或外部对象目录。管理变更前保存当前内容，恢复版本检查当前版本；回收站恢复只新建、不覆盖。历史前 100 条明确 hasMore，回收站每页 100 条、使用稳定 ID 游标继续读取，按 ID 恢复不依赖完整列表，私有目录检查上限 20000 项。没有自动裁剪、保留期限或硬磁盘配额。
- **准确回执**：文件系统与 Git 历史不是一个原子事务。文件已提交但历史/回收站确认失败时返回明确的部分完成消息和 committed:true，不伪造回滚、不自动重试。默认工具和外部编辑器的中间版本不承诺连续记录；下一次 Corilo 管理变更可保存其当前内容。
- **共同服务**：页面新增历史预览、恢复、回收站和不覆盖恢复入口。配置 stateRoot 后注册 6 个恢复工具，总计 10 个；未配置时保持原 4 个工具。所有入口复用同一 NotesStore 队列。API 的根身份请求头会在文件操作前校验，旧页面不能静默写到新根。
- **独立分发**：corilo-notes init/check/start 复用 npm 包和固定 dsh 启动器，检查 Node/Git/底座版本、客户端构建、目录边界与状态绑定；init 独占创建配置，不覆盖、不迁移资料。Harness 改为固定运行依赖，独立安装不需要全局 dsh、源码或 esbuild；首次安装依赖仍需要 npm 网络。包保留 private，未发布 npm、未部署或更改仓库可见性。

验收：17 项插件 Node 测试通过，含真实 Git 持久化/恢复/取消/部分完成/危险状态拒绝、真实 Harness 工具管线，以及 npm pack 后在仓库外仅装生产依赖的 CLI 检查与真实 dsh web 启动/鉴权/退出。三套真实 Harness Chromium 流程分别覆盖原笔记页面、持久草稿恢复与换库/存储故障、历史预览/冲突恢复/回收站不覆盖。旧应用 59 项 Node 测试与三套旧浏览器回归通过。全部使用虚构资料，没有调用真实模型或开通通知服务；远端 Actions 状态单独确认。

本轮覆盖 H12–H14 的已测范围及 H01–H04 的相关流程；真实手机、真实 DeepSeek、远程部署、独立备份/NAS、事项/提醒/记忆仍未验收。本机 Git 检查点不能替代 H11 的完整资料与独立备份恢复。

## v0.18 复查修复（2026-11-08）

回收站原先超过 1000 条会同时阻断列表与按 ID 恢复。现改为每页 100 条、稳定 ID 游标与明确 hasMore/nextCursor，支持在游标记录已恢复后继续分页；已知 ID 直接核验对应引用、原路径及历史祖先，不枚举完整回收站。页面与 Agent 工具均可继续取下一页。真实 Git 的 1001 条夹具覆盖分页不重不漏、非首屏 ID 恢复和禁止覆盖，真实 Harness 页面覆盖“加载更多”与超千条恢复。

草稿初始化原先直接调用仅安全上下文提供的 crypto.randomUUID，普通 HTTP 来源会在页面注册前失败。现复用 uuid 11.1.0 的浏览器 getRandomValues 回退，构建时内联并附 MIT notice。真实非安全 Chromium 来源已验证可构造草稿运行时；实际发布版 Harness 的草稿恢复、冲突与换库测试另在随机 UUID API 缺失情况下通过。该证据不等于远程网络、TLS 或手机真机部署验收。

## v0.18 多角度复查记录（2026-11-08）

此次复查在上述两处修复后进行，覆盖用户价值/体验、恢复可靠性、性能和独立分发维护。另发现原路径被超限正文、无效 UTF-8、目录或链接占用时，回收站页因读取原正文而整体失败；现改为不进入链接的逐层元数据占用检查，权限阻塞也按不可用路径处理。恢复到占用路径仍拒绝，恢复到新路径成功，原内容/目标保持不变。

当时发现的事项如下；本轮对应处理见后续 v0.19 记录：

1. **浏览与找回**：累计正文扫描超过 8 MiB 或目录条目超过 2000 时，当前列表整体拒绝，页面没有分页/按路径打开的后备入口。9 篇各约 960 KiB 的合成笔记可复现列表失败、单篇读取正常。限制保留，但应增加有界元数据浏览/直接打开路径；不要只提高总扫描阈值。仅文件名搜索无法找回时间戳/UUID 命名的原话正文，下一阶段先核实 Harness 现有搜索扩展，优先复用成熟全文检索（如 ripgrep），规模需要时再评估 SQLite FTS5 与中文查询策略。
2. **交互连续性**：“新笔记”当前要求明确丢弃当前草稿或取消，缺少“保留草稿并捕获另一条”的直接路径；恢复草稿列表只有文件名/时间，多个未命名草稿难辨认；历史前 100 条之后只有提示、没有继续浏览入口。这些是现有能力缺口，不代表已保存文件或 Git 历史丢失。
3. **性能瓶颈，已实测**：Git 每个子命令都完整检查恢复目录，读取 100 条历史需 102 个 Git 进程/全树检查，回收站页 100 条需 101 个。公共操作共用队列，所以慢历史查询会阻塞其他页面的读写。优先复用 Git cat-file --batch 有界批量读取并协调检查，不直接删掉安全校验。自动 Git 维护关闭后缺少无删减压缩入口，宜复用 Git repack/pack-refs；不自动决定清理历史或保留期限。
4. **新手分发**：独立 tarball 与生产依赖启动已测，但 Node/Git/npm、三个绝对路径及 Harness 自带模型 onboarding 仍偏开发者流程。优先补中文最短安装/无模型使用引导，继续使用 Harness 扩展，不另造账号或模型管理。

性能证据来自 Node 24.19 / Git 2.52 / Linux tmpfs，201 篇约 800 KiB 笔记，3 次中位数。1000 packed refs 时：列表约 70 ms、读取 0.23 ms、修改保存 46 ms、历史 100 条 548 ms、回收站 100 条 618 ms；同样 1000 loose refs（恢复目录仅 1059 项）时：列表 74 ms、读取 0.25 ms、保存 254 ms、历史 4247 ms、回收站 3413 ms。一次读取排在历史之后实耗 3158 ms。数值只用于本环境比较，不外推到物理主机、手机或 NAS。源码 checkout 可运行 npm --prefix plugins/notes run benchmark 复现实验；只使用并清理临时虚构资料，不是 CI 时间阈值。

源码脚本在占用检查修复后另一次完整复跑：1000 loose refs 时，历史 100 条约 3205 ms，回收站页约 3482 ms，排队读取约 3547 ms，完整目录 1060 项。两轮都复现秒级阻塞；各轮数据分别保留，不把单一环境延迟当作产品性能承诺。

最终功能验证：20 项插件 Node 测试通过（含仓库外生产依赖安装/启动），3 套真实 Harness Chromium 回归及 1 套非安全来源浏览器能力检查通过；旧应用 59 项 Node 和 3 套浏览器回归通过。新增占用路径回归覆盖超限/损坏内容、目录、链接和权限阻塞，确认原占用不变且可恢复至新路径。该段保留当时证据，当前完成情况与边界见下节，不以通过测试数量代替用户价值判断。

## v0.19 收敛修复与当前实现（插件 v0.2.0，2026-11-08）

- **大库浏览与找回**：新页面和 corilo_notes_browse 通过 library.mjs 读取纯路径/大小元数据，每页 100 条，稳定路径游标；不为浏览读取全库正文或计算全部版本。20 层/20000 条/10 秒的扫描上限仍明确存在，并提供不依赖列表成功的按路径打开。原 corilo_notes_list 保留旧有完整版本列表和 2000 条/8 MiB 限制以兼容调用，不再作为新页面入口。
- **正文搜索**：复用固定 @vscode/ripgrep 1.18.0 及其 npm 平台二进制，不再要求用户另装系统 rg。安全服务先检查路径并读取 UTF-8 正文，通过 stdin 给 rg 搜索，rg 不重开知识库路径；没有持久索引或模型调用。字面查询最多 256 字节、搜索正文最多 64 MiB、10 秒/取消预算、最多 100 条带行号/片段的结果，截断明确提示。用转义后的字面模式消费一整行，只输出每行首次匹配位置，避免常见字符产生重复匹配明细；位置输出有 64 KiB 上限。
- **连续记录**：新建、打开其他文件和恢复另一草稿时，先以 IndexedDB 事务将当前草稿保留到独立 UUID 记录，成功才切换。失败保留原编辑器及恢复记录。候选显示正文摘要与只读预览，不自动写磁盘。复用原版本冲突/CAS 规则，无第二套临时编辑状态服务。
- **历史批读与更早页**：Git cat-file --batch-check/--batch 有界读取元数据，保留对象类型/大小/UTF-8、路径/引用/祖先和私有目录检查。首屏 100 条历史从 102 次 Git/完整检查降至 4 次，回收站页从 101 次降至 3 次；历史游标页支持继续读取更早版本。没有简单删除安全校验来换速度。
