## 1. 先验证复用，不从零搭大系统

### 1.1 三种选择及顺序

先在测试库运行原项目，建立输入、编辑、打开重开与文件变更的行为基线；在派生分支接入最小本地存储桥、一次只读 Agent 问答和一次任务创建。比较修改面、测试成本与现有体验是否得以保留。

首选是保留页面和编辑器的派生原型。若写入入口能够收口、目标 WebView 可用且补丁可维护，继续作为 fork；若模块耦合或系统桥接成本过高，提取已验证的局部页面/编辑模块。只有实际阻碍被证明无法合理解决时才替换相应模块，不以技术栈不熟悉作为全面重写理由。

不同时维护“原 Files.md 可写应用”和“新续页可写应用”共享一套正式文件。原型可保留只读对照副本，真实写入只能启用一条链路。

### 1.2 本轮不做

不建立泛化 Agent 平台、技能市场、多引擎管理台、独立向量服务或微服务体系。不上来就重做图谱、习惯、媒体库、Telegram Bot、重复任务或完整日历。不把原项目支持某个扩展视为本项目必须重新验收并对外承诺。

基础编辑与搜索不依赖模型；本地读写与通知不依赖同步；手机不依赖一台常开的桌面 Agent。需要补的可靠性是内容使用本身的一部分，不因“原型”二字跳过。

## 3. 最小模块与运行边界

建议在现有仓库上渐进增加少量模块，而不是先拆成多个可发布包：

```text
web/                         # 保留的页面、样式、编辑器与既有脚本
  xuye/
    content/                 # parse / patch / 关系与业务校验
    commands/                # 唯一写入口、预览、回执
    query/                   # 本机查找、任务与 Today
    agent/                   # Pi 适配、上下文、4 类内置方法
    sync/                    # 可选同步客户端
    platform/                # 小型容器能力适配
src-tauri/                   # 候选容器，文件恢复/凭据/通知等桥接
server/                      # 优先保留可复用 Go 宿主；仅启用必要同步路径
  xuye-sync/                 # 建议的新版本协议，不让旧 Bot 并发修改正式库
tests/                       # 基线、领域、故障、容器与双端测试
```

这是建议目录，不是已存在的代码。新业务模块可用 TypeScript，保留脚本经一个明确的 JS facade 调用；是否引入打包器取决于 Pi 与容器构建需要，不以此要求全站迁移框架。

依赖方向：`同一 Web UI → Command/Query → 共用内容领域层 → 平台持久化桥`。Agent 读取经 Query，写入只提议变更再交给 Command。同步下载也经校验和同一本地提交，不直接覆盖文件。

| 责任 | 唯一拥有者 |
|---|---|
| 笔记/任务语义、时间、来源、删除影响 | 共用 JS/TS 领域层 |
| 本机一致提交、预览批准、幂等 | CommandService 与一个库写入协调者 |
| 路径权限、实际持久化、崩溃日志 | 容器原生桥，逐平台验证 |
| 模型循环与工具事件 | 一个内置 AgentAdapter，不含业务写库特权 |
| 云端复制与版本检查 | 可选 SyncClient + SyncService |
| 当前设备通知与系统权限 | NotificationAdapter，不持有另一套任务 |

M0 同一库先限制一个活动业务窗口。原生锁保护本应用实例，不能声称锁住不合作的外部编辑器。长模型请求、解析和检索不占用文件写锁。

## 4. 内容格式：普通文件优先，属性按需

### 4.1 身份与原文分开管理

普通 Markdown 导入或阅读不注入 front matter，不改文件名、行尾、空格或未知字段。为兼顾稳定身份与低污染，建议使用一个**公开且随库导出的身份清单**保存文档 ID 与相对路径；它属于用户内容元数据，不是可删除的查询缓存。关系、任务状态和时间仍保留在对应 Markdown 的可读表达中。

```text
Vault/
  任意用户目录/…/*.md
  .personalos/
    vault.json              # 格式版本、vaultId、日程时区、documentId→path
    history/…               # 仅要求保留的最近一次 AI 修改前内容
```

品牌改成续页不需要同时改协议。此处继续使用既有建议前缀 `personalos` 和 `.personalos/`，避免纯改名引入迁移。若此前没有真实数据，这只是新原型格式选择；有旧 `personalos.id` 时沿用并校验清单一致性，不全局替换字符串或重复分配身份。

身份清单按条目表达，导入、创建、移动和删除均随同组提交更新。普通笔记标题默认取文件名，H1 是用户正文，不强制同步。已有明确标题字段保留并按版本规则读取，不新写重复标题。清单里的 ID 使同名内容不被误合并；用户可从路径和文本理解关系，不需要应用解码内部编号。

丢失 SQLite 索引可从文件和公开清单重建；**丢失清单不是“删缓存”**。有嵌入 ID 的文件可帮助恢复，其他文件只能重新核对身份，不假称无损恢复。必须将清单加入导出、备份、同步和文件恢复测试。

外部只移动普通文件而不更新清单时，先提示路径变化，不仅凭相同内容 hash 自动认定身份；重复文件可能拥有相同字节。正式应用内移动则维护同一个 ID 和受支持关联。

### 4.2 正式任务建议格式

仅明确启用的行动加稳定任务标记。标题和状态只存正文一处，必要时间和关系放命名空间，不另在数据库维护权威副本。

````markdown
---
personalos:
  schema: 1
  tasks:
    "33333333-3333-4333-8333-333333333333":
      planned: "2026-09-18"
      due: {kind: date, value: "2026-09-20"}
      reminder:
        at: "2026-09-18T15:00:00+08:00"
        timezone: "Asia/Taipei"
      sources:
        - id: "22222222-2222-4222-8222-222222222222"
          title: "实验记录"
          path: "../实验/实验记录.md"
---

# 方案比较

本次结果已经记录，后续再验证内存占用。

- [ ] 验证内存占用 <!-- personalos-task:33333333-3333-4333-8333-333333333333 -->

下面是资料中的示例，不是正式任务：

```text
- [ ] 不执行此项
```
````

这是设计 fixture，来源 ID 指向测试库中的已存在文档，不是当前用户真实资料。无日期任务不要求建立空属性表；普通笔记完全可以没有上述头部。主项目、来源、捕获时间/处理状态、项目目标只在需要时以公开字段保存；任务不自动继承承载笔记的项目和来源。

正文 `[ ]` 为未完成，`[x]`/`[X]` 为完成，`[-]` 为取消；取消标记是本产品扩展，不宣称通用 GFM 语法。任务标记必须位于允许的列表项，代码、引用和普通 HTML 中出现相同字符串不执行。单纯复选框不是正式任务。

重复 ID、属性指向不存在任务、无效时间、不支持 schema 或命名空间冲突必须报告，不跳过坏字段后报成功。完成/取消清提醒，恢复不重开；这些由领域层执行，不靠模型重写。删除标记或包含该任务的正文，要按删除影响核对。

### 4.3 局部修改与外部坏内容

解析同时保留 AST/词法片段和源码范围；字段修改采用范围 patch，不把整篇 YAML/Markdown 重新序列化。范围统一为 UTF-16 code unit 的半开区间，hash 使用 UTF-8 实际字节。中文、emoji、组合字符、BOM、CRLF、未知 YAML 注释都要有黄金样例。

应用内无效业务编辑保留草稿、阻止错误正式提交。外部已写入的坏字节不能被应用丢弃或替换；标记受影响文件为待核对，停止无法确定的任务与 Agent 自动写回，核对并取消不再可信的本机提醒。其他普通笔记仍可工作。

原生层执行提交前必须核对源/目标 hash。应用内约束不等于跨进程文件事务；同时运行旧 Bot、其他同步器或外部编辑器写同一库，不属于 M0 保证。

## 5. 本地提交、恢复和幂等

### 5.1 不变量与持久材料

编辑器、聊天保存、任务表单、导入、同步应用和通知动作共用一个写入协调者。每组提交包括正式文件、身份清单、关系修改、必要 AI 修改前内容以及可重建投影；SQLite 只保存运行登记和查询投影，不能证明多个 `.md` 文件天然原子替换。

库外按 vault 保存状态数据库、提交日志、before/after 暂存与待同步快照。身份清单和规范历史在库内。运行日志、冲突材料和同步 outbox 都有恢复用途，不可统称缓存后随意清空，也不直接同步正在使用的数据库/WAL。

```text
准备：读取来源/目标 → 编译候选 → 校验与预览 → 必要时确认
获取库写入锁；阻止该组半成品被 UI / Agent / 导出 / 同步读取
核对 operationId、请求摘要、授权代次、来源/目标 hash、目标路径和影响集合
持久写入 before/after 与 PREPARED 日志
持久写入 APPLYING 决定
逐文件安全替换 / 创建 / 删除；验证实际 after hash
登记同组投影、localSeq、回执、run 结果及必要的不可变 outbox
持久标记 COMMITTED；开放同一版本视图
锁外：按本地结果核对通知；启用同步时再尝试上传
```

确认后不再让模型生成一遍实际写入内容。索引可以重建；成功登记、恢复日志与尚未上传的字节不只是索引。原生桥负责目标平台的实际持久性，必须测磁盘满、崩溃与掉电边界；不能仅凭调用 write/rename 返回就声称零丢失。

### 5.2 恢复状态必须可解释

| 发现状态 | 行为 |
|---|---|
| PREPARED 之前中断 | 没有正式内容修改；保留输入，不报保存成功 |
| PREPARED 但无 APPLYING | 放弃暂存或重新核对；不得视为已完成 |
| APPLYING 后仅部分文件变更 | 逐项判断 before/after 并安全推进；未恢复前不开半组正式状态 |
| 文件已完整而索引/回执未登记 | 从日志登记同一 operationId，重建投影，不生成第二批任务 |
| 已 COMMITTED 但页面未收回执 | 还原原回执并读取当前结果，不重做命令 |
| 某文件既非 before 也非 after | 保存真实字节和日志，报告恢复冲突，不覆盖外部修改 |

保证的目标是应用内一致可见、崩溃后可恢复，不是对任何外部编辑器提供多文件原子快照。APPLYING 后出错可能是“恢复中”，不能一律报告“已全部回滚”。

### 5.3 前提、批准与去重

operationId 由应用生成并先持久登记，不能拿模型每次新生成的 toolCallId 替代。请求摘要覆盖 vault、命令、选中项、明确时间和读取版本。相同 ID/不同摘要拒绝；同 ID/已提交回放事实。更改用户意图或重核新的差异后产生新操作号。

来源发生变化也会使旧提议过期，即使目标没变。移动/删除/合并提交时重算关联影响，多出的未批准文件返回 PREVIEW_STALE。单纯改标题、路径或排版不产生新任务身份。

确认记录由本地可信控制层签发或登记，绑定确切计划、范围与文件前提；模型不能提交 `approved:true` 来获得权限。用户修改草稿不再调用模型，但必须重新计算当前预览和确认摘要。

最近 AI 修改前内容和 outbox 引用必须有清理规则。操作登记长期只留去重摘要与结果 ID，不永久保存已删除的全文；恢复完成后才能清除不再需要的暂存。

## 6. 内置文字助手：一个引擎，自己的工具

### 6.1 Pi 是优先验证，不是文字质量冠军

沿用上一轮的 Pi agent-core + pi-ai 原型候选。其官方说明提供工具执行、事件、上下文转换与可配置流接口 [C01–C02]，便于注入产品自己的方法，而不是嵌入完整 coding CLI。实际文字效果仍由具体模型、上下文、工具和任务共同决定。

不加载默认 bash、任意文件写、任意 SQL、外部命令或自动插件安装。dsh、Codex、Claude 宿主只作为后续可选适配方向，本轮不新增比较 UI、常驻服务要求或全部引擎实现。保留小接口而不是搭建通用多 Agent 平台。

Pi 在共用 JS Worker 的具体入口、打包和网络适配必须实测。官方浏览器能力有认证和 provider 例外 [C02]；不把 Node OAuth、CLI 子进程或 Node SQLite 会话后端塞进手机 WebView。模型凭据通过原生安全存储和受限网络桥使用，或经用户单独授权的模型网关；不开同步也可调用模型。

### 6.2 工具与文字工作方法

| 工具 | 输出与边界 |
|---|---|
| `search_content` | 当前授权范围的匹配片段和真实内容引用，不上传全库 |
| `read_content` | 当前文件 hash、允许的文本范围、可打开来源 |
| `list_tasks` / `get_relations` | 同一领域查询的任务、Today 和关系，不另造模型记忆 |
| `propose_changes` | 有来源和版本前提的提议，不返回虚假的“已保存” |

四类内置方法保持输入整理、知识整理、阅读与思考、任务与安排。方法可使用仓库内受控 Markdown 与小 manifest；资料中的 AGENTS.md 只是一种内容，不替代应用授权。用户不必选择 Skill 或理解工具链。

应用先持久接收输入，根据请求选择回答、记录或候选变更。普通讨论只在会话中；明确保存的输入可用捕获记录引用而不复制原文。直接执行策略只放行操作类型、目标与内容均明确的小操作；改写、推断时间、批量组织或删除先展示差异。不仅凭模型置信度判断授权。

### 6.3 来源、回复与暂停

引用来自实际读取结果的文档 ID、hash、range 和可读标题/路径；应用分配 citationId，模型只能引用已提供的 ID。不存在的引用拒绝，旧版本不能拿当前相同位置冒充。来源冲突并列，事实与推断分开；只有 URL 的资料不足以支撑全文结论。

回执使用本地提交事实，不由模型自行宣称完成。分别表达本地保存、同步和本机通知；必要时展开差异与来源，不默认重发整篇笔记。

```text
本机接收 → running → awaiting_input / awaiting_confirmation
                   → committing → completed
                   → completed（仅问答）
                   → paused / failed
恢复：先核对 operationId → 当前文件 / 授权 / run 代次 → 用户继续
```

每个 run 只有一个本机执行者和递增代次。挂起/关闭时不承诺后台持续推理；迟到响应在写入前重核范围和版本。另一设备查看已同步会话不等于自动接管运行、批准或工具调用。未确认编辑和租约不作为可执行状态同步。

同一 UI 从对话到笔记再返回保留会话锚点；新消息不能悄悄覆盖一组待确认内容。限制上下文字节、模型步数与工具返回量；达到上限说明剩余内容，不只保存第一项却报全部完成。

### 6.4 文字评测安排

沿用六类固定任务，每类至少三例：跨笔记问答、限定段落改写、资料合并、长对话接续、多个行动提取、中断/部分接受。原型优先固定同一模型版本与工具、上下文、采样和预算；无法固定时标记为“模型＋引擎”的组合测试。

记录引用核对、事实错误、原口吻保留、人工修改量、遗漏、等待、确认与纠错成本。不提供未测分数；虚构来源、越权、静默覆盖或不可恢复丢失任一出现，阻止真实资料写入。

## 7. 小型行动层与本机提醒

计划日期、日期型截止、绝对时刻、IANA 日程时区使用不同类型。相对时间以本次明确参考时刻与用户确认时区解释；缺上下午、夏令时不存在/重复时刻须消歧。不能用设备本地时区或 `new Date("YYYY-MM-DD")` 隐式改写计划日期。

任务状态、时间、来源都从公开内容解析。Today 是纯查询：未完成且计划、截止或提醒落在今天及之前的任务去重展示；积压与未来计划分别说明，昨日未做不自动改日期。日期型截止按该日结束判定，不在当日零点报逾期。非今日页只显示所选日已有属性，不伪造历史状态。

到期不复制任务到 `Chat.md`；正文中的同一任务持续存在。完成/取消清提醒，恢复不重开，修改计划/截止不自动移动提醒。重复规则与日历事件不进入本轮数据模型。

通知按本机已提交内容安排，标识至少包含 vault、安装实例、taskId 和提醒指纹/本机代次。指纹来自实际时间与任务状态，不用另一设备本地 revision 判断有效性。投影重建不重新触发已消费提醒。

打开、回前台、本地提交、接收同步后：核对权限和系统实际通知 → 取消失效安排 → 安排允许的未来项 → 保存真实结果。重试不得产生同一提醒副本。已实际安排而登记未落库的崩溃窗口由系统枚举对账；安排成功不保证用户一定看见通知。

完成和稍后提醒可离线执行，但先检查当前任务、库、指纹与冲突状态，走统一本地提交后才改系统通知。稍后时间以用户确认时刻计算，重试复用绝对目标，不每次往后推。旧动作不能覆盖后来改过的提醒。

Tauri 通知能力存在平台差异 [C04]，定时、动作、重启恢复、权限、勿扰和数量限制必须单独测试或补少量原生代码。冲突版本不生成第二组活跃通知；受冲突影响无法判定的提醒暂停/取消并准确报告。其他设备尚未同步仍可能通知，不保证远程即时撤回。

## 8. 可选同步：复用宿主，不继承错误语义

### 8.1 只落地一个服务

先复用上游 Go 服务的适用网络/部署结构作为候选宿主，不为同步另造常驻 Node 知识 API。本轮建议为新版协议增加一个小型事务存储，原型使用单实例 SQLite 保存版本清单与小文本传输对象；这是新设计，不声称上游已经有此结构。正式选择以体积、备份和组提交验证为准，不同时建设 SQLite/PostgreSQL/R2 多后端。

云端只存复制用版本，不参与本机正常编辑、检索和提醒。原项目旧文件同步、配置写入、Bot 和 Worker 不能同时操作续页远端库。不能沿用“时间戳新就合并并覆盖”的策略来处理业务任务。

建议最小远端数据为：`remote_vaults(binding, epoch, head)`、`sync_commits(opId, requestHash, baseHead, newHead, manifest, payload)` 和必要的删除/去重记录。完整组及 head 在一个服务端事务提交；不假装跨文件逐次写入等于事务。

### 8.2 初始绑定与内容范围

用户主动选本地库、同步账号和远端库。初次上传、连接两个已有库、下载新副本是不同动作，先预览身份、路径、重名与差异。同名库或相同目录不自动授权上传；换账号不改变既有绑定。

正式同步范围为 Markdown、公开身份清单、必要关系属性、日程时区和规定的最近 AI 修改前内容。已提交的会话可独立作为非知识记录同步；活跃 run、批准、未提交草稿、密钥、索引、系统通知登记不复制。

M0 建议完整复制知识文本，不做占位按需下载。初次未完成时明确可用范围，不能报告全库已可查。仅本地模式不生成无用的云 outbox；首次启用从明确快照建立基线。

### 8.3 传输协议

| 操作 | 必须核对 |
|---|---|
| push：binding / epoch / syncOpId / expectedHead / manifest / payload | 授权、体积、hash、组完整性、基线；同 ID 不同摘要拒绝 |
| 查询 syncOpId | 超时先检查是否已接收，不新建第二组 |
| pull(afterHead) | 返回完整提交组与删除，组内不拆页，只有本地完整应用才推进游标 |
| snapshot(head) | 返回一致版本的清单和所引用字节，不能普通分页混用不同 head |

outbox 引用不可变正文/快照，不只存当前路径和 hash，否则之后编辑会改变待上传字节。顺序上传同一链，ACK 持久绑定到相应组；本地继续编辑产生后续组，不原地改已发 payload。已同步表示本设备已确认的版本，不等于每台设备已应用。

下载组先暂存校验，再经第 5 节恢复协议落地、更新本机投影和通知。不完整/未知不前进游标；恢复中也不上传本地半组。

### 8.4 冲突、删除与退出

M0 保守地保留双方，暂停该库待协调的同步链，而不是静默 LWW 或把两份任务行都作为有效结果。普通无关本地编辑仍可做；受冲突影响的自动写回与提醒先停用。解决时核对完整依赖、当前本机 hash 与远端 head，形成新的解决组，旧已发送/结果未知的操作先查询。

不能比较两台设备的 localRevision 或设备时间认定新旧。身份清单并发变化同样需要协调，不能为了减少冲突而猜测文件身份。后续才根据实测收益增加无交集自动合并，不首版上 CRDT 或通用实时协作。

删除传播有版本的 tombstone；离线旧端不得自动复活已删内容。过保留窗口设备返回 RESET_REQUIRED，显式重建基线；不能按缺失的一页清单推断删除。冲突材料置于非活动区域，导出时单独标记，不启动第二组任务/通知。

本地删除后，处理尚未上传的旧正文链：先核对未知远端结果，再用新的同步操作号合成相对已知基线的差异；不把旧操作 ID 绑定到新字节，不继续发送已被替代的敏感正文。恢复日志引用未释放前不强删必要恢复材料，但它们不作为用户可访问历史暴露。

关闭同步/退出账号保留本机内容与有效提醒；删除远端库不发送“本地全部删除”。删除同步中的单篇笔记才属于内容删除并传播。移除本机副本与删除远端分别确认。同步不是备份；服务端访问边界和清理期限在提供服务前公开。

## 9. 一套 Web 页面与薄容器

保留可复用页面，新加聊天结果、预览和任务视图也使用同一前端；桌面和手机只调整布局，不复制业务逻辑。Tauri 2 是优先容器候选，官方支持已有 Web 前端及桌面/移动目标 [C03]；但这不证明 Files.md 当前脚本在目标 WebView 中无修改可用。

资源随容器打包并检查依赖加载路径。无网络首次启动必须能完成本地保存；需要远程下载的字体、脚本或动态资源必须明确替代/打包策略并检查许可。不能把“在线网页能打开”当作容器离线验收。

原生桥只提供按库授权的读写/恢复、安全凭据、受限模型网络、分享接收、通知和生命周期，不开放任意 shell、SQL 或任意路径。模型看不到原生桥，只有白名单领域工具；远程页面在无特权外部视图打开，不能继承本地权限。

接收其他 App 的分享与向外分享是不同能力，目标系统可能需要扩展/原生入口；交接后的正式输入流程仍复用 Web。尚未选库时使用可恢复的本机交接队列，不静默绑定云账号或自动执行分享正文。

实际文件授权、自有目录、外部目录挂载、中文 IME、软键盘、安全区、返回手势、长文性能、Worker 挂起与升级迁移都要逐端测试。若 Tauri 必要能力不能合理补齐，再评估保持同一 Web 构建的其他容器，而不是回退独立 RN 页面。

## 10. 导入、导出与删除

### 10.1 原文优先的接入

Files.md 的普通 `.md` 通过现有导入预览接入，不修改原始库。Chat/Later/日记作为原始资料，复选框和旧到期配置不自动启用；用户选定行动后才分配任务 ID、核对来源和时间。对未支持的配置、图片或专用链接保留引用并说明，不报完全导入成功。

普通 Markdown 文件正文可以逐字不变，文档身份登记在公开清单；只有真实启用业务时才添加必要字段。重复路径给出跳过、另命名、明确替换；重复 ID 要明确新副本或替换关系，不按相似标题去重。每批提交走统一操作，超过安全预算的导入先说明分组，不隐藏部分成功。

在原型库禁用上游 Bot/Worker/旧同步写入，不能对用户真实库边读取边迁移。若已有生产数据，先取实际 schema 和样本、备份并验证恢复、在副本转换和对账；没有旧数据时不为假想迁移编造脚本。

### 10.2 导出的是本机事实

锁定一个短暂本地一致快照，复制有效正文、身份清单、公开格式说明和规定历史后再打包。包含本地已保存而未同步的内容，不要求上传；明确其他设备未到本机的内容不在快照内。冲突材料独立非活动目录，不与正文混成双份任务。

导出排除凭据、未提交编辑、运行缓存和已删除正文。关系包含可读路径/标题，不只剩 UUID。普通工具能读 Markdown，索引删除后可重建正式业务；跨应用完整兼容未测试时不宣称无损往返。

### 10.3 删除覆盖所有入口

删除计算内含任务、独立来源、主项目、链接、提醒及恢复副本。可先把内含任务带原 ID 移到独立承载文件，再同组删除笔记。仅以笔记为来源的独立结果不连带删除，标明来源已删。

清理受影响的 AI preimage、工具缓存和可访问来源摘录；完整旧 preimage 会泄漏已删任务时也要清理。混合助手摘要无法安全移除被删资料时隐藏该条依赖消息并说明；用户已明确保存到独立笔记的结论按 SPEC 保留。

同步/恢复日志只保留必要 ID、hash 和版本，不做长期隐藏回收站。云备份、已下载文件和离线其他设备有不同可控边界，不承诺远程立即清空所有副本。复制修改前内容恢复是新编辑，不跨对象撤销后续任务或其他端结果。

## 11. 应用自有接口轮廓

下面是用于模块拆分和类型检查的建议，不是声称已存在的 SDK/API。实际入口仍需运行时 schema、权限、路径和版本验证。

```typescript
type Id = string;
type Hash = string;
type DateOnly = string;
type Due = { kind: "date"; value: DateOnly }
  | { kind: "instant"; value: string; timezone: string };
type Reminder = { at: string; timezone: string };
type TaskPatch = {
  title?: string;
  description?: string | null;
  status?: "open" | "completed" | "cancelled";
  planned?: DateOnly | null;
  due?: Due | null;
  reminder?: Reminder | null;
  projectId?: Id | null;
};
type Expected = { documentId: Id; path: string; sha256: Hash | null };
type Command =
  | { type: "document.create"; id: Id; path: string; markdown: string }
  | { type: "document.append"; id: Id; text: string }
  | { type: "document.replace"; id: Id; markdown: string }
  | { type: "document.move"; id: Id; path: string }
  | { type: "document.delete"; id: Id; preserveTaskIds: Id[] }
  | { type: "task.set"; id: Id; patch: TaskPatch }
  | { type: "task.delete"; id: Id };
type ChangeSet = {
  protocolVersion: 1;
  vaultId: Id;
  operationId: Id;
  scopeVersion: number;
  expected: Expected[];
  items: { id: Id; dependsOn: Id[]; command: Command }[];
  selectedIds: Id[];
};
type Receipt = {
  operationId: Id;
  localSeq: number;
  changedIds: Id[];
  local: "saved";
  sync: "off" | "pending" | "confirmed" | "conflict" | "failed";
  notification: "not_requested" | "pending" | "scheduled" | "denied" | "failed";
};
type AgentInput = { runId: Id; vaultId: Id; userText: string; scopeVersion: number };
type AgentEvent =
  | { type: "text"; delta: string }
  | { type: "evidence"; citationIds: Id[] }
  | { type: "proposal"; proposalId: Id }
  | { type: "stopped"; reason: "done" | "confirmation" | "paused" | "failed" };
interface AgentAdapter {
  run(input: AgentInput, signal: AbortSignal): AsyncIterable<AgentEvent>;
}
interface CommandService {
  preview(change: ChangeSet): Promise<{ previewId: Id; digest: Hash; affectedIds: Id[] }>;
  commit(previewId: Id, trustedApprovalId?: Id): Promise<Receipt>;
  lookup(operationId: Id): Promise<Receipt | "not_committed" | "recovering" | "unknown">;
}
```

任务创建通过内容构造器生成含唯一标记的目标文件 patch，再交给同一文档命令；不提供独立写 task_projection 的捷径。字符串类型不等于合法日期/UUID；`expected.sha256 = null` 只表示已批准的新建目标应不存在，不是允许覆盖任意旧文件。

结构化错误至少区分 VALIDATION_FAILED、VERSION_CONFLICT、PREVIEW_STALE、IDEMPOTENCY_MISMATCH、SCOPE_DENIED、RECOVERY_REQUIRED、RESULT_UNKNOWN、LIMIT_EXCEEDED。页面保留输入和定位，不让 SDK 错误泄露凭据或越界内容。

## 12. 安全、迁移与观测

外部资料不可信，包含指令也不能扩大权限。Markdown 禁用可执行 HTML/危险 URL；外部图片/嵌入不默认联网；CSP 与原生桥权限同时限制。YAML 限制体积、深度、展开和自定义可执行标签。来源范围在读取和发模型前检查，不能只在 UI 隐藏按钮。

模型密钥不进入 bundle、localStorage、Markdown、日志或同步。首次远程 AI 说明实际提供商、范围与数据处理；同步另说明服务端可读范围。TLS、系统凭据存储、账号隔离与备份恢复是基本要求，不因此宣称端到端加密、零保留或绝不训练。

为原型冻结上游 commit、引擎/依赖版本和原生构建工具；升级先做兼容迁移和数据副本核对，失败不得清库。旧 protocol/schema 先识别再显式迁移，不靠品牌替换影响已有绑定。

日志默认记录 operation/run、错误码、阶段耗时，不记录正文、完整提示词和工具原文。指标分别测输入接收、模型等待、确认、持久化、同步、通知和人工纠错；不写未实测的延迟、成本或容量承诺。

优先使用真实个人资料规模的脱敏测试库。明确单文档、组大小、模型步数和 outbox 预算；触限解释剩余范围，不能截断后报成功。前端测试与真实文件系统、双端同步及系统通知证据分别记录，不互相替代。

## 13. 可执行实施顺序与复用决策

| 阶段 | 要交付的验证结果 | 退出条件/不能冒称 |
|---|---|---|
| P0 上游与关键风险 | 固定 commit；原版独立运行；列全写入口；同一页面进桌面/手机候选容器；文件持久/恢复、Pi 流、通知/分享可行性小样例 | commit 已通过 GitHub 固定；部分源码/调用链已验证；完整 checkout、原版、容器仍未完成。详见第 16 节 |

### 16.3 新候选：读取未知不得变成删除

[0002-fail-closed-sync-scan.patch](../p0/patches/0002-fail-closed-sync-scan.patch) 改两个函数，不重新设计整个同步协议：

- 分类器把“路径被观察到”与“正文可读取”分开。状态 error、异常、无效状态、返回路径不符、修改结果缺正文都阻断本轮批次，不上传其中看似正常的部分。
- 内存目录缺失的删除候选，在原版 `exists()` 上进行只读磁盘核对。文件仍存在表示目录状态不完整，停止本轮；权限错误或句柄异常同样停止，不能当作 NotFound。
- 文本同步排除范围同时用于本地和远端比较：媒体、日志和两个独立处理的编辑器路径不被误列为文本删除。
- 删除候选超过原有 20 项保护阈值时停止，不再清空已确认的同步基线。
- 批同步调用方捕获扫描失败，释放 `isSyncingFiles`、记录未发送原因并退出。此时尚未调用 `post` 或修改同步快照；后续清除故障可重试。

候选代码放在 [分类器](../p0/candidates/delete-guard/collectModifiedAndDeletedFiles.function.js) 和 [调用方](../p0/candidates/delete-guard/syncFilesWithServer.function.js)。检查器验证生成的 patch 与实际接受测试的函数完全一致，防止“测的是另一份实现”。

**保守代价：一次扫描不完整会暂停这一轮批同步，包括健康文件的上传。** 本机文件和编辑不被回滚；下一次完整扫描再发。这是原型安全补丁的取舍，不是新的产品同步协议，也不是宣称 UI 已经显示完善的错误恢复流程。
