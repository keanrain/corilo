# Corilo 可里业务规格

**简体中文** | [English](PRODUCT-SPEC.en.md)

## 当前交付范围

普通内容编辑不得丢弃已到期但尚未处理的提醒；取消／完成和显式改提醒时间可失效原提醒。持续跨日的任务时间块应出现在其覆盖的今天／未来日期，起止采用半开区间。日历任务选择必须可加载超过 100 条的记录。

todos planner 提供：任务日期／截止／优先级／清单／状态、六个任务视图与分页、今天的逾期／今日／此前计划分组、FullCalendar 月周日议程与表单／拖放排期、独立与全天事件／任务时间块、持久站内提醒和主动授权网页通知。任务恢复后重新安排未来提醒；过去 24 小时以外的到期提醒保留站内记录而不集中网页通知。网页通知认领只表示尝试，崩溃不重发，关闭页面不推送。

新实例默认 notes＋todos planner；已有单插件和旧双插件配置保持原格式。planner 使用新目录的 v2 数据库，拒绝原 v1 数据库，升级工具尚未实现。重复、CalDAV／ICS、笔记来源关联、邮件及其他外部通知尚未实现。

## 数据与交互约束

笔记与附件以磁盘文件为权威；正式任务与日历以 todos SQLite 为权威。Markdown 清单不自动复制为任务，Agent 的内部执行计划不属于个人待办。普通编辑和任务安排不需要模型。

笔记面板只用于查看和编辑笔记：保留文件树、编辑、查找、改名、移动、归档、随机打开、分栏、链接、日记和清单；不提供收集页（收件箱由对话写入，见下文 2026-11-27 方向），也不在工作区内放 Agent 入口（Agent 从宿主侧栏进入）。`Chat.md` 等已有文件原样保留在磁盘上，不删除、不迁移；`Later.md`、`journal/`、`media/`、`config.json` 的用途保持；classic 模式继续兼容。

现有文件边界继续适用：正文／设置 1 MiB、附件 16 MiB、单目录累计读取 64 MiB、扫描最多 20000 项／20 层／10 秒；拒绝路径穿越、隐藏路径、软硬链接及特殊文件。更新校验实际读取的 SHA-256，移动／删除校验版本，目标已存在不覆盖。Go 同步、Telegram 和自动外联媒体不接入，不放宽整个宿主 CSP。

保存只确认提交快照，组字期间暂停提交。保存期间新增输入阻止依赖保存的导航；冲突或未知结果保留输入，未知写入只读核对，不自动覆盖或重发。切 Agent 与其他面板后保留 iframe 和编辑状态；关闭未保存页面提醒，不承诺崩溃草稿恢复。

任务包含标题、详情、状态、可选计划日期、截止、优先级和清单。标题 1–200 字符，详情最多 20000 字符，清单名称最多 100 字符；状态为 open／done／cancelled，优先级为 normal／high／urgent。完成与取消分别记录，恢复是显式操作。计划日期不自动产生截止或提醒。日期截止按所属时区次日开始判断逾期，精确截止按指定时刻判断；无截止不标逾期。任务时间块关联任务，独立事件不要求任务；全天与定时事件的结束均为排他边界。

定时起止使用明确 UTC／偏移时刻与 IANA 时区，结束必须晚于开始；不存在或有歧义的本地时间不可猜测，应要求明确偏移。

Agent 仅按用户明确要求写入任务和日程，写前读取版本；缺少必要日期、时长或时区时先澄清。最终工具参数使用明确日期／时刻与 IANA 时区，不能把自然语言猜测直接落库。未知结果先查回执，不得宣称已经成功。

提醒事实持久存储；启动及每 30 秒补扫。超过 24 小时的到期提醒保留站内记录，不集中触发网页通知。通知须用户授权，认领仅表示一次尝试，关闭页面不推送。不要将其描述为外部推送或送达保证。

修改沿用版本校验与请求回执：相同 requestId 重试不能重复写入，相同 ID 不同载荷应拒绝；未知结果先只读核对。

新 planner 使用 v2 数据库并拒绝 v1 库。已有单插件、旧双插件与 v1 数据不自动迁移或清理。备份必须明确覆盖 notes、todos 和需要保留的 DSH／导师资料，不能把笔记备份称为整实例备份。

## 产品方向（2026-11-27）

根本需求是一个持续记住用户的“外脑”：用户只负责说话和丢东西进来，由它记住、整理、提醒。

三条原则：
1. 一个入口：用户对 Agent 说话；笔记页与日程页是手动模式，用于查看和小修改。
2. 记忆在文件里：笔记根目录是唯一的个人空间和事实来源，对话可随时丢弃；重要结论当天写入文件。
3. 克制：Agent 只在早晨简报、晚间回顾和到期提醒时主动联系；修改用户自己写的笔记须明确批准。

一个节奏：每天早晨由 DSH 定时任务新开一个主对话，给出简报（今日日程、任务、逾期、收件箱数量）；每天晚上做回顾（完成／未完成、改期、把收件箱整理进 `wiki/` 或日记、记一句今天学到什么），把当天归档进文件。主对话保持轻量：重活交给子 Agent，只回传简短结果卡，避免上下文腐化（借鉴 dsh-superagent-prototype：主会话只放紧凑卡片，状态放在对话之外）。

Agent 在笔记根目录可写 `wiki/`、`收件箱/`、`journal/`；其余区域默认只读，经批准才改。限制：DSH 沙箱无法按子目录限制写入，所以此约束靠笔记根目录的 `AGENTS.md` 指令和现有版本冲突保护实现；必要时以后再加 git 快照。个人待办（planner SQLite）与 Agent 自己的工作事项严格分开；待办数据库保持原位，在笔记根目录之外。

本轮实现：notes 插件自动把其根目录注册为 DSH Workspace；`plugins/notes/templates/` 提供 `AGENTS.md` 模板，供用户审阅后复制；planner 修复（成功提示自动消失、全天开关保留所选日期、表单中全天结束日期按含当日显示、表单简化并增加“更多”折叠区、“新建日程”只在今天／日历视图出现）；删除 Android 工程，移动端暂以手机浏览器打开 DSH 网页。

下一步：用 DSH 自带功能（Agent 预设、子 Agent、定时任务、karpathy-llm-wiki 技能）试用 1–2 周，不新增插件代码；之后看三点：是否每天打开、是否仍需重新解释上下文、是否漏了提醒。暂缓：代码仓库管理、文件监听、Ticket 插件、手机 App／推送、学习插件改动。

以上不改变既有规则：不做 Markdown 与任务的同步，不迁移数据，不改 vendor，不放宽 CSP，Agent 的计划不是个人待办。

## 学习导师边界

学习导师独立分发，仅支持已有 DSH 用户安装。用户自行选择工作区和教学预设；插件不改变宿主默认预设或日志设置，不随默认 notes＋todos 组合加载。

学习记录保存在会话工作区 `.learn/`。正式成绩需要真实题目、用户作答及考官证据，导师自报结果不提升掌握度。具体规则与互动行为见 [导师指南](../packages/learn-anything/README.md)。
