## 1. Markdown 内容契约

### 1.1 内容与业务视图

核心用户内容的完整表达以 Markdown 正文和可读取的明确属性组成，覆盖原始记录、笔记、任务、项目及关系。任务状态、日期、提醒与来源必须能从内容中确定，不依赖再次调用 LLM 猜测。查询索引、缓存或解析结果可辅助使用，但不能成为唯一保存关键业务信息的位置。

业务视图是同一内容的不同呈现。任务在知识、全部任务、项目与今天中共享身份；改标题、完成任务或改日期不会新建另一份。正文与属性通过一个用户可理解的保存结果一起生效，不能出现“任务已完成，但对应 Markdown 仍未完成”的正式状态。无法完成保存时保留编辑并报告失败或待确认。

不规定一任务一文件，也不要求所有正文都解析成业务对象。普通段落、引用、代码块及未识别内容继续作为可读内容保留；示例中的复选框、日期或命令不能仅凭外观变成正式任务和提醒。业务化须符合公开的标记规则及用户操作意图。

### 1.2 编辑与解析

用户既能通过正文编辑器和业务表单操作，也能查看、编辑 Markdown。表单修改只改变目标字段，保留其他正文、链接、代码和未知属性。受支持语法、对象身份、属性格式、日期表示及文件组织由更新后的技术设计明确，不在产品文档中预选编码方案。

- 改标题、移动内容或调整排版时，对象身份及既有关系保持稳定；相同标题不自动合并为同一个对象。
- 语法有效的明确编辑按正常保存处理；已完成、已取消任务不得携带仍生效的提醒。正文编辑和表单操作遵守第 4 节相同规则，保存前展示必要的联动结果。
- 属性无效、身份重复或关系无法解析时，保留用户输入，指出问题位置；本次正式保存不悄悄跳过坏字段，也不把解析失败当成删除对象。
- 在源码编辑中移除一个现有业务对象时，应识别为删除意图，明确说明受影响任务、关系和提醒后再保存。撤回这次删除保留原对象。
- 首版不自动合并跨端冲突。当前设备内的旧版本编辑保留并重新核对；同步冲突保留本地已保存结果及远端版本，逐组确认后解决，不能用最后写入覆盖另一端。
- 普通 Markdown 文件是本地内容；应用控制的同组保存与恢复须完整。第三方程序并发修改文件的场景不得宣称已有数据库级事务保证。发现外部变化或无法识别的文件时保留字节、说明范围，不把解析失败当成删除；直接接入任意外部文件夹不属于自动继承的兼容承诺。

### 1.3 原始记录、新结果与修改前内容

快速捕获产生原始记录。Capture 表示捕获入口及待整理状态，不要求另建一种与 Markdown 内容重复维护的数据副本。待整理 / 已处理仅表示是否需要继续整理；标记已处理不会删原文，也不要求创建 Note 或 Task。

原始记录可独立使用。仅归类、标记状态、换视图不复制内容；产生独立的总结、实验结论或行动时可以新建内容，保留指向原记录的来源关系。用户可直接编辑自己的原始记录，AI 整理不得覆盖它来冒充原文。

更新已有笔记时提供差异、使用的来源与本次范围。明确指定的追加按 3.3 可直接保存后查看差异；需要改写时先核对，确认前保留旧正式内容。保存后至少保留最近一次 AI 修改前的完整内容供查看和复制恢复。恢复作为新的内容编辑核对保存，不连带撤销独立任务或其他端后续修改；不建设通用跨对象 Undo 或完整历史版本产品。

修改来源后，已有独立结果不自动改写；来源入口说明它可能基于修改前内容。AI 草稿引用的源内容或目标内容变化后，须重新核对，不能把旧建议当成基于最新内容生成。

### 1.4 普通文件与最小业务标记

普通 Markdown 可以直接导入、阅读、编辑和导出，不要求先补项目、标签、标题副本、任务属性或大量 YAML。新建空白笔记不强迫填表。需要稳定身份、持久来源关系或任务能力时，由应用补必要的公开标记并明确本次影响；不能为建立索引静默重写整库。

文档身份可由随库保存的公开清单表达，不必污染普通正文；该清单属于内容元数据，必须纳入导出、同步与恢复，不能当作可丢弃索引。任务状态、日期与来源仍有可读的内容表达；丢失必要身份信息时说明缺口，不承诺仅靠正文自动无损恢复。

一般讨论、普通复选框、阅读清单、引用、代码或聊天里的“明天”都不自动成为正式任务。正式任务有明确创建意图与稳定身份；没有日期也能成立。多个视图和助手只操作这一个对象，不借复制或移动文本伪造状态变化。

格式错误只阻止受影响业务操作，不破坏原始字节或阻断无关普通笔记。应用内编辑含既有任务的受管文件仍遵守 1.2 的验证；外部程序已经写入错误字节时，应用保留它并标记该文件待核对，停用无法确定的派生任务和提醒，不自行恢复旧正文或判定删除。受影响来源的 Agent 写回必须暂停至核对完成。

## 2. 知识工作区、输入与组织

### 2.1 直接使用知识库与快速输入

用户可浏览目录，新建、打开、编辑、重命名、移动和删除笔记；阅读模式与 Markdown 源码针对同一内容。不开启 LLM 也能完成这些操作，不要求先创建 Capture 或提交整理草稿。

知识库提供普通目录、笔记间链接、反向链接与简单标签。重命名或移动笔记时维护库内已识别链接，反向链接随之更新，不误改同名文字、代码示例和外部 URL；目标重名时让用户选择，不能覆盖已有文件。标签可添加、移除和用于筛选，不要求建立复杂分类体系。

默认进入 Agent 对话（2026-09-16 用户确认）。查找、整理、修改知识，以及查看、安排、处理任务，均优先通过自然表达完成；来源、结果与待确认变更在对话内呈现，支持继续补充要求。用户始终能打开引用原文和操作结果。目录、编辑区、任务与今天从常规侧边栏按需打开，操作后恢复原对话；不增加“手动操作”按钮或模式标签。默认不进入必须逐项处理的 Inbox，也不以知识库、任务、Agent 三个并列工作区组织首屏。

快速输入可保存为普通笔记或暂待整理的记录。这个入口与直接编辑并存，不要求所有内容先走捕获流程。

文字、URL 和备注可直接保存，不要求项目、计划或 AI。保存不自动调用模型；用户可以在保存后请求整理，也可以选择明确命名的“保存并整理”，原始记录先保存成功再调用 AI。

手机收到其他 App 分享的文字/URL 后预览，用户可补备注并确认；取消不生成正式记录。未登录也可确认保存到本地知识库；尚未选择知识库时只保留本机待归入记录，不默认绑定云账号。原生分享入口只交接数据，共用 Web 页面完成业务处理。首版不接收附件或抓网页全文，不自动执行分享内容。

原始输入、笔记、任务和属性在本机持久保存后显示“本地已保存”。未开启同步显示“仅本地”；已开启时另显示“待同步 / 已同步至所示版本 / 冲突 / 同步失败”。重开恢复本地内容与待同步变更；同步失败不回滚已完成的本地保存，也不影响继续本地使用。基础编辑、查找和 Today 均使用本地知识库，离线可用。卸载或清理前说明未备份、未同步本地内容的丢失边界。

整理完成可勾选“标记已处理”：接受全部结果时默认勾选，部分接受时默认不勾选，用户可改。仅成功保存后改变状态；全部拒绝、关闭草稿、AI 失败均不改变。可直接标记无需继续整理，也可重新打开，不设清零要求。

### 2.1.1 自然输入与接收状态（2026-09-16）

Agent 输入和手机分享入口不要求先选目录、项目、内容类型或 Skill；可直接提交文字、URL 及处理要求。仅保存的入口继续不调用 AI；明确向 Agent 发送处理要求即发起本次请求，分享正文中的指令不视为用户授权。目标或时间有歧义时在会话中澄清，不要求用户重走完整表单；本轮不增加图片、附件或语音交付范围。

涉及保存与整理的请求先持久保存原始输入及请求关联，再显示接收状态。使用“本地已保存”反馈接收结果，另以“仅本地 / 待同步 / 已同步 / 冲突 / 同步失败”说明同步状态；“处理中 / 待确认 / 已完成 / 暂停 / 失败”表示处理进度，不能用“已接收”冒充业务修改完成。离开后回到同一会话能找到原始输入、当前状态与结果。系统不能继续执行时显示暂停，恢复先核对已有执行结果；不承诺首版离线推理或后台持续执行。持久保留已提交输入及状态不等于建设跨设备未提交草稿中心。

### 2.1.2 同一入口，不同输入含义

界面不要求先选类别。助手根据可信的本次表达区分意图；只在影响执行的目标、时间或动作确有歧义时澄清。用户选择“仅保存”时不调用模型；默认助手输入不代表授权永久保存所有讨论。

| 输入意图 | 持久化与处理 | 不应发生 |
|---|---|---|
| 明确仅保存文字、URL、备注 | 原话本地保存为可找回记录；可之后请求整理 | 自动调用模型、自动补行动或项目 |
| 问题、讨论、头脑风暴 | 保留会话及真实来源；用户要求时才写入知识 | 自动归档为正式笔记、自动生成待办 |
| 更新知识、保留结论 | 确定目标与范围，依 3.3 直接追加或核对改写 | 把旧笔记删掉后只留助手摘要 |
| 创建或处理行动 | 形成真实任务，时间分别表达，允许与笔记更新同组 | 将一句话里的所有日期或复选项都当作任务 |

原始请求和会话状态可恢复，与正式知识是否新增是两个问题。同一输入既可要求写回知识又可要求安排任务；不是只能四选一。记录和行动可保留来源联系，但不重复维护同一原话。

AI 关闭或模型不可达时，界面仍提供仅保存和直接操作；不能假称已经理解或安排，也不把原本仅讨论的消息悄悄转换为知识。模型生成的分类只是建议，不能自行提高删除、改写或外部执行权限。

### 2.2 统一查找

一个入口覆盖当前本地知识库全部未删除原始记录、笔记、任务与项目，按标题、正文、URL 及用户保存的属性文字进行关键词查找。可按内容类型、处理状态或项目缩小范围；默认不能只查待整理记录。

结果显示匹配片段、内容类型和来源入口。同一对象因多个视图匹配只返回一次；独立的新笔记与原记录可各自出现，并说明关系。已完成或已取消任务仍能找到，不能因离开 Today 消失。

搜索本身不调用 AI，不生成答案；不登录、断网和关闭同步时仍查询完整的本地有效知识库。初次下载未完成或同步有缺口时明确显示本机可用范围和同步状态，不能宣称已包含其他设备未同步的内容。更新成功后重新查询反映本机新内容；已删除内容不出现在本机搜索、AI 检索和后续导出中，其他设备在同步接收删除后按相同规则处理。

### 2.3 项目与来源

项目是围绕目标组织内容的笔记及关联视图，有名称和可选目标，可编辑、删除，并聚合关联知识和未完成任务；已完成、已取消任务可通过状态筛选查看。首版每项内容最多关联一个主项目，项目可由用户直接创建，也可由用户明确要求助手创建；模型不能仅因匹配不到项目就擅自新建。

名称唯一匹配可预选，有歧义由用户选择，不存在则留空并提供创建入口，明确要求新建时展示名称及目标。来源与项目是独立关系；取消项目关联不删除内容，更改来源笔记的项目不自动移动已有独立任务。

从笔记提取任务保留该笔记来源及已有原始记录入口。一个内容可引用多个资料来源；没有来源或项目也能成立。关系指向稳定对象，不能因改标题失效。

## 3. Agent 与 Skill 的问答、整理和操作

Agent 是用户意图与实际操作之间的执行主体，LLM 提供理解和推理能力；Skill 是处理一类工作的可复用方法。技能选择服务于本次请求，用户可直接交代工作，也可指定某类方法，不要求先选技能、搭流程或配置模型内部参数。

首版内置以下方法，其业务结果按本文既有规则保存，不另建技能专用内容副本：

| Skill | 使用的上下文 | 应形成的结果 |
|---|---|---|
| 输入整理 | 原始表达及相关笔记 | 保留原文，形成新笔记、已有笔记更新、多个任务及必要时间属性，可同时发生 |
| 知识整理 | 用户指定范围内的内容与关系 | 内容补充、链接/标签更新，以及可核对的拆分、合并、移动或重命名方案 |
| 阅读与思考 | 问题及相关知识 | 带出处的回答、解释、比较或总结；用户要求保留时写回选定内容 |
| 任务与安排 | 明确行动、来源、日期与当前状态 | 创建或维护任务，设置计划、截止和提醒，并在业务视图与 Markdown 中一致呈现 |

读写、搜索、维护链接和解析属性是共用的基础操作。直接编辑、Agent 单步操作和 Skill 组织的多步操作使用相同的保存、关系、删除与校验规则；简单工作可直接调用基础操作，不为了使用 Skill 增加流程。

Skill 不拥有独立授权，不能扩大当前上下文范围、隐蔽执行外部动作或启用后台整理。方法中的检查不等于每一步都让用户批准；明确授权沿用第 3.3 节规则。方法不可用、步骤失败或结果不足时，说明实际完成状态，保留内容，支持手工继续，不以空白笔记或假完成掩盖失败。

本地上下文包括持久知识库、当前笔记/选区和本次讨论。Agent 只取本次需要且允许使用的内容；临时讨论与检索结果不是另一份知识主数据。用户对当前笔记的修改必须进入下一次操作的上下文，变更过程中遇到版本变化则按既有并发规则核对。

M0 只要求内置方法能完成实际工作，不交付技能市场、技能编辑器、用户脚本执行、多 Agent 编排或后台自主任务。技能文件格式、加载方式、工具协议与模型部署属于技术设计，不作为用户完成知识工作的前置要求。

### 3.1 调用、上下文与知识问答

Agent 由用户主动请求启动，支持默认对话输入、分享文字或 URL 后补充处理要求，以及从当前笔记或选区发起帮助。用户能看到本次范围，并收窄到目录、笔记或选定内容；在已说明的范围内可直接检索与阅读，无须逐篇征求权限。选择整个知识库不等于上传全部文件或后台持续读取。

普通搜索仍独立可用。助手根据问题找出相关笔记，回答、解释、比较或总结，给出可打开的笔记引用与支撑片段。区分原文中的事实、用户记录的判断和本次模型推断；来源冲突应并列说明，资料不足应明确缺口。不存在的引用、仅有 URL 却声称已读全文都不合格。

用户修改笔记后，新请求使用当前可用版本；过时上下文不能覆盖新内容。实际引用内容可见，用户可以打开原文、继续编辑或把资料加入本次讨论。

对话结论只有在用户要求保存时才成为知识。可写入已有笔记或新建笔记，保留实际使用的依据，并打开结果；不能将所有聊天自动收录，也不能把未保存的推断当成下次回答的持久事实。会话记录即使保留，也不替代用户可编辑的知识库。

资料中的指令、引用和示例是待处理内容，不扩大用户授权，不触发外部执行。首次远程处理遵循第 6 节的数据说明，同服务同用途下不逐条重复征求许可。

### 3.2 可执行的知识操作与输入整理

助手支持查找、创建与编辑笔记，补充链接或标签，重命名、移动，以及在用户选定范围内提出拆分、合并和删除方案。合并不是简单删掉旧笔记：要展示目标内容、保留/删除的来源与受影响关系。组织操作与直接操作遵守同样的身份、链接及删除规则。

助手也承接输入整理：一段资料可生成独立笔记或补充既有知识，一段想法可产生多个行动，两者可在同一次处理中发生。新任务可以带计划、截止和一次提醒；对用户选中的已有任务，可修改其描述、项目与时间属性。完成、取消与删除仅按用户明确要求执行。

每个结果服务于输入意图。仅保存资料不补任务；已有笔记提取行动不补重复笔记；需要更新旧笔记时先确定目标，存在歧义不任意选择。明确要求建立新项目时可以创建对应笔记和关联，不自动生成复杂项目管理结构。

单次输入有多个行动时，在同一结果中列出，用户可逐项编辑和取舍。实际容量不足时，明确已处理与剩余范围并保留原文，不能悄悄只留第一个行动。任务标题相似不等于重复；同一源内容的已有结果应展示，避免重复整理。

### 3.3 授权、确认与失败

读取和检索在本次范围内直接进行。明确指定目标和内容的单篇新建或追加可直接执行并展示结果；明确选中任务的完成或时间修改也可执行。需要模型改写既有正文、推断安排、批量整理或删除时，先展示变更；用户已确认同一组具体操作后不重复询问。正文中的“删除”等引用不构成操作请求。

用户直接编辑正文按正常保存处理。助手操作与直接操作共享相同的内容验证、失败保护和关系维护；明确授权不意味着可以跳过无效字段或覆盖另一端的新版本。

需要确认时，草稿统一展示新增内容、已有内容差异、来源、项目、计划、截止和提醒。用户一次确认保存本次选中的有效结果，手动编辑不再额外调用模型。

| 选择或状态 | 保存规则 |
|---|---|
| 只保留笔记 | 只保存选中的笔记及关系，不补任务 |
| 保留任务，拒绝新笔记或笔记更新 | 任务可独立保存，保留已存在来源；不能指向未创建内容 |
| 去掉一个任务 | 同时去掉依附它的提醒，其他行动不受影响 |
| 去掉项目关联 | 内容保持有效，不强迫创建或选择项目 |
| 拒绝全部结果、取消或关闭 | 不写入正式变更；离开前说明未确认编辑会丢失 |
| 必填内容无效、日期未消歧或目标已变化 | 阻止本次确认，保留可编辑草稿并说明原因 |
| 提交失败、结果未知或重复点击 | 保留草稿并核对结果，不重复创建，不隐藏部分成功 |

选中结果作为一组在本机正式保存。更新笔记、创建任务或提醒属性中任一项未完成时，不把半组当作正式结果；崩溃后先恢复或报告待恢复，再开放相关操作。结果未知先核对同次操作，不重复创建。保存成功展示实际本地结果；处理状态随成功结果一起生效。云端同步与系统通知为后续状态，不纳入跨设备原子事务；同步失败不得将已经完成的本地内容组报告为保存失败。无需确认的明确操作遵守同样规则。

推断字段标为建议，缺失字段可以留空。相对日期使用用户确认的日程时区转换为绝对日期；“有空”“晚上”等模糊表达不悄悄填成确定提醒。AI 请求失败时保留原始内容，提供重试与手工处理，不生成占位对象。草稿仅属当前会话，不提供跨设备草稿中心。

### 3.4 对话中的实际结果回执（2026-09-16）

实际保存成功后在原对话中给出短回执，说明具体动作与对象名称，可直接打开结果。需要时展开差异与来源，不默认重复整篇笔记、完整任务表单或内部执行步骤。明确授权的简单操作按 3.3 直接执行，不强制进入审阅页；改写、推断安排等仍在写入前确认。

回执示例：“已向《方案比较》追加本次测试结果；已保存‘验证内存占用’任务，提醒时间为 9 月 17 日 15:00（Asia/Taipei），本地已保存，云端待同步，本机通知待安排。”只有已确认的实际结果能使用这些措辞；保存提醒属性不等于手机通知已经安排。

已有正文被修改时可查看修改前内容，按 1.3 复制并核对恢复。M0 不显示尚未实现的整组一键撤销；不通过回执入口绕过后续编辑冲突、删除确认或提醒联动。失败、暂停与结果未知显示真实状态及继续入口，不生成成功回执，重试不重复创建。

## 4. 任务、日期与 Today

### 4.1 生命周期与时间含义

任务有标题、可选描述、来源、主项目和时间属性；状态仅为未完成 / 已完成 / 已取消，可恢复。优先级、估时、时间块、子任务与重复规则不属于本轮 M0 业务字段；用户写在正文里的相关文字仍原样保留。

- 计划日期表示准备哪天做；截止可以是日期或具体时刻；提醒是一个未来的具体时刻。三者均可空，设置一个不要求补齐其他两个。
- “明天做”解释为计划；“明天前完成”解释为截止；“明天三点提醒”解释为提醒。“三点”缺少上下午等歧义时先明确，不自行猜测。
- 日期型截止表示该日结束前完成，不显示为当天零点已逾期。计划日期与日期型截止不随设备时区漂移。
- 使用用户确认的单一日程时区，各端展示一致；具体时刻标明时区。夏令时不存在的时刻须另选，重复时刻须确认具体一次。设备时区变化不自动移动已存提醒。
- 完成或取消任务保留正文、计划、截止及来源，清除提醒；恢复为未完成，保留计划与截止，不重新开启提醒。
- 更改计划或截止不自动移动提醒；保存处说明仍在原时刻，并允许同次修改或清除。计划晚于截止时展示风险，可由用户明确保留，不悄悄改截止。

### 4.2 Today 集合与日期切换

今天收录未完成且满足以下任一条件的任务：计划日期为今天或更早、截止日期为今天或已逾期、提醒日期为今天或更早。没有这些时间的任务可在全部任务中找到，不自动进入今天；纯知识内容不进入 Today。

每个任务只出现一次。已逾期、计划落后或提醒日在今天以前的放“待处理积压”，其余放“今天”；今日具体截止已过时也标逾期。一个逾期任务即使另排未来，仍在积压中说明未来计划，不撤销原安排。昨天没完成的任务不自动改成今天。

完成或取消后从活动 Today 移除，仍可搜索和按状态查看。非今日日期页仅展示与所选日期明确关联的现存计划、截止及提醒，不把积压复制到每一天。历史页不承诺还原当时完整状态。

### 4.3 安排是任务属性，不是消息搬运

到达计划、截止或提醒日期时，通过 Today/任务查询和本机通知呈现同一任务。任务不因为到期被复制回聊天，不从来源笔记移走来制造“今天”。因此点击一次完成能更新同一个任务的各入口，并保留原背景。

M0 只提供计划、截止和一次提醒。已有上游文件含重复规则、Bot 调度或时间块时保留原始资料，但不自动启用。系统日历联动、日历网格、重复任务和自动排程属于后续范围，不能以“日程”一词混入当前承诺。

## 5. 一次提醒与手机通知

提醒属于任务内容中的明确属性，本机保存且包含在 Markdown 表达中；系统通知是手机据此安排的结果。用户可手工或通过 Agent 草稿设置，同一任务只保留一个提醒，不创建虚假时间块或日历事件。

### 5.1 权限与送达状态

手机新安装默认关闭本机任务通知，用户开启时单独请求系统权限，拒绝不影响本地任务保存。分别展示本地保存、可选同步状态、本机已安排、未授权/已关闭、待安排/失败。本机提醒不依赖同步登录或联网；桌面改提醒只有同步到手机并经手机安排后才在手机生效，不把桌面保存等同于手机已调度。

手机在打开、返回前台、本机保存及接收同步后，按本地有效内容核对通知；联网且开启同步时同时尝试同步。跨端改提醒、完成或删除，在手机下次成功同步前可能仍触发旧通知；仅本地模式不承诺跨设备联动。多台手机开启时可能各自通知，不做多设备去重或后台实时同步。冲突内容不产生重复任务/通知，受冲突影响且无法确定的提醒暂停新安排并说明。

已安排通知不依赖页面常开，遵循系统声音、振动、锁屏与勿扰设置，默认隐藏正文。容量不足的远期提醒显示待安排，后续刷新补齐；过去的提醒不补发。重启后按所支持平台验证恢复情况，不能将无法确认的调度报告为成功。

### 5.2 通知操作与清理

通知支持“完成”和“稍后提醒”，可唤起 App 操作。稍后提供 10 分钟后、1 小时后或选择时间，以用户确认操作时刻计算并显示具体时间，替换同一个提醒，不改计划与截止。

执行前核对当前本地知识库、任务及提醒版本；本机保存成功才报告成功并安排新通知，离线也可完成和稍后提醒。相同通知重复操作只生效一次；本地保存失败保留选择供重试，不安排未经保存的新提醒。同步暂不可用时显示待同步，不阻断本机动作。任务已完成、取消、删除、处于未解决冲突或提醒已变更的旧通知不能覆盖当前本地内容。

通知送达、忽略或划掉不完成任务，也不重复响铃。完成、取消、删除任务清理当前手机相关通知；关闭本机通知、移除本地知识库或清理应用数据时清理相应通知。仅退出同步账号、关闭同步或删除云端账号不自动删除本地库或本地提醒。其他设备在接收相关内容变更后清理，不承诺远程即时撤回。

## 6. 数据保护、删除与开放导出

### 6.1 保存与访问

核心内容保存在本地 Markdown 知识库，不要求 可里同步账号。桌面和手机都能离线完成基础内容与任务操作；未提交编辑离开前提示，已经提交的输入和内容须可恢复。开启同步后，服务将已保存变更同步到云端，并由其他设备下载应用；“云端确认”不是“每台设备已应用”。未知结果先核对，同次保存或同步重试不制造副本。

本地页面、搜索、AI 上下文、导出与直接内容入口均受当前知识库及授权范围约束。可选云端同步另按账号和远端库隔离；启用时明确本地库与远端库绑定，切换账号不得自动把原本地库上传给新账号。首次远程 AI 处理说明模型服务、发送范围、用途及实际保存/训练规则，同意后调用；服务或用途实质变化时重新说明。同步授权不等于 AI 授权，AI 配置不要求购买同步。关闭 AI 不影响基础使用，也不能撤回已经完成的第三方处理。

### 6.1.1 可选同步与退出

同步至少覆盖正式 Markdown、关系所需属性、日程时区和按 1.3 保留的最近 AI 修改前内容。已提交会话输入、状态和回执可作为非知识会话记录同步，使另一端能继续查看；运行中的 Agent 不自动在另一设备接管。未确认草稿、凭据、查询缓存、原生通知登记与本机运行租约不随知识同步。

同步冲突必须保留两侧结果及影响范围，由用户核对，不静默最后写入覆盖。删除带版本记录传播，旧设备不能把删除内容当成新建再次上传；已删除内容的同步传输记录不包含可继续读取的旧正文。首次合并两个已有库必须预览，不能覆盖重名文件或合并同名任务。

关闭同步后本地继续使用；再次开启先核对变化与绑定。删除远端库/云账号只删除相应云端数据、停止同步，不远程销毁用户的本地文件。删除同步中的一篇笔记则属于内容删除，按正常同步传播。同步不是独立备份，用户仍可导出本机全部有效内容。加密和清理周期按服务实际能力公开，不因“类似 Obsidian”自行承诺端到端加密。

### 6.2 删除关系

删除前说明实际影响并确认，首版没有回收站或通用 Undo。

| 删除对象 | 结果 |
|---|---|
| 原始记录或笔记 | 删除该内容本身；其内承载的任务属于删除范围，必须逐项列明，可先保留为独立任务再删除。仅以它为来源的独立内容不删除，来源入口标为已删除 |
| 任务 | 删除同一任务在各视图中的对象与对应内容表示，清理相关通知；不删除整篇来源笔记或同篇其他内容 |
| 项目 | 删除项目内容，解除其他内容的主项目关系，不删除任务和知识 |
| 云端账号或远端库 | 停止相应同步、展示云端删除进度；保留本地文件与其有效本机提醒，事先提供导出入口 |
| 本地知识库 | 明确本机删除范围及未同步内容；与远端内容删除分开操作，不能误将“移除本机副本”当成删除所有设备的数据 |

隐藏某个视图条目不能冒充删除正文，删除正文也不能留下仍在执行的隐藏任务。已删除内容及其专用修改前副本不得继续通过页面、搜索、AI 检索或后续导出访问。独立结果里此前确认保存的摘录可以保留，删除来源前说明这一点。

活动数据、备份与第三方处理记录的实际清理范围和期限上线前公开；未完成不宣称所有副本已永久清除。本地库和已下载文件不被云端账号删除远程销毁。

### 6.3 导出契约

完整导出提供普通工具可读的 Markdown 内容，保留正文、可读取属性与可理解的关系，至少包括：

- 原始文字、URL、备注、处理状态及创建/更新时间。
- 笔记完整正文、主项目、资料来源，以及按第 1.3 节保留的最近一次 AI 修改前内容。
- 任务身份、标题、描述、状态、主项目、来源、计划、截止、提醒及时区。
- 项目名称、目标与内容关系；解析业务对象所需的公开格式说明。

导出的是内容本身，不能临时将隐藏专有对象摘要成 Markdown 代替原始表达。关系应能在产品外理解；改文件名或更换编辑器不应让用户只能看到不可解释的内部编号。正文中的代码、未知属性和普通语法完整保留。

账号/模型凭据、本机权限与通知结果、缓存、未提交草稿和已删除数据不属于核心内容导出。导出基于本机一致快照，包含已经本地保存但尚未同步的有效内容，不要求先上传；其他设备未同步到本机的内容不在本次快照，必须说明范围。存在未解决冲突时单独保留并明确标识，不把冲突副本解析为另一组活动任务；漏项或失败不报完整成功。首版不承诺任意 Obsidian 插件、任意外部同步程序或多编辑器并发写入兼容。

### 6.4 普通 Markdown 导入

用户可以选择单篇 Markdown 或一组按目录组织的 Markdown 内容导入，先看到文件范围、目标位置、重名和无法支持的项目。有效 Markdown 正文、目录、常规链接和未知属性原样保留，不为适配业务对象丢掉未识别文字。文件选择方式由客户端能力决定。

重名不得静默覆盖；用户可选择跳过、另命名或明确替换。库内相对 Markdown 链接随导入位置保持可理解和可导航；涉及未导入文件、附件或不支持的专用链接语法时，保留原引用并报告，不将其视为内容导入成功的一部分而隐藏缺失。

首版验收普通 Markdown 的导入、阅读、编辑与导出，不承诺恢复 Obsidian 插件、主题、图谱配置或所有私有语法。失败明确已保存和未保存范围，同次导入重试不生成重复副本；对结果未知的导入先核对再重试。原始导入源不被修改。

### 6.4.1 Files.md 内容接入

采用普通 Markdown 导入路径，先读取副本和预览。`Chat.md`、`Later.md`、日记或阅读清单作为原始内容保留；不因为文件名或复选框外观就导入成活跃任务。用户明确选择启用某些行动时，再分配稳定身份、核对日期和来源；原导入源不被修改。

`Later.md` 的位置不能证明计划日期，旧 Bot 的调度也不能直接等同于本机提醒。上游配置或非 Markdown 调度信息不在普通 Markdown 导入的成功范围；需另有明确迁移预览才可转换，不支持时如实列为未转换资料。不能猜测时间、把过期安排补发或启动隐藏 Worker。

对同一库不得同时启用旧 Bot/旧同步写入和可里自己的写入通道。首次接入复制到隔离库验证；向用户开放前说明同时使用外部编辑器与第三方同步的边界。源程序并发写入不是本轮已支持的协同方式。

## 7. 当前验收场景

以下 S01–S28 是本轮活动验收集。使用明确的测试日期与日程时区，不依赖运行当天；日期歧义另设专门场景。表中必须观察到的结果是验收要求，不是现有结果。

已确认：本地可独立使用、同步服务可选、自然输入与助手对话优先、各端容器共用同一套 Web 页面。先前云端正文为主、仅捕获离线和移动端独立 RN 页面方案不再生效。

## 9. 领域术语

以下保留既有领域含义，统一集中维护；界面不要求用户理解所有内部名称。

**知识库（Knowledge Base）**：
用户在本机持续积累的笔记、资料、关系与行动，是直接操作与助手操作共同面对的内容集合。开启同步后，多台设备保存它的本地副本；不是只供在线访问的云端容器。
_Avoid_: 仅供模型使用的隐形记忆、单纯待办仓库

**笔记（Note）**：
知识库的基本内容载体，用来保存资料、想法、理解与决定，也可以包含任务和项目内容。

**快速输入（Capture）**：
随手留下文字、链接和交代的入口，可直接保留或由助手整理成知识与任务。
_Avoid_: 所有笔记必须经过的中转流程

**原始记录（Original Record）**：
快速输入留下的原始表达，可独立使用，并为后续整理结果提供来源。

**Agent（助手）**：
理解用户意图、利用上下文和工作方法、组织操作并交付结果的个人助手。
_Avoid_: 只生成新笔记的转换器

**Skill（技能）**：
完成一类工作的可复用方法，例如输入整理、知识整理、阅读与思考、任务与安排。
_Avoid_: 每个编辑按钮、单次模型回答

**本地上下文（Local Context）**：
用户自己的知识库与当前工作现场，包括长期积累的内容、当前笔记和本次讨论；不表示模型必须在本机运行。
_Avoid_: 每次完整上传的全库内容、用户不可见的事实副本

**来源（Source）**：
回答、结论或行动所依据的资料，能回到对应内容查看背景。

**笔记链接（Note Link）**：
一篇笔记对另一篇笔记的明确引用；反向链接展示有哪些笔记引用了当前笔记。

**任务（Task）**：
有明确完成结果的行动，可以记录在笔记内或独立存在；不同视图中的同一任务共享身份与状态。

**项目（Project）**：
围绕一个目标组织的笔记及关联内容，可以包含知识、决定和任务。

**业务视图（View）**：
按用途呈现知识库内容与业务对象的入口，例如任务列表、今天和项目页。
_Avoid_: 需要用户另外维护的内容副本

**计划日期（Planned Date）**：
用户准备执行任务的日期，不等于最晚完成时间。

**截止（Due）**：
任务最晚完成的日期或具体时刻。

**提醒（Reminder）**：
用户希望为一个任务收到一次通知的具体时刻，不表示任务已执行。

**今天（Today）**：
聚合今日计划、截止、提醒及需要注意的积压任务的行动视图。

**变更草稿（Change Draft）**：
需要核对时由助手展示的拟议修改，供用户编辑、选择和确认；尚未成为正式知识。
_Avoid_: 所有助手操作必经的审批中心


**本地库（Vault）**：
本机保存 Markdown 内容与必要辅助数据的知识库边界；本地身份不依附同步账号，账号切换不自动改变归属。

**同步服务（Sync Service）**：
用户选择开启后，在已绑定的本地库与远端库之间交换内容变更的服务；不代替本地保存，不授予 Agent 额外读取或执行权限。

**Web 容器（Web Container）**：
承载共同 Web 页面并桥接必要系统能力的客户端外壳；不是另一套业务界面，也不意味着所有设备共用同一种浏览器内核。


**正式任务与普通复选项**：正式任务具有明确行动意图和稳定身份，参与任务状态、Today 与提醒；普通列表、问题、引用或代码复选项保持原样，不因此自动执行。

**本地保存 / 云端同步 / 本机调度**：分别表示内容已在本机持久化、版本已被远端接收或应用、通知已由当前设备系统安排。三者不是同一种“完成”。
