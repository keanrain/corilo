# Corilo 可里业务规格

v0.15 · 2026-10-21。本文件是当前业务规则唯一来源。替代 v0.12 本地/Android 路线；以下云端 N 系列验收仍待验证；本机功能证据单列，旧 C 系列不再定义首期范围。

## 0. 范围、术语与交付边界

目标产品是简单、资料可带走的个人记忆与行动助手，知识库是资料基础。文件开发阶段、Agent 开发阶段和个人助手版本是连续实施阶段，不是三份独立产品需求。只有文件功能时应称“云端文件开发版”，不能称第二大脑已交付。最终个人助手验收覆盖 N01–N19；早期内部验证只记录已覆盖部分，不因此删除后续验收。

“Agent 执行任务（run）”是一次推理/工具运行，“用户待办（todo）”是用户生活中需要完成的事情，两者不能共用完成状态。日程（event）描述时间安排，提醒（reminder）描述何时通过指定渠道提示；待办可关联日程和提醒，但创建待办不自动等于创建提醒或外部日历事件。

下面区分产品目标、当前实现限制和待定决策。当前代码证据统一见技术设计第 11 节；待定项集中在第 8 节，不能把建议当用户已确认选择。

## 1. 账号与知识库

首期邀请制，每个账号一个独立知识库。邀请关联预期收件身份、有效期和使用状态；未受邀、过期、撤销或已被其他账号使用时拒绝开通。验证身份后原子兑换邀请，重试不得重复创建知识库。退出登录撤销当前登录会话，不隐含退出其他设备；账号停用使所有会话后续请求失效。失效会话不能继续访问文件、对话或执行任务。文件路径、用户 ID、会话 ID 和任务 ID 均不能替代服务端授权。

每库正文为普通 Markdown，附件为普通文件；不强制专有格式。服务端持久工作目录是正文唯一权威来源。配置、模型凭据、Pi 会话、运行日志、任务元数据和缓存在知识库之外。浏览器缓存不是第二份权威知识库，禁止回退为独立 OPFS/内存库并显示保存成功。

导入只接受安全的文件和目录，拒绝路径越界、危险链接及超额内容；重名先说明处理方式，不覆盖现有内容。导出包含用户正文和附件，不含服务端凭据、内部日志或其他用户信息。已有本地库由用户显式导入，不自动上传本机配置、`.git` 或隐藏运行目录。

## 2. 保存与跨设备访问

文件成功写入服务端后才显示“已保存到云端”。保存中、未保存、断线和冲突有明确区分；失败保留当前编辑文本。首期不承诺断网打开完整知识库或关闭页面后恢复所有草稿。离开仍有草稿的页面时提示，重新联网后先核对版本，再保存，不能无条件覆盖。

每次保存带读取版本。另一设备或 Agent 修改后，旧版本写入被拒绝，保留草稿并提供读取最新内容、另存副本和手工合并入口；不静默选择最后写入者。删除、移动也要检查预期版本或目录版本，重名不能覆盖。

一库只运行一个 Agent 修改任务。发起设备先保存当前草稿，再提交任务；其他设备已有草稿不会被强制丢弃。服务端串行协调文件变更、任务启动和版本恢复，Agent 运行时编辑器可阅读，保存请求明确拒绝并保留草稿。结束后更新文件列表和已打开文件；含未保存文本的编辑器不得自动重载覆盖。

其他设备通过状态事件或轮询获知文件变化；回到前台重新获取状态。多端访问不是各设备分别 Git pull/push，不承诺多人实时协同。

## 3. 对话与任务

Pi 运行在服务端隔离环境中，使用原生 read/write/edit/bash、模型配置和会话能力；不增加逐文件审批、propose/apply 或定制文件事务。默认 cwd 指向用户知识库，不把 cwd 或系统提示词当作安全沙箱。

明确的阅读、创建、整理和修改意图直接执行；Agent 判断目录、分类与步骤，必要歧义才询问。普通讨论不自动写笔记。“仅保存原话”直接写 Markdown，不调用模型。配置沿用 Pi 标准机制，由服务端部署管理，用户页面不接收平台模型密钥，不另建模型配置表单。

每条执行请求有持久任务 ID 与客户端生成的幂等键，同一请求重试返回已有任务。任务状态为排队、运行、停止中、已停止、完成、失败或中断。跨设备查看同一会话和任务；关闭网页、切后台和断线不等于停止任务。重连读取记录，不重发 prompt。

停止只终止尚未完成的执行，已经发生的文件变更保留并展示。服务重启或 worker 丢失后，未完成任务标记中断；核对存活执行后才释放写入占用，不自动重放有副作用的命令。用户可查看已完成内容并明确继续。

结果文件卡来自实际文件与运行记录，不以模型文字伪造成功。工具失败、历史保存失败或用量不足说明当前状态；不宣称文件自动回滚。

## 4. 隔离与额度

不同用户的文件、Pi 设置与会话、任务和凭据相互隔离。Agent 可执行 shell，所以只分目录或在共享进程中切换 cwd 不构成隔离。运行环境不得访问其他用户卷、平台管理凭据、宿主 Docker socket 或云实例元数据。用户隔离是开放邀请使用的前置条件。

每用户一个活跃修改任务；平台有全局并发、队列长度、任务时长、CPU、内存、进程数、磁盘容量、上传大小和 AI 用量上限。未配置额度或超额时不无限执行。等待与超额原因可见，不虚构剩余时间。普通笔记浏览和保存不应因全局 Agent 队列排满而失效；本库 Agent 正在修改时按第 2 节协调。

平台模型凭据不能通过默认 bash 被读取。模型请求在隔离环境之外使用平台凭据，内部调用身份限用户、限任务、可撤销并受用量控制；不改造 Pi 的模型管理机制。日志默认不记录正文、完整 prompt、认证头或密钥。

## 5. 版本、备份与隐私

每库保留独立 Git 历史作为恢复手段；初始化和 Agent 修改前建立基线，编辑保存批次及任务结束后提交。保存文件、版本记录与独立备份是不同状态：文件落盘但版本记录失败不能谎报文件未写，也不能声称已受历史保护。

用户从历史恢复会生成新版本，先检查当前文件是否变化，不删除后续历史。Agent 运行中不恢复。删除文件可从保留期内历史找回。Git 与当前文件同盘不算独立备份；上线前必须完成异地或独立故障域的备份与恢复检查。

首期无 GitHub 绑定要求。后续 GitHub 集成不应阻塞保存、登录或基础恢复，且不能把代码仓库当知识库。

首次使用说明资料保存在服务端，AI 会接收当前请求所需内容，无端到端加密。用户能导出资料、申请删除账号及数据；删除需覆盖活动目录、会话和任务记录，备份按明确保留期限过期，不能谎称所有备份瞬时擦除。运营方在邀请使用前明确容量、版本与备份保留期，不默默无限保存。

## 6. 简单使用与资料自主

用户可直接说、记、问，无需先配置分类、数据库或自动化流程。首页优先对话输入与少量需要关注的事项；文件、记忆、待办与日程按需展开。日期修改、任务完成、记忆纠正提供明确操作，不强制所有小操作都通过聊天完成。

记忆区分用户明确陈述、来源资料和模型推断，记录出处及更新时间。用户可查看、更正、删除；新信息与旧信息冲突时不默默把两者都当事实。普通讨论不自动成为笔记或已确认事实；自动提取的候选记忆必须与已确认记忆区分，不以“第二大脑”为由无限留存。是否默认自动记忆、何时要求确认尚待第 8 节决策，现有“每条候选都要确认”并不是用户已确认需求。对话历史与长期记忆是不同数据，关闭自动记忆不等于删除会话历史。

第一阶段行动闭环是明确待办与一次性提醒。创建时明确内容、日期、时区、通知渠道及状态，歧义才询问；服务端实际创建成功后才能说“已安排”。调度使用结构化记录，不能靠模型记住未来执行。修改、取消与完成可操作，重试不能重复创建提醒。通知渠道未配置或投递失败要如实说明，不能把服务器触发等同于用户收到。外部日历写入、发消息给他人等动作需对应授权。

资料自主包括可导出和可恢复，不只是单篇复制。分阶段提供 Markdown/原附件、记忆与任务 JSON、日程 ICS、对话及关联元数据，附公开格式与版本说明；导出明确覆盖范围和排除项。未来账号级导出须覆盖所有用户资料并验证重新导入。自托管和备份到用户指定存储属于后续交付，当前不宣称已支持。云端运营方仍能读取托管内容，开放格式不等于端到端加密。

当前第一项实现为知识库 ZIP 导出：仅包含已保存的可见普通文件、附件与空目录，保持字节和相对路径；附 SHA-256 清单。隐藏项、Git 历史、Pi 配置与凭据、对话、任务和日程不在本次范围，不称完整账号备份。遇到可见链接或特殊文件明确拒绝，不悄悄漏掉。第一版单次上限 128 MiB、10,000 个可见目录/文件；超过上限返回错误，不生成截断包。受管理的 Agent、同步和文件写入与导出串行，发现外部修改时拒绝并提示重试；不宣称能对任意外部进程提供文件系统快照。生成下载不等于文件已保存到用户设备。

### 6.1 记忆的最小闭环

明确的“记住、纠正、忘掉”直接执行，持久化成功后简短回执，可打开来源和修改，不再逐条二次审批。用户陈述代表“用户说过”，不等于外部验证过的事实。非明确委托内容是否自动提取仍待第 8 节决定；建议推断只进入候选，不默认作为确定事实参与行动，留存期限未明确前不无限积累候选。

明确更正更新同一记忆的版本；来源相互矛盾时保留冲突关系，不静默覆盖为事实，仅在影响当前回答或行动时询问。来源可指向会话消息或文件路径及内容版本，源文件已变更或不存在时明确提示。

“忘掉这条记忆”删除记忆及其检索/自动注入内容，保留不含原文的必要抑制记录，避免从同一来源版本再次提取。原始笔记、旧对话、用户下载副本与模型供应商已接收内容不会因此消失；Agent 仍可能通过默认文件工具读到保留的原文。不承诺自动识别所有改写和复制。用户要求连原文一起删除时，说明并处理对应文件/对话、索引和保留历史范围，备份按公布期限过期。

### 6.2 待办、日程与提醒

首版方案为待办、内部一次性日程、一次性提醒和 ICS 导出；暂不做周期规则、自动排满日程或外部日历双向同步。待办截止日期不自动生成提醒；日程结束不代表待办完成；停止一次 Agent run 不取消已创建的事项。只有明确时间、已知时区和用户启用的通知渠道都具备时，才可直接完成提醒安排；“下月爸爸体检”等模糊资料不能自动变成具体时间的通知承诺。

用户可核对时区。明确日期和时间的提醒保存其确定时刻；修改个人显示时区不悄悄改动已安排时刻。夏令时造成不存在或重复的本地时间时需澄清，全天事项不自动变成午夜提醒。完成或取消关联待办/日程会取消尚未进入发送阶段的提醒，重新打开待办不自动重发旧提醒。

通知只发往用户验证并在可信界面启用的本人渠道；Agent 不能自行更换收件人或声明已获授权。渠道未启用时可保存事项，但必须显示提醒尚未启用。修改绑定后旧提醒暂停，重新启用前不自动转发到新地址。首渠道建议邮件，尚未确定供应商或开通服务；邮件服务接受、确认投递和用户读到是不同状态，不承诺准时阅读。

发送前可修改/取消；已开始提交给渠道时明确提示可能无法撤回。网络超时且结果未知时显示“投递结果待确认”，不谎称失败后盲目重发。服务恢复时按公布的补发宽限处理延迟提醒，过期事项标为错过，不批量补发陈旧通知。ICS 是可下载日历视图，不代表已加入或同步外部日历；默认不附加闹钟以免重复提醒。

### 6.3 完整资料包与恢复

知识库 ZIP 与完整账号资料包分别标明范围。完整包覆盖仍保留且用户可访问的正文/附件、可见历史、对话、记忆及来源、待办/日程/提醒与结果、关联和偏好，并包含避免重复提取所需的抑制元数据；不导出登录凭据、平台密钥或内部调试记录。普通文件可直接阅读，结构化数据提供公开版本化格式，ICS 和对话 Markdown 为方便阅读的视图。

首版完整恢复只面向空知识库：预览范围、校验并暂存，全部就绪后发布；不猜测合并已有资料。重复导入同一资料包不重复创建对象；失败不能展示半套恢复结果。导入的会话是历史，不自动执行旧工具；所有待发提醒暂停，用户重新绑定渠道并启用后才安排未来通知，过期提醒不补发。

同服务恢复旧包时须应用较新的删除/抑制记录，避免复活已遗忘内容。独立实例无法知道旧包产生之后的删除，导入预览说明其快照时间与范围，不承诺恢复包能识别未知的后续遗忘。平台无法撤回用户已下载的副本。自托管必须能独立认证、运行、备份恢复和升级，不依赖 Corilo 官方服务可用；目前尚未交付。

这些条件描述目标产品，不是当前已通过列表。N01–N05/N14/N15 的部分文件与会话路径已有开发测试，真实身份、完整数据生命周期与移动端仍未验收。N06–N12 涉及云端 Agent，N17/N18 涉及记忆与行动；当前禁用或未实现，不可用本机测试替代。N19 的完整账号恢复尚未实现，只有知识库内容导出不能满足整项。
