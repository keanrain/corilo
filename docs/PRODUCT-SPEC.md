# Corilo 可里业务规格

v0.34 · 2026-11-11。此文件是当前业务规则唯一来源。独立任务与日程方向替代 v0.33 中“全部个人待办仅使用 Markdown、todos 仅退役兼容”的目标；Files.md 的保留要求不变。本版是设计，新增能力均待实现，不代表当前安装包支持。

## 1 范围与数据归属

使用一个 Harness 的登录、权限、会话和模型设置；业务入口为笔记、任务与日历，任务和日历由同一插件提供。首期个人单所有者、单主机；不建设第二个 Agent loop 或任务执行底座。

笔记权威数据为主机普通文件；个人任务和日历权威数据为任务插件 SQLite。笔记中的清单是原文，不自动与数据库同步。任务必须由用户明确建立，普通讨论、笔记勾选与 Agent 执行计划不自动转为个人事项。已有单插件或双插件配置均保留；新默认组合要在阶段 A 验收通过后才调整代码。

## 2 笔记工作区连续性

保留 Files.md 文件树、编辑、查找、改名、移动、归档、随机打开、分栏、链接、收集、日记和清单菜单。Chat.md 是收集文件，Later.md 仍是普通清单，journal/、media/、config.json 保持。classic 页面继续作为显式兼容选项。

现有写入边界继续适用：正文／设置 1 MiB、附件 16 MiB、单目录累计读取 64 MiB、扫描最多 20000 项／20 层／10 秒；拒绝路径穿越、隐藏路径、软硬链接及特殊文件。更新校验实际读取的 SHA-256，移动／删除校验文件或目录版本，目标已存在不覆盖。原生外部服务、Go 同步、Telegram 和自动外联媒体不接入。

保存只确认提交快照，组字期间暂停提交。保存期间新增输入则阻止依赖保存的导航；冲突或未知结果保留输入，未知写入只读核对，不自动覆盖或重发。切 Agent 与其他面板后保留 iframe 和编辑状态；关闭未保存页面提醒，不承诺崩溃草稿恢复。

## 3 任务规则

任务包含标题、详情、状态、可选计划日期、可选截止、可选优先级、可选清单及笔记关联。标题 1–200 字符，详情最多 20000 字符；保留现有 UUID 和版本条件。优先级为普通／高／紧急，默认普通；清单一层，不实现多级项目树。

状态为 open、done、cancelled。完成与取消独立，允许明确重新打开；首期取消代替永久删除。记录完成时间、取消时间和操作版本，不自动清理历史。旧 cancelled 记录仍取消，不因重新显示而复活。

计划日期是“打算哪天做”，不自动变成截止或提醒。截止可以是日期，或带时区的精确时刻：日期截止在其所属时区次日开始时才逾期；精确截止按该时刻判断。没有截止的任务不标逾期。计划日期已过但未完成只标“计划已过”，不自动顺延或改变状态。

| 视图 | 内容与排序 |
|---|---|
| 收集箱 | open 且无清单、计划日期、截止和未来时间块的任务；新建时间倒序 |
| 今天 | 今日计划、今日截止、逾期截止、今日任务时间块的 open 任务去重；先逾期、再精确时间、再优先级与创建时间 |
| 未来 | 从明日起，按计划／截止／时间块中最早的未来相关日期分组；同任务提供其他日期标记 |
| 全部 | 按状态、清单、优先级、关键词筛选；稳定分页 |
| 完成与取消 | 分开展示，支持查找和明确恢复，不进入今日待完成计数 |

“今天”按用户设置的 IANA 时区计算，首次建议浏览器时区并要求用户确认，不能硬编码服务器或开发者时区。收集箱中的任务可加入清单或安排时间；不是所有任务都必须先清空收集箱。

## 4 日程与任务时间块

日程包含标题、描述、定时或全天范围、可选地点及笔记关联。定时日程必须有起止时间、IANA 时区且结束晚于开始；全天范围存日期，结束日期不包含在内。允许跨日，日期不经 UTC 零点转换。

任务时间块是关联一个任务的日历条目：一个任务可有多个时间块；日程也可独立存在。把任务拖入周历创建时间块，不修改任务截止；首次建议 30 分钟并在落点确认表单中可改。移动时间块仅改安排，不修改任务状态。任务完成后，过去时间块保留，未来时间块标示任务已完成并停止相应提醒，用户选择保留或取消安排。

固定事件不使用“完成任务”按钮；可取消，过去事件按时间自然归档。事件／时间块重叠给出冲突提示但允许用户明确保存。待办到期在日历中显示截止标记，不占用会议时间。月、周、日与议程查询统一使用当前显示范围，手机默认议程而非挤压周网格。

断线时保留当前编辑内容并标未保存；重连先核对版本。拖动失败恢复到服务器位置并保留待提交的调整供重试，不能显示为已经改期。列表和日历必须有不用拖动的等价操作。

## 5 笔记关联

从笔记显式建立任务时，打开任务表单，预填所选文字与来源；用户确认后创建，不自动修改原文。从任务或事件可打开关联笔记，切换前沿用笔记保存保护。

关联存库身份与相对路径，不能接收任意文件系统路径。改名后若无法定位，显示“来源已移动”，允许手工重新关联，不因失联删除任务。阶段 A 不承诺跨插件原子改名或自动修复全部关联。正文更新不会自动改任务标题；任务完成不自动勾选原文。

## 6 重复规则与提醒

以下在阶段 B 实现。重复系列支持每天、每周指定星期、每月同日及间隔数，可无限、按结束日期或次数结束；首轮不支持农历、节假日、工作日历和任意高级 RRULE。每月 31 日遇到短月跳过该月；UI 显示接下来三次供确认。

任务系列的每次发生有独立状态和版本，完成本次不完成整组，也不自动补造无限历史。支持仅本次与整组未来发生的修改／取消；“从这次起另设规则”的系列拆分后续再做。整组修改保留已完成和已过去实例；单次例外优先于系列默认。错过的未完成实例不自动完成，可在系列中汇总查看。

重复使用系列的当地墙上时间和 IANA 时区。夏令时不存在的时刻跳过该次并展示原因；重复时刻取较早偏移且展示偏移。手工新建遇到不存在的时刻要求换时间，遇到歧义要求选择偏移。用户切换显示时区不重写事件原时区或全天日期。

提醒是独立配置，默认关闭，用户可选择在精确截止／日程开始前多久提醒；只有日期的任务须指定提醒时刻。完成、取消、改期或关闭提醒会使未发送旧提醒失效。阶段 B 仅交付持久站内提醒中心；页面关闭时不宣称已向手机送达。

重启后，过去 24 小时内的到期提醒在站内合并为“离线期间到期”，更早的保留记录但不集中推送。通知状态区分待发送、渠道已接受、失败／结果未知和用户已读；渠道接受不等于用户看到。阶段 C 的外部或 Web Push 通道须单独选择并验收，不能因实现设计而自动开通服务。

## 7 Agent 规则

复用 Harness 原生会话与权限。明确的用户指令可以直接执行：如“把这个任务设为明天下午三点截止”；缺少事件时长、日期存在歧义或涉及整组修改时先澄清必要参数。查询和普通 UI 操作不要求额外审批，不增加 Corilo 自有审批系统。

相对日期以请求时用户时区和当前日期解析；工具最终必须收到明确日期／时间／时区。写前读版本；成功回复引用已提交的对象和日期，未知回执不能声称成功。AI 可提出排期建议，但没有用户要求时不批量改期、不创建任务或通知。个人任务工具与 Harness 内部计划工具明确区分。

## 8 兼容与升级

现有 todos 0.5.2 的 v1 数据库、notes 0.7.0 与旧配置保留。本轮只制定方案，不启动真实数据库迁移。未来 v2 使用显式离线升级命令：停止服务、备份、预览映射、写入新的目标目录、校验、明确切换配置；不在启动时自动变更 schema，不覆盖原库。旧 ID、状态、关联、原时间和幂等回执全部保留，新日期默认空，不虚构历史安排。

已有 SQLite → Markdown 导入工具继续可用，但属于用户选择的单向导出路径，不再作为默认退役流程。已导入的 Later.md 不删除、不回迁；若旧库仍在可选择它为任务来源，后续 Markdown 修改不自动合并。没有旧库时先做人工选取建立任务，后续批量导入必须有来源预览、冲突与防重复设计。不得同时静默维护两份当前任务状态。

任务插件提供版本化 JSON 导出；阶段 C 提供 ICS 导出并进一步评估 CalDAV。JSON／ICS 不是完整备份，完整恢复需数据库一致快照、笔记和配置映射；凭据与 Harness 会话单独保护。恢复后通知默认暂停，用户检查后再启用。
