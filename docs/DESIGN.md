# Corilo 可里交互设计

v0.27 · 2026-11-09。DeepSeek Harness 为主体，业务规则见 [PRODUCT-SPEC.md](PRODUCT-SPEC.md)。以下为目标交互，插件工具注册不代表这些页面已完成。

保留 Harness 原有对话、会话、模型设置、工具进度和停止体验。Corilo 通过插件增加“笔记”和“事项”入口；不再把旧 Files.md/Pi 应用嵌套为另一套主界面。桌面与手机使用同一服务，手机无终端初始化流程。

当前视觉为 Astryx Neutral 0.7.11 静态设计 token 的局部适配：中性主色、明确主次按钮、轻列表分隔、10px 控件圆角、清晰蓝色键盘焦点和语义状态色。字体和浅深色模式继承 Harness，只作用于插件根；没有加载全局 reset、网络字体或新 React。React 组件要求与固定宿主不兼容，不能把静态主题适配描述成 Astryx React 组件集成。

## 核心交互（v0.26）

参考 [Obsidian 的笔记管理](https://obsidian.md/help/manage-notes)、[文件列表](https://obsidian.md/help/plugins/file-explorer)及滴答清单的[快速添加](https://help.ticktick.com/articles/7055782422935240704)、[任务详情](https://help.ticktick.com/articles/7055782408586526720)。复用它们的常见操作结构，不引入账号、插件体系或完整日历功能。

笔记桌面为左侧常驻列表、右侧文档。列表显示简洁标题和所属目录，仍保留完整路径的可访问名称；搜索支持回车，刷新独立于搜索。编辑区顶部是标题，下方正文，保存与状态位于正文之后。新笔记标题可留空，也可直接写普通标题（保存时补 `.md`），不改写正文。已保存笔记提供明确的重命名入口和确认表单，目标限同目录，失败保留输入。新建与打开后焦点回到正文；编辑区内 Ctrl／⌘S 复用显式保存，中文输入法组字时不触发。编辑采用 Markdown 源文，提供实时预览；桌面可同时看正文与预览，手机在两者间切换。已有笔记停止输入后自动保存，首次保存新笔记仍需明确操作。草稿恢复本身不自动落盘，失败、冲突和未知结果暂停自动保存。

手机笔记采用列表／正文两个视图：默认显示正文与保存，点击“查找笔记”切换列表，打开结果回到正文。两者不再纵向堆叠；“返回正文”只切换视图，不丢输入。历史、回收站与删除留在“更多操作”。浏览器草稿就绪的常驻说明移除；正在保护、未保存到主机、错误和冲突保持可见。

待办默认是快速输入与列表；回车新增后焦点留在输入框。未完成、已完成、全部、已取消直接用状态按钮切换，当前状态明确标识；搜索始终可见，回车或点击搜索执行。列表行以标题和首行说明为主，不重复每行相同状态文字。点勾选完成，反馈提供撤销；点标题打开详情。桌面在列表旁打开详情，手机进入独立详情视图，保存与“返回列表”可发现。

切换待办或返回列表时，未保存的详情先原子保留为浏览器恢复草稿，再切换；失败停留原编辑器。保留不等于写入主机，恢复仍由用户明确操作；结果未知的请求必须先明确处理，不能靠切换抛弃或重新发送。状态操作、其他行操作和快速录入继续保护当前详情草稿。说明、关联路径、取消、导出等不抢占快速输入的主入口。

编辑显示未保存、保存中、已保存、失败与版本冲突；失败保留草稿，冲突可核对最新内容或另存。外部变化时不自动覆盖未保存文本。默认行为不要求每个动作都发对话。

新建或切换笔记先安全保留当前草稿，失败保持当前编辑器。重载后显示带正文摘要及预览的待恢复草稿，用户可恢复或丢弃；显示“草稿已保存在此浏览器”与“已保存到文件”的区别。历史提供更早页、只读预览和版本恢复；回收站显示原路径、时间及恢复目标，存在同名文件时要求另选路径。恢复与删除不静默丢弃当前未保存内容。

日程视图后续提供，工具执行计划不混入个人事项。日期、时区与提醒状态尚未交付，当前不展示虚假的日历／提醒入口。渠道与手机后台行为须单独设计和实测。

后续记忆显示内容与来源并支持更正/忘掉。资料管理明确区分笔记文件导出、完整数据包与系统备份，各自标注范围。历史导入不继续执行旧会话或重发提醒。

窄屏输入采用至少 16px 字号、44px 按钮和底部跟随的保存栏；缩小视口仍需能编辑与保存。触控浏览器模拟检查不代替物理手机、原生输入法与 iOS WebKit 验收。

首期对话和笔记入口优先；工具层、Web 页面、真实模型、手机与部署分别记录验收。Harness 默认界面的移动可用性也必须实际检查，不能由 Web UI 存在推断通过。

## 自动保存、预览与重命名（v0.27）

保存时正文继续可写，状态反馈区分“保存中”与随后新输入的“未保存”。服务器确认只更新提交快照的版本及原文，不清空较新输入。恢复草稿先回到编辑器，不自动写入；用户继续编辑或明确保存后按原版本检查。离开前仍有未保存内容则保留浏览器恢复副本。

预览复用成熟 Markdown 解析和 HTML 清洗器，仅在需要时渲染；禁止原始 HTML、主动外部资源和危险链接。大正文可编辑保存，超过预览阈值则说明暂不预览，不能静默截断后称完整。预览不会修改 Markdown 源文。

重命名只改当前目录中的文件名，正文先保存再操作；目标已存在则留在表单供修改。成功后列表、当前路径和历史入口一致更新；旧名称的历史可只读查看。失败或结果未知保留原输入并要求核对新旧路径，不替用户重发；链接与待办关联路径不自动重写。
