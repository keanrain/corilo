# Corilo 可里交互方案

v0.34 · 2026-11-11。目标是在 Harness 中提供完整个人任务与日程体验，同时保留 Files.md 笔记。以下布局是待实现设计；业务规则只由 [PRODUCT-SPEC.md](PRODUCT-SPEC.md) 维护。

## 入口与导航

沿用 Harness 主框架与原生会话。侧栏增加“任务”和“日历”，由同一个 todos 插件承载；“笔记”继续打开原 Files.md 工作区。不是三个独立网站，不增加第二次登录或另一套模型设置。

任务面板内部导航：收集箱、今天、未来、全部、清单、完成与取消。侧栏只保留常用入口，清单在面板内管理。切面板保留选中对象、滚动位置和未提交详情；离开未保存笔记时沿用已有保存保护。

## 桌面布局

```text
Harness 侧栏 | 任务导航       | 今日计划                         | 详情抽屉
会话         | 收集箱         | ＋ 新建任务        搜索／筛选     | 提交方案
笔记         | 今天           | 逾期与截止                       | 状态／清单／优先级
任务         | 未来           | □ 提交方案   明天截止   工作      | 计划日期／截止
日历         | 全部           | 今日要做                         | 安排到日历
             | 清单           | □ 准备评审   15:00–16:00         | 关联笔记
             | 完成与取消     | 今日时间安排                     | 详情正文
             |                | 14:00–15:00 评审会                | 保存／取消编辑
```

今天页把“要完成的事”和“已占用的时间”放在同一页，但任务行与事件行有不同图标与操作。逾期独立提示，不把所有未完成任务都塞入今天。列表行优先显示标题、状态和最需要注意的日期；次级操作收进菜单，不能用纯色表达截止或冲突。

快速新增先填标题，回车建立无日期任务；可展开计划、截止与清单。高级选项不阻碍快速收集。详情使用明确保存，保存中仍输入时只确认提交快照；关闭抽屉前询问保留编辑或放弃，不能误把已提交旧快照当最新内容。

## 日历

顶部为今天、前后翻页、当前日期范围、月／周／日／议程和时区。月视图适合概览，周／日适合安排时间；未安排任务抽屉可选择任务后“安排时间”。拖放只是快捷方式，所有动作都有表单等价入口。

事件点击打开详情；从空白格建立事件时预填日期／时间并确认。全天栏独立于小时网格。任务时间块带勾选状态和关联任务入口；任务截止用标记展示，不画成占用时间的会议。重叠显示警示与冲突详情，不擅自挪动其他事件。

拖动后立即显示“保存中”；成功后确认，失败恢复服务器位置，同时在详情保留待提交的新时间。系列事件的修改弹窗明确选择“仅本次／整组未来”，没有默认批量改动。

## 手机

390px 默认展示今天或议程，日期横向切换、任务卡片纵向滚动。月视图用于跳转日期，周网格作为用户主动选择；新增和筛选按钮保持可触达。详情使用全屏页而非三列缩小版，返回时保留筛选与位置。

所有主要触控目标至少 44px；键盘可遍历，焦点返回触发入口。日期支持直接键入、选择器与时区说明；输入法组字时不提交。拖动不作为移动端唯一排期方式。

## 三条日常流程

1. 从笔记行动：选中“周五前提交方案”→ 建立任务 → 确认标题与截止 → 出现在任务列表，保留来源链接；原笔记不被改写。
2. 安排一天：今天页选中“准备评审”→ 安排时间 → 周四 15:00–16:00 → 日历形成时间块，任务截止不变；完成任务时明确显示未来安排仍存在。
3. Agent 调整：用户要求“把明天下午的准备时间移到上午十点”→ Agent 查询对应事项和版本，必要时澄清对象／时长 → 更新成功后回复准确时间，日历重新可见时刷新。

## 状态与提醒

统一提供正在加载、空列表、未保存、保存中、已保存、冲突、结果未知和离线状态。冲突提供当前服务器值与本地输入对比；未知结果显示“核对操作”，不重复创建。来源失联显示可重新关联的提示，不删除任务。

阶段 A 不出现可点击但无效的提醒开关。阶段 B 加入站内提醒中心，区分到期、渠道已接受和已读；关闭页面时能否通知必须与实际渠道一致。重复表单展示未来三次发生，用户在保存前能看到短月或时区调整的效果。

## 视觉与连续性

复用 Harness 字体、间距、圆角、亮暗色和图标规范；任务页 CSS 限定在插件容器。信息密度应支持真实任务管理，不只显示大卡片和空白区。Files.md 仍在独立 iframe 中保持原生菜单与风格，不为统一视觉重写 vendor 或裁剪功能。

桌面、390px、键盘与 Chromium 是不同验收切面；物理手机、WebKit、原生输入法和真实通知各自记录证据。没有通过的设备能力不以设计图或模拟视口代替。
