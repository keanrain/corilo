# Corilo 可里交互设计

v0.30 · 2026-11-10。当前业务规则见 [PRODUCT-SPEC.md](PRODUCT-SPEC.md)，模块与实际验收见 [TECHNICAL_DESIGN.md](TECHNICAL_DESIGN.md)。本轮解决整体像表单、操作零碎的问题；不能用控件存在或测试总数替代完整流程与实际画面的检查。

保留 Harness 的对话、会话、模型设置和默认工具。Corilo 增加笔记与待办入口，继续使用宿主 React 18 和 Astryx Neutral 0.7.11 静态 token，不嵌套旧应用或引入第二个 Agent／模型配置系统。参考 [Obsidian 笔记管理](https://obsidian.md/help/manage-notes)、[文件列表](https://obsidian.md/help/plugins/file-explorer)及滴答清单的[快速添加](https://help.ticktick.com/articles/7055782422935240704)、[任务详情](https://help.ticktick.com/articles/7055782408586526720)，采用常见操作结构。

## 笔记：打开就写

桌面左侧浏览笔记，右侧是一张连续的文档。上方只放新建、轻量保存状态、编辑／预览切换和更多操作；标题直接在正文上方呈现，不把文件名、重命名、保存说明分成多张表单。文件扩展名不占标题显示，所属目录仅作为次级路径提示。

默认点击“新笔记”即创建正式 Markdown 文件并把光标放入正文，主机选择未占用的“未命名.md”“未命名 2.md”等名称。初始空白页面也可直接输入，停止输入后用同一新建服务一次保存初始原文。正常记录不要求先命名或首次再点提交；出现失败／未知结果则保留输入并停止自动重试。

点击文档标题即可原位修改名称，Enter 或离开标题确认，Esc 取消并回到正文，输入法组字时不提交。只改同目录名称；同名拒绝、失败保留名称输入，未知结果进入核对新旧文件的界面。这里使用小型确认／取消操作，不再新增一个“新文件名”设置表单。正文未保存或请求进行中不同时改名，不自动重写笔记链接或待办关联。

正文复用 CodeMirror 6 编辑与 Lezer Markdown 解析，标题、强调和行内代码直接呈现样式，非当前行收起其标记，光标返回时显示源文。常用格式、撤销／重做和正文查找放在轻量工具条，支持 Ctrl／⌘B、I、F 和 Markdown 列表回车续写；不要求用户手打所有标记，也不转换成私有富文本格式。保存回执不重置光标／撤销历史，切到另一篇笔记隔离撤销历史，组字期间暂停自动保存与格式按钮。

完整阅读预览仍复用 markdown-it 与 DOMPurify；桌面可并排，手机在编辑／预览之间切换。只有主动打开完整预览时才解析 HTML，超出阈值明确暂停预览，完整正文仍能编辑保存。原始 HTML、危险链接、主动图片和其他网络资源不执行或加载；编辑器的即时样式不是附件、表格或嵌入块的完整所见即所得编辑。

自动保存属于插件生命周期，切换到其他 Harness 页面继续执行。提交中可继续写，成功只确认提交快照；后续输入不被响应覆盖。默认切文档或新建前，先等待当前修改保存成功，再读取目标；同路径重新打开也不能用保存前的旧读覆盖新内容。保存失败停留原处。恢复后尚未继续编辑的草稿，以及关闭自动保存的手动模式，先安全保留再切换，不因导航自动提交。失败／未知结果时仍可点列表核对文件，但需明确确认先保留草稿；随后只读所选文件，不自动重发创建。恢复草稿只回到编辑器，不因恢复本身写入主机。冲突、失败及未知结果始终可见，并暂停自动提交。

用户可在“更多操作”关闭自动保存，使用显式保存／Ctrl／⌘S；这一手动工作流保留“仅保存原话”的语义和兼容入口。它不是默认记录路径。首屏不放解释浏览器草稿机制的长段落，正常保存反馈只用工具栏的小型状态；保护失败仍直接告知。

## 待办：记下一件事，做完就勾

参考开源 [Vikunja 的快速添加](https://github.com/go-vikunja/vikunja/blob/main/frontend/src/components/tasks/AddTask.vue)、[任务行](https://github.com/go-vikunja/vikunja/blob/main/frontend/src/components/tasks/partials/SingleTaskInProject.vue)与[详情说明](https://github.com/go-vikunja/vikunja/blob/main/frontend/src/components/tasks/partials/Description.vue)，以及 [Super Productivity](https://github.com/super-productivity/super-productivity) 的清单与键盘操作（对照其官方演示 `docs/screens/reel.gif`）。复用常见交互模式，不嵌入整套 Vue／Angular 应用，也不引入项目管理或时间追踪流程。

默认入口为一个快速输入框和清单。输入标题后回车新增，成功清空并继续聚焦输入框；列表勾选直接完成，反馈可撤销。状态切换和搜索清楚可见，标题／首行说明组成行内容，不重复每行同一状态文案。

快速录入行位于清单内，状态和搜索位于其上方；从已完成／已取消视图新增后回未完成，从全部视图新增保持全部，成功新增会清除当前搜索，让新事项可见。清除搜索提供直接入口。更多操作使用不挤动内容的浮层，外部点击或 Esc 关闭；导出和详细新建仍是次级入口。

列表聚焦时 N 回到快速输入，/ 聚焦搜索，上下方向键移动任务标题焦点，Enter 打开；输入框内不截获字符，组字期间不导航或提交。Esc 从详情保存后返回；冲突、失败和未知结果仍阻止离开。

点标题按需查看详情。桌面在列表旁打开内容面板，手机进入独立详情并能返回；标题和说明直接编辑，顶部保留完成勾选、轻量状态和关闭操作。正常已有事项不再显示独立的保存／完成按钮区或多层表单标题。标题自动换行，说明按内容伸缩，有行数上限以保留其他操作空间；短说明不常驻大文本框。图标使用 Lucide，伸缩复用 react-textarea-autosize，均使用宿主 React。

默认在离开编辑区域、切到另一事项或返回列表时保存已修改详情，再继续目标操作。插件内动作统一安排保存与后续请求，第一次点击不能因为 blur 触发保存而被吞掉。组字期间不提交；失败／冲突留在原内容，未知结果保留原 UUID 供明确重试，不能自动换号或重发。草稿恢复本身不提交；用户明确继续编辑／保存后仍检查原版本。

“更多操作”可关闭离开详情时保存，保留手动工作流和详情草稿的明确恢复。详情草稿只属于该事项，不携带独立快速输入，不把已经新增过的标题带回来；归档／导航间的崩溃窗口仍保留完整恢复副本。导出、取消、关联路径及放弃修改退到次级入口。

## 辅助与异常

笔记的恢复草稿位于侧栏，历史、回收站和手动开关位于更多操作。只有需要时展开，不在正文前堆叠大块恢复面板。手机先显示文档，查找切到列表，打开结果或恢复后回正文；编辑、列表和预览不纵向堆叠。

存储失败、版本冲突、未知提交和身份改变不是可折叠的普通说明，必须在当前流程直接可发现。只在落盘确认后显示已保存；浏览器恢复副本与主机文件区分，不能把草稿当备份。历史恢复、删除和重命名共同遵守版本与进行中操作锁。

窄屏输入至少 16px、主要触控目标至少 44px，工具栏和主要操作在缩小视口仍可达。最终应查看正常桌面／手机画面，并完整走过新建→输入→切换→再打开，以及新增→详情编辑→切换→完成／撤销；保留录入和保存错误的独立回归。Chromium 触控模拟不代表物理手机、原生输入法或 WebKit 已验收。

日期、日程、提醒、联动和自动记忆仍暂缓，工具执行计划不混入个人待办；不增加虚假的日历或提醒入口。
