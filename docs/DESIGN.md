## 1. 设计方向

**像给自己发消息一样轻，像打开自己的文件一样可控。** 接住想法、找回背景、接着做事；不将知识目录、复杂任务面板与 Agent 操作台一起堆到首屏。

Files.md 是轻量输入、文件自主与低维护负担的参考，技术稿第 2 节维护上游证据。已有页面和编辑器优先验证复用，不为采用新名称先全面重画。本文是可里自身的设计要求，不声称上游已经实现所有交互。

产品显示名采用用户已确认的“Corilo 可里”：英文 Corilo，中文可里；助手直接称“助手”。续页/Xuye、PersonalOS/Jarvis 不作为用户需要同时理解的第二套品牌。历史设计图仍保持原名称，不用修改说明文字冒充修改了画面。

## 2. 信息结构与接管

首屏以对话/输入区为主，显示当前讨论、真实结果与必要状态。侧边栏按需打开知识目录、搜索、任务和今天。项目从相关内容组织中进入，不要求新用户先建立项目才能留一句话。

不增加“手动模式”按钮。来源、笔记或任务在需要时打开，返回恢复同一 conversation、输入与滚动位置。手机折叠侧栏、按视口切换阅读和对话，并不另建一套移动业务页面。

不默认出现待清空的 Inbox 计数、Skill 卡片墙、内部执行流水或要求配置模型链路的向导。必要的模型配置、同步开关和通知授权可以从设置与使用时提示进入，不成为普通本地记笔记的强制前置步骤。

## 3. 输入与回应

同一个输入框承载记录、问题、修改和行动。用户不必先选类型；仅保存提供轻量入口且不调用模型。输入的真实意图、字段有效性及确认边界以 SPEC 2.1.2、3.3 为准。

| 场景 | 画面应呈现 | 不应呈现 |
|---|---|---|
| 随手留一句话 | 本地已保存及可打开记录 | 自动补一个待办或要求选目录 |
| 提问/讨论 | 带来源的回答、继续追问入口 | 未经要求的永久笔记或任务 |
| 明确追加 | 实际结果，差异可展开 | 每次都强制审批整个文档 |
| 正文改写/多行动 | 可核对差异和选择项，选中结果统一保存 | 无限重复确认或多个互相独立的假保存 |
| 日期歧义 | 在当前会话补问必要信息 | 把用户送回完整表单重新开始 |
| 模型不可达 | 原输入、真实失败/暂停，以及仅保存/手动操作 | “已经记住并安排”却没有落盘 |

原始表达、讨论回复、知识结果和任务卡片通过可读样式区分，但不用四种入口逼用户分类。一个任务可在不同页面出现，仍是同一个对象，不由 UI 复制状态。

## 4. 状态分开，细节按需

| 维度 | 状态示例 | 用户应理解的含义 |
|---|---|---|
| 输入/内容持久化 | 未保存、已接收、本地已保存、恢复中 | 内容是否真正可在本机重开找回 |
| 助手处理 | 处理中、需补充、待确认、完成、暂停、失败 | 本次工作推进到哪里，不表示云端或通知成功 |
| 可选同步 | 仅本地、待同步、已同步至版本、冲突、同步失败 | 哪个版本被远端接收；不是所有设备已经更新 |
| 当前设备提醒 | 未启用、未授权、待安排、已安排、安排失败 | 本机系统实际调度状态，而非另一个任务状态 |

首屏给出与当前动作有关的短状态，不固定堆四排徽标。用户需要时展开完整状态；有失败、未知、冲突或恢复时不能隐去。

示例回执：“已更新《方案比较》并保存‘验证内存占用’。本地已保存；云端待同步；本机提醒已安排。”只有实际成立才使用。未安排则换成真实状态；提醒时间展示消歧后的绝对日期、具体时刻与日程时区。

不展示未实现的一键全组撤销。可打开结果、查看差异、查阅修改前内容；复制恢复属于一次新编辑，不能暗示会撤销其他任务或后续同步。

## 5. 行动安排的最小交互

任务详情只需标题、可选描述/来源/项目、状态、计划、截止、一次提醒。默认隐藏未使用字段；自然语言填入后用户可核对和手改。三种时间可分别为空，不能设置提醒就强制填满排程。

Today 只呈现同一任务，区分今天与待处理积压，显示已有未来计划但不悄悄改日期。无日期任务可在全部任务中找到。到期不复制回聊天，完成不删除背景；恢复不自动重开旧提醒。

M0 不展示尚未实现的时间块拖拽、自动排程、重复任务、日历网格或系统日历同步按钮。日程的有效性来自清楚的任务属性，不来自看起来像完整日历的画面。

## 6. 本地、同步与冲突的可理解性

首次本地使用不要求同步账号。选择/创建本机库时说明存放范围，不把演示内存当成正式本地文件。正式容器无法持久保存时明确阻止成功反馈。

开启同步时先展示本地库与远端库的绑定、范围、同名和差异。关闭同步与删除云账号不应出现“本地内容不可用”；“删除笔记”“移除本机副本”“删除远端库”是不同动作和确认文案。

冲突预览保留双方和受影响关系，解释需核对的原因；不把两份冲突文件当成两条正常任务展示。恢复中不开半组正式视图，显示真实范围，并保留无关可用的本地工作。

## 7. 多端同一页面的验收

同一前端构建包含对话、编辑器、目录、查找、任务、Today、确认与同步状态。不同容器只适配系统能力与窗口形态；逻辑与状态不按端复制。

首轮就验证离线首次启动、中文输入法、长文编辑、软键盘遮挡、安全区、返回手势、来源页回对话、容器挂起/重开，以及从系统分享和通知动作进入正确本机库。不能用 Chrome 截图替代手机系统行为。

不因借鉴 Files.md 就默认其主题、图标或所有快捷键都是新品牌最终设计。先确保已有体验不退化；视觉品牌、Logo 和最终商店图不属于此次文档交付。
