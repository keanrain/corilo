# learn-anything

**简体中文** | [English](README.en.md)

Corilo 自有界面跟随 DSH 语言设置（中文／English），切换不改变用户内容或草稿。教学材料、提示词和作答协议保持原有语言。

学习导师：DeepSeek Harness (dsh) 的个人学习插件包，按渐构方法规划路线、诊断、出材料、新情况验证、间隔复习。

本项目位于 [Corilo 大仓](../../README.zh-CN.md) 的 `packages/learn-anything/`，独立以 `@corilo/learn-anything` 分发，版本与 notes／todos 分开维护。

源码开发时在大仓根目录运行 `npm run setup:learn-anything`，依赖锁保留在子项目内，与 notes／todos 分开维护。随后可在本目录运行原有的 `npm test`、`npm run build`、`npm run test:boot` 和评测命令，也可从根目录运行 `npm run test:learn-anything`、`npm run build:learn-anything`、`npm run pack:learn-anything`。根目录打包命令将 `.tgz` 写到大仓根目录；在本目录执行 `npm pack` 则写到本目录。发布只针对此子项目，不发布大仓根包。

原项目的源码、测试、提示词、skills、研究资料及市场索引一并迁入；`PROMPT.md` 和 `research/` 保留项目设计历史。市场索引的仓库路径现为 `packages/learn-anything/market/index.json`。导师以独立 DSH 插件运行；知识助手的实现状态见大仓说明。

## 安装

仅支持**已有 DSH 用户**。需要 Node.js ≥ 24.9、DSH `0.2.2-rc.3`，以及 DSH 插件管理所需的 pnpm。

在大仓根目录构建分发包：

```sh
npm run setup:learn-anything
npm run build:learn-anything
npm run pack:learn-anything
```

将生成的 `.tgz` 安装到已有 Web profile（把 `web` 换成你实际使用的 profile 名称）：

```sh
dsh plugin --profile web add /absolute/path/corilo-learn-anything-0.1.0.tgz
```

重启该 DSH 实例，在已有工作区中新建会话并选择「学习导师」预设。学习记录保存在会话工作区的 `.learn/` 中。

插件只添加教学预设、工具与界面，不创建专用 profile，不自动切换工作区，不改变宿主默认预设、会话日志或插件清单设置。宿主启动、模型配置与插件更新均使用 DSH 原有流程。

`market/index.json` 保留为后续 npm 发布后的市场索引；其安装目标是 npm 包，尚未发布时使用上述本地 `.tgz`。发布时同步索引的 `version` / `publishTimestamp`。`PROMPT.md` 与 `research/` 中的独立启动方案仅为历史设计。

## 互动题

正式成绩由宿主核验：`verification_record` 从会话取得已展示题目与真实作答，内部调用独立考官；导师自报的正确答案或判定不能增加掌握度。相同作答只记录一次，缺少证据或判题失败时不写入。历史记录保留，但没有会话及考官来源证据的旧成绩不再计入掌握，升级后可能需要重新验证。原话保存也要求可读取的学习者历史及完整语句，求助消息不能作为规律。

路线选择优先完成 `prerequisites`，拒绝循环依赖。明确请求跳过/恢复可用 `kp_skip`，跳过不等于掌握。难度 1 仍要求实质新情境，考官未确认新颖性的题不计独立掌握。

只读卡片（路线、靶图、进度、判题反馈）在**最终回答**中与文字按阅读顺序混排，不显示在工具执行过程里。展示工具返回的 `[标题](learn-card:...)` 引用由导师原样独立成段放在正文所需位置，前后留空行；引用对应本轮真实工具结果，不复制卡片 JSON 或导师私有参考。题卡与翻面闪卡保留在原生右侧「学习」工作区，正文保留打开入口；收起或求助后仍可恢复草稿，历史练习可回看。窄屏使用原生全屏展示。

诊断、讲解和归纳阶段的案例判断、对比、预测和排序也优先使用题卡：`quiz_show(purpose="practice")` 标为「理解练习」，提交后继续反馈和追问，不写验证记录或提升掌握度。正式验证沿用默认流程；简短核对和用户用自己的话完整归纳规律仍在正文中进行。

验证题默认以互动卡片出现在学习工作区，按题型选组件：情境卡 / Boss 关（迁移题）、找冒牌货、配对分拣、滑块预测、选择、改写气泡、举例工坊、理由框，以及下面四种玩法。考官把题目再写一份
[OpenUI Lang](https://github.com/thesysdev/openui) 程序，导师用 `quiz_show` 校验后显示，学习者在卡片里作答，
答案作为「【作答】…」消息发回，照常交给考官判题。卡片里没有标准答案；显示不了时退回文字题。

### 四种玩法（独立 Exercise）

题型（`questionType`）不变，题卡另有四种作答形式。它们是独立的 Exercise：`src/quiz/examples.js` 导出
`PLAY_EXAMPLES`，四道完整样例覆盖编程与日常两个领域；每个 `view` 都是完整的 OpenUI Lang 程序，不依赖
DSH，装了同一组件库的宿主可以直接渲染。题卡和文字版内容一致，且不含标准答案。

| 玩法 | 检验什么 | 学习者做什么 | 组件 | 配的题型 |
|---|---|---|---|---|
| 反例侦探 Counterexample | 概念边界 | 从候选里选一个能推翻说法的案例，指出缺失条件 | `Counterexample` | `discriminate-neg` |
| 最小改动 MinimalChange | 输入 → 输出 | 只改一个条件并写理由，其余原条件原样保留 | `MinimalChange` | `scenario` / `contrast` |
| 双局预测 DualPredict | 单因素变化 | 两场从同一组选项里各预测一个，并解释差别 | `DualPredict` | `predict` |
| 迁移任务 TransferTask | 实质陌生的新情境 | 写实际方案，并说明原规律为什么在这里适用 | `TransferTask` | `transfer` |

迁移任务写清决策目标和实际约束；涉及经济决策时，另需写清收益/成本口径（例如是否只求收支平衡、有无补贴）。
四种玩法都已内含理由，题卡不再额外放 `Reason`。标准答案、应选案例、缺失条件和推荐改法只留在考官私有内容里，
不进入题卡；一次选对不自动掌握，掌握仍按连续、无提示、非蒙的新情况验证累计。最小改动只做结构校验，
不做自动语义判分。

`src/client/exercise.js` 的独立 `Exercise` 用 `status` 把两件事分开：`status.readOnly` 表示这张卡不能编辑、作答
（例如只读展示或归档），`status.canSend` 表示当前宿主/会话能不能把答案送出去（例如正在发送、输入框被占用）。
`status.canSend: false` 不代表题目不可编辑；`status.readOnly: true` 时即使 `canSend` 仍为真也不能提交。
调用方分别传这两个字段，不要合并成一个 `disabled`。
`status.sending: true` 在实际发送期间暂时锁定作答；未确认或失败的 `status.pending` 本身不锁定编辑。

纯规则在 `src/quiz/program.js`（解析、可作答校验、文字回退）和 `src/quiz/play.js`（答案完整性、可读格式）中。
`src/client/exercise.js` 导出受控 React 组件 `Exercise` 和 `QUIZ_CSS`；调用方提供 `view`、`answers`、
`onChange`、`confidence`、`onConfidenceChange`、`status`、`onAction`。动作是 `submit`、`hint`、`help`、`easier`、
`harder`、`break`；提交携带 `{title, answers: [{prompt, value}], confidence}`。调用方确认提交后再传
`status.closed: 'answered'` 和可读的 `status.answerText`；失败时保留作答并传 `status.error`、`status.pending`。
DSH 的历史、缓存和消息发送集中在 `src/client/quiz.js` 适配层，增加玩法无需改课程存储或掌握度算法。

“没看懂”可选择“这个词不懂 / 不知道从哪开始”，发出 `{type: 'help', kind: 'term' | 'approach', title}`。
导师补一个必要概念或起步例子，再回原题；草稿保留，求助本身不判分。补讲计入本题辅助次数，不消耗两级提示的顺序；后续另用新情况检验独立应用。直接打字说概念陌生或从零讲也能触发补讲。

同题消息被宿主接收、仍在排队时，题卡阻止重复提交，草稿仍可编辑；撤销排队消息后可重新提交。作答状态以真实会话消息为准。复习提醒使用 DSH 原生任务管理：暂停或删除后不会因下一次答题自动重建；明确要求设置提醒时间时才恢复或新建。
流式题卡最终校验失败时隐藏预览，保留工具错误与文字题回退，不触发对话窗口重建。

需要分清执行与等待的题，可显式传 `quiz_show({ui, question, helpDemo: 'execution-waiting'})`，补给入口会出现“动手看一眼”。首次使用会先确认补给请求，再展示演示；操作完成回到原题，已填答案保留。旧题未携带此字段时保持原样。

`src/client/task-demo.js` 的 `TaskDemo({config, disabled, onAction})` 仅依赖 React，接收场景文案，返回 `mode / place / inspect / reset / return` 操作事件，不发消息、不保存记录、不判分。演示预设两个执行位、等待区有空位，只帮助认清“正在执行 / 尚未开始”；实际题目中的扩容、拒绝和交接按题面判断。独立使用时注入 `TASK_DEMO_CSS`；挂载到 `Exercise` 时传 `helpDemo: TASK_DEMO_SCENE`，由调用方在确认辅助后传 `status.demoReady: true`，操作从 `{type:'demo', title, event}` 返回。

验证阶段按心流理论设计成一段连续练习：
- **难度贴着能力走**：每个模型有一条 1～5 级的难度阶梯，连续两题无提示答对升一级，答错降一级，其余保持（这种 2 升 1 降的阶梯会稳定在七成左右的正确率）。导师把这一级的要求交给考官出题，卡片标题旁显示难度点。
- **即时、有信息量的反馈**：判题卡片显示对错；作答时的把握和结果对不对得上（很有把握却答错，说明有个误解）；一张「挑战 × 技能」心流图，标出这题落在心流区、偏难还是偏轻松，以及下一题的难度和原因；离下一级还差什么（再连对几题、还缺哪种题型）。答错时用「上层规律 ↕ 下层例子 / 地基」示意哪一层出了问题。考官给导师的反馈要点不会给学习者看。
- **不打断**：答对或部分对时模型留在验证阶段，导师在同一轮里接着出下一题；只有答错才回到诊断。
- **掌控感**：卡片上可以选把握（稳 / 有点把握 / 蒙的，蒙对的不计入熟练进度），可以要提示（考官预先写好两级提示，只指方向，题目继续开着），可以嫌太难或太简单换一道，也可以歇一会儿。

还可以在对话中请求这些练习：
- **四种玩法**：反例侦探 / 最小改动 / 双局预测 / 迁移任务，见上表；可以指定其中一种出题。
- **翻面闪卡**：信息类知识点先选「能独立回忆 / 只记得一部分 / 暂时想不起来」，再翻面核对。选择「再练一次」可安排稍后重现；自评本身不增加掌握度，正式回忆会另行验证。
- **找茬修复**：点出有问题的一行，再写出自己的修正，适合辨认误解和代码缺陷。
- **步骤排序**：依次点选打乱的步骤，支持撤销和重新排列，适合推演执行过程。
- **错题重赛**：从仍有效的错题中选取薄弱点，生成同一知识目标的新情境，反馈对照两次回答；重赛答对后不再推荐对应旧题。

找茬和排序复用互动题的提交、重试、历史恢复与教材引用；题卡只包含题面，答案由考官独立判定。翻面闪卡是用于揭晓已有事实答案的自测卡，与正式验证分开。

输入框下的状态条显示连续学习天数 🔥。eval 统计卡片的渲染成功率、答案泄漏、记录了难度的验证占比和落在心流区的作答占比（`quizParseRate`、`quizLeaks`、`difficultyRecordedRate`、`flowZoneShare`）。不想要互动卡片，在学习导师预设里给 `@corilo/learn-anything/tools` 设 `interactiveQuiz: false`。

## 教材检索与引用

`material_search` 按空格分隔关键词，标题或正文部分命中也会返回；优先按命中不同关键词数、标题命中数、正文词频排序。导师读取真实块后引用其 ID，`checker` 对照原文核对关键说法，出题和判题沿用这些来源。

靶图显示参考资料和例子来源，判题卡显示判题依据。题卡提交时会带上教材引用；作答前不展示依据链接。写入教材引用时会检查块是否存在；内容是否支持说法由 `checker` / `examiner` 核对。没有教材时仍可正常教学。

重新导入同一路径时，相同内容复用材料 ID，内容变化会创建新 ID 并保留旧块，已有引用继续指向原文。材料列表和默认检索只展示该路径最近导入的内容。

## 开发

`src/client/index.js`（Web 端）和 `src/vendor/openui-lang-core.js`（宿主端用的 OpenUI 解析器）是
`npm run build` 生成并提交的文件，用户安装时不需要构建，也不会装 OpenUI 的包；改了 `src/client/`、
`src/quiz/` 后重新构建，`npm test` 会检查生成文件是否最新。

- `npm test`：工具、教材、卡片状态和插件包回归。
- `npm run test:boot`：在隔离 profile 中检查真实 DSH 的插件装配，使用模拟模型；另以 1 秒任务验证原生定时投递、暂停不投递及单次回执。
- `npm run eval:mock -- --only materials --until verified`：用三个教材场景检查引用贯穿出题、作答和判题。场景异常、代写、答案泄漏、无效引用落库或引用链丢失会使评测返回非零退出码。mock 检查链路，真实模型的语义判断仍需单独评测。
- `npm run eval:mock -- --quality`：离线检查 8 个固定题目质量案例与失败判定；`npm run eval -- --quality` 使用 `DEEPSEEK_API_KEY` 跑真实考官，也可加 `--anthropic` 沿用现有网关配置，或 `--only alternative-solution` 只跑一个案例。覆盖卡片漏条件、产能无法推出限时交付、文字版漏选项、合理替代解、等价措辞、选对但理由错、反馈过度归因和正常正确作答。判定错误、归因缺少原话证据、已知的过度归因、接口错误或截断都使命令退出非零；报告分开统计质量失败和请求错误，并保留实际提示与回复。这组案例检查已知缺陷，不能替代新生成题目的语义复核；mock 通过不代表真实模型通过。
- `npm run eval -- --only repair --until verified --no-judge --keep`：在临时课程中注入一次“卡片漏规则”的出题结果，随后使用真实导师、考官和学习工具，检查质疑后暂缓判定、修题、重新作答和仅记录一次结果的完整链路。重新作答前若有验证记录、掌握度或复习安排变化，评测失败。该场景仅显式选取时运行，不支持 mock；它检查 Host 与落库，不检查浏览器里的草稿保留。
- `npm run eval -- --only learning-loop --until verified --no-judge --keep`：在临时课程的首张真实题卡后发送一次固定求助，其余出题、作答和判题使用真实模型。检查补讲保留原题、辅助作答不计入独立掌握、下一张新题无辅助答对后才累计一次连续答对；失败返回非零。该场景仅显式选取时运行，不支持 mock。
- `npm run eval -- --only prerequisite-recovery --no-judge --keep`：用隔离相机课程重现“多个基础概念不懂、却反复验证”的求助，随后确认先学基础。真实导师运行两轮；自动检查基础提前、原表述和掌握度保留、求助期间没有继续出题判题，失败返回非零。另需人工阅读报告的 `recovery.replies`，确认实际开始讲基础，而非仅承诺调整；不支持 mock。
  该场景可加 `--local-auth`，通过 DSH 凭据服务沿用本机已保存的 API 凭据；课程与会话仍在临时目录。两轮学习者消息及选项确认均使用固定文本，不额外调用模拟学习者模型。此模式只支持该场景及 `--no-judge`，不能与 `--anthropic` 混用。
- `npm run eval -- --local-auth --only trust --until verified --turns 3 --no-judge --keep`：沿用 DSH 已保存的 API 凭据，在隔离课程中用真实导师出题、固定学习者作答、宿主独立判题，检查落库原文与会话消息完全一致并带考官来源证据。`--local-auth` 同样支持此场景。单样本检验来源链路，不代表考官语义判断的普遍准确率。
- `npm run test:browser`：`http://127.0.0.1:3092/playground` 直接运行四玩法的独立 `Exercise`，查看结构化事件并验证只读、流式锁定、失败重试；`http://127.0.0.1:3092/` 保留原有卡片的插件适配回归，检查草稿、历史恢复和新题关闭旧题。只使用独立测试数据，不调用模型或修改学习记录；`Ctrl-C` 清理临时构建。
- `http://127.0.0.1:3092/demo`：直接运行独立的执行与等待演示，查看两种状态、区域解释和操作事件；根回归页的题卡同时验证补给请求、辅助计数与返回原题。

评测报告包含首题就绪时间、提交到反馈的耗时、同一轮反馈到下一题的等待（`nextQuizMs`），以及每题生成和判题的导师模型步数。下一题等待排除用户思考和后续回合，末题没有后续时为 null。耗时以 Host 事件为准，不代表浏览器完成绘制；子代理调用成本另行统计。

报告的 `performance.models` 和 `performance.tools` 按会话、轮次、步骤及调用 ID 关联导师和子代理耗时。模型项提供步骤开始到回复、首 token 等待及解码时间；工具项提供调用到返回的时间。缺少事件证据时为 null，重试等待不混入解码时间；步骤耗时包含请求准备，不等同于纯 API 耗时。可配合 DSH 的「开发者工具 - 统计」定位慢在导师准备、考官生成还是工具执行。

考官保留推理，普通出题和判题默认使用 `low` 强度；排序推演、多步计算等复杂任务通过 `examiner.reasoningEffort: "high"` 使用较高强度。模型选择、导师与校验员的设置沿用原配置。教材核对和题卡校验保持原流程。

单独测考官出题耗时（默认与考官使用相同的推理强度；可用 `--reasoning high` 对照）：设置 `DEEPSEEK_API_KEY` 后运行 `node eval/question-latency.mjs --case order --runs 3`（或 `--case spot`）。使用当前考官提示词及组件定义，不读写学习记录；报告保存在 `eval/results/`。对照旧版时用 `--system-file` 指向此前保存的完整系统提示词。报告只自动检查输出完整性和卡片语法，题目条件、标准答案和唯一顺序需人工核对；该耗时不包含导师准备和展示题卡的时间。`--self-check` 可离线检查评测脚本。

同一 Host 进程中，同一工作区的学习数据写入按队列执行。修改已经作答的模型定义时需要新 ID；信息类知识点按每张记忆卡分别检查掌握度，所有卡片达标后才算掌握整个知识点。
