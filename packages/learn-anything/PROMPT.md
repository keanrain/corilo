## 1. 产品一句话
用户输入学习目标（可附材料），Agent 结合材料和网络搜索规划学习路线，再按"诊断 → 开方 → 执行 → 复诊"的循环，带用户把每个知识点真正学会。这里的"学会"指能处理没见过的新情况，而不是"感觉懂了"。

## 2. 教学方法论（产品核心，所有教学行为必须遵循）
方法论来自《学习观：从感觉懂了到真正学会》（于建国 / YJango）中的"渐构理论"。下面是要点转述；system prompt 中同样用转述，不嵌入原书文本。

### 2.1 术语
| 术语 | 含义 |
|---|---|
| 信息 vs 知识 | 信息是单个具体事实（如"某人生于某年"）；知识是"输入变量 → 输出变量"的映射规律，能用于预测新情况 |
| 记忆 vs 学习 | 记忆是能重现见过的内容，验证方式是复现原内容；学习是能泛化到未见情况，验证**必须用学习材料之外的新情况** |
| 判别模型 | 判断"某现象是不是概念 A"的能力，格式是"x 满足共有属性 → A，否则 → 非 A" |
| 联结模型 | 概念之间的映射，即根据输入的具体状态推测输出的状态 |
| 上层 / 下层 | 上层是抽象规律（规述），下层是具体例子（例述）。知识 = 上下两层连接起来的结构 |
| 知识坍缩 | 下层丢失（会背规律，不会落到具体情况）、上层丢失（只记住例子，不会举一反三）、下上错配（例子归到了错误的规律下） |
| 记言代学 | 只记名称或只记原句，没有建立模型，换一种说法就不认识了 |

### 2.2 知识表示
每个知识点 = **输入概念判别模型 + 输出概念判别模型 + 输入→输出联结模型**。信息类内容不走这套表示，改走记忆流程（间隔重复）。

### 2.3 教学主循环（以单个模型为单位）
1. **描述知识**：从目标和材料中拆出待学知识，写成"输入 / 输出 / 映射规律"，并标注是知识还是信息。
2. **评估学况**：根据用户历史和最近的验证反馈，判断：是否记言代学、偏好先例子还是先规律、有没有知识坍缩、前置知识是否缺失、已有知识带来的正迁移或负迁移、当前掌握程度。
3. **制定材料**：按诊断结果生成或挑选材料，并保证每条规律都有对应的例子：
   - `#d` 规律讲解　`#e` 例子（正例 / 反例 / 对比例组）　`#t` 类比或对比　`#v` 验证题
   - 讲清"哪些因素影响结果"的因素材料，讲清"结果随输入怎样变"的关系材料
4. **继承模型**：引导用户**用自己的话**写出、更新三句表述（输入内涵、输出内涵、映射规律）。Agent 只追问、纠偏，不代写。
5. **验证模型**：出用户没见过的新情况题；答完后把这道题加进例子库，并把反馈交回第 2 步。直到泛化能力达标。

### 2.4 诊断 → 处方
| 诊断 | 处方 |
|---|---|
| 概念混淆 | 对比例组、外延对比（相等 / 包含 / 相交 / 互斥）、特征对比 |
| 上层丢失 | 新情况题让用户意识到目标是规律，再补充规律讲解 |
| 下层丢失 / 例子无效 | 降低例子的抽象层级，换贴近用户生活的例子 |
| 讲解看不懂（缺前置知识） | 先补前置知识，或换用户已知的概念重新解释，或改从例子入手 |
| 记言代学 | 换一种说法重新提问，要求用户自己举正例和反例 |
| 已掌握某个子知识 | 拆分目标知识，复用已掌握的部分（正迁移） |

### 2.5 练习设计
- **主力**：场景题和预测题（新情况）、判别题（"x 是不是 A？为什么"）、对比辨析题、让用户自己举正例和反例。
- **辅助**：换一种说法的问答、费曼式复述（要求不复用原文措辞）、苏格拉底式追问。
- **仅限记忆内容**：填空、原文复述、闪卡。
- **例习循环**：多出来的例子先当练习题用，验证完再当例子；用户忘掉的例子可以重新当练习题。
- **掌握程度**按能稳定处理多少新情况来分级（未入门 / 入门 / 熟练 / 精通），不以"看完了"来计。
- 欢迎你在此框架下补充更有效的手段，但要说明它对应循环中的哪一步。

### 2.6 适用边界
本框架主要覆盖**外显知识的继承学习**。外语听说、运动、乐器等内隐技能，Agent 需要告知用户这一局限，改用以练习和反馈为主的方式，或建议线下练习。

## 3. 功能需求
1. **目标接入**：用户输入目标，可附材料。优先支持 **PDF、EPUB、代码仓库（本地路径或 Git URL）、TXT**；Markdown 和网页链接放到后续版本。代码仓库需要能提取结构（目录、模块、关键接口），不只是拼接全文。Agent 追问现有基础、可用时间、学习目的、偏好（先例子还是先规律）。
2. **路线规划**：结合目标、材料和网络搜索生成大纲：章节 → 知识点（标注知识 / 信息）→ 前置依赖 → 预计时长 → 资源（附来源）。用户可增、删、改、调整顺序，确认后锁定。后续可根据诊断结果动态调整。
3. **学习会话**：按 2.3 的循环逐个知识点推进；每轮都可以看到当前诊断和下一步计划。
4. **渐构靶图**（核心界面）：每个知识点一张可视化卡片，上层是输入概念、输出概念和三句用户表述，下层是例子和做过的验证题。用户随时可以编辑，它就是笔记。
5. **进度与复习**：持久化学习者模型（每个模型的掌握程度、诊断历史、错题、靶图）。关闭后再打开可以继续。信息类内容进入间隔重复队列。提供总览：已学、待学、薄弱点。

## 4. 技术约束
- **底座：DeepSeek Harness（dsh）**。用户通过 `npx @deepseek-ai/dsh web` 启动，直接使用 dsh 自带的 Web 页面；learn-anything 以 dsh 的**插件 / 自定义 profile** 形式交付，不另做独立的 Web 服务和 Agent 框架。
  - 已知事实（npm `@deepseek-ai/dsh`，2026-10 查询）：最新是预发布版 0.2.0-rc.2，另有 0.2.1-alpha 系列；BSD-3-Clause 许可；基于 cordis 插件体系，profile = 按顺序叠加的插件 bundle 加 `cordis.patch.yml`；支持 `dsh plugin --profile <name>` 安装插件，可以用 `--from-default-profile` 从模板创建自定义 profile；内置 skill、persona、subagent、ask-user、todo、MCP client、web 工具等模块。
  - 目标启动方式（调研后确定其中一种）：① `npx @deepseek-ai/dsh web` 加上安装好的 learn-anything 插件；② 基于 web 模板的自定义 profile，例如 `dsh --profile learn`；③ 一个很薄的 `npx learn-anything`，内部完成 profile 初始化后再拉起 dsh web。
- **BYOK**：API Key 只存本地，优先复用 dsh 自带的 Key 配置方式。**MVP 只接 DeepSeek**，选它是因为模型自带搜索能力；以后接其他厂商时，依赖 dsh 自身的模型适配能力。
- **模型调用**：使用 dsh 内置的 DeepSeek Anthropic 兼容 Messages 接口（`dsh-llm-deepseek`，协议不可配置）。已确认不使用 Responses API，详见 `research/phase1-report.md`。
- **搜索**：使用 dsh 内置的 `web_search`（`dsh-web-search-deepseek`，Anthropic 格式的 server tool，返回带 URL 的 Sources，界面显示来源卡片）和 `web_fetch`，不额外接搜索服务。
- **运行时**：Node ≥ 24.9；锁定 dsh 的精确版本（当前 `0.2.2-rc.5`，以 `package.json` 为准）。
- **数据本地化**：SQLite + 文件目录，不依赖云服务。
- **材料可信度**：AI 生成的例子和讲解可能出错，关键事实要附来源，或经过一次自检（例如另一个模型调用校验例子是否真的符合规律）。

2. **Web UI 可扩展性（最关键）**：能否在 dsh web 中加自定义面板或页面，以承载渐构靶图、大纲、进度总览；能否渲染富内容（表格、图）；有没有交互式组件（如 ask-user 用作选择题）。如果不能，有哪些替代方案（例如用插件起一个子页面、用 present 交付 HTML 文件、生成 Markdown 视图）。
