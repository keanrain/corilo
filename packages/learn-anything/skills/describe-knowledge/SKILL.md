# 描述知识（第 ① 步）

目标：把一个知识点写成可以检验的模型，作为之后出材料和出题的标准。这一步是你自己的备课，**不需要用户参与，也不要把参考规律直接告诉用户**。

## 1. 先判断：知识还是信息
- 问自己：掌握它以后，能不能预测一个没见过的情况？能 → 知识；只能回答「是什么 / 叫什么 / 在哪里」→ 信息。
- 规划时标错了（例如把一条规律标成了信息），重新 `course_save` 改 kind 前要先确认它还没有学习数据；否则新建一个知识点。

## 2. 知识：拆出三个模型
从 `kp_get` 的参考资料中选相关块，用 `material_read` 读取原文；找不到时先 `material_search`，必要时用 `web_search` 核对。参考规律末尾标注实际依据的块 id 或 URL，供后续校验和出题使用，然后写：
1. **输入概念的判别模型**（id 建议 `in`）：输入是什么概念？判断一个东西是不是它的**共有属性**是什么？
2. **输出概念的判别模型**（id 建议 `out`）：同上，针对输出。
3. **联结模型**（id 建议 `map`）：输入的哪些因素、怎样变化，决定了输出怎样变化？

`reference` 字段要写得能直接拿来判题：
- 判别模型：列出属性 a、b、c，「同时满足 → 是，缺任一 → 不是」；再写一个最容易混淆的相邻概念，以及区别在哪。
- 联结模型：写清因素（哪些输入影响输出）和关系（怎样影响，有没有边界条件）。

例：知识点「函数」（数学）
- in：判别「自变量 x」——属于给定的非空数集 A（定义域）；
- out：判别「函数值 y」——由 x 经对应法则得到，属于数集 B；
- map：「对定义域里的每一个 x，按对应法则有且只有一个 y 与之对应」——判题时最关键的是「有且只有一个」。

简单的知识点可以只建一两个模型（例如纯概念辨析只需要一个判别模型）。不要为了凑数硬拆。

## 3. 信息：写记忆卡
每张卡一问一答，问题要能从多个方向提问（正向、反向）。信息量大时分组，每组不超过 7 张。
保存后用 `kp_get` 查看每张卡的稳定 id；重存未改变的卡时保留 id，新增或改变事实时使用新 id。后续按卡记录作答，所有卡达标后信息点才算熟练。
需要先熟悉内容时可用 `flashcard_show({kpId, factId})` 翻面自测，展示已保存的问答和来源。先选把握再揭晓，翻面后的自评仅用于安排重现；正式掌握度由未揭晓答案的独立回忆决定，按 `examine` 的回忆流程验证。

## 4. 保存
`kp_define_models` 保存后，模型自动进入「评估学况」。这一步是备课，不必向用户展示；保存后直接加载 `diagnose` skill，用一张理解练习题卡开始评估（第一个知识点尤其如此）。
已有验证记录的模型需要改变定义时，使用新模型 id；原定义的学习记录继续保留，不作为新规律的掌握证据。
