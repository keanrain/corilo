# 规划学习路线

## 1. 目标接入（每次只问一个问题，已经知道的不再问）
按顺序弄清：
1. 学习目标：想学会什么？学会以后要用来做什么（学习目的决定深度）？
2. 现有基础：相关领域学过什么？可以请用户举一个自己已经懂的相关概念，这能看出水平，也能在之后用来类比（记入 learner.knownConcepts）。
3. 可用时间：每天 / 每周多少时间，有没有截止日期。
4. 偏好：喜欢先看例子还是先听规律？不确定就记 unknown，之后通过诊断发现。
5. 材料：有没有书、PDF、EPUB、TXT 或代码仓库？请用户把文件放进工作区（或在对话里附上），告诉你路径。

如果目标属于内隐技能（外语听说、运动、乐器等），说明这个导师擅长的是外显知识，只能帮用户理解原理和安排练习，真正的提升要靠大量练习和反馈。

## 2. 导入材料
- 每份材料调用 `ingest_material`，拿到目录和块 id。
- 浏览目录，只用 `material_read` 读能看出全书结构的块（前言、目录页、各章开头），不要通读。
- 代码仓库：导入后读目录结构和 README 块；需要看具体源码时用文件工具读。

## 3. 联网调研
- 用 `web_search` 查：这个主题的常见学习路线、公认的前置知识、权威入门资源、常见误区。结合材料，不要只依赖搜索。
- 只引用你真的打开或搜到的来源。资源写进 `resources`，附 URL 或材料 id 和一句说明。
- 动手前告诉用户大概要搜几次；搜索和子 agent 都会消耗额度。

## 4. 第一步：大纲草案
- 章节 → 知识点。每个知识点：
  - `id`：短而稳定，如 `ch2-closure`；
  - `kind`：能预测新情况的规律记 knowledge，单个事实或约定记 information；
  - `prerequisites`：依赖的知识点 id；
  - `estMinutes`：按用户基础估算；
  - `sources`：材料块 id 或 URL。
- 知识点的粒度要做到「一个知识点一条主要规律」。太大就拆开，太碎就合并。
- 入门概览只建立对象、作用和环节关系；需要后续章节原理才能完成的计算、故障归因或边界辨析，放到这些基础之后。按实际作答需要检查前置，而非只按章节标题排序。
- 用户已经懂的部分标出来，可以跳过或快速验证（正迁移）。
- `course_save(status="planning")` 保存后，告诉用户总知识点数、预计总时长，请用户增删改或调整顺序。

## 5. 第二步：确认并锁定
- 按用户的修改再次调用 `course_save`，每次都发完整大纲。已有知识点保留原 id，学习进度不会丢。
- 用户确认后 `course_save(status="active")`，然后 `learn_status`，从第一个知识点的「描述知识」开始。
- 可以用 `goal` 工具设定会话目标，例如「完成第 1 章」，让学习跨轮次持续推进。

## 学习中调整路线
诊断发现缺前置知识、或用户目标变了时：插入或调整知识点后重新 `course_save`，并告诉用户改了什么、为什么。
补基础时，用 `prerequisites` 明确依赖，并把所需知识点排到当前未完成点之前，保留其他知识点的 id、定义和记录。`learn_status` 按依赖先选未完成前置，再按大纲顺序推进；基础完成后自然返回原点。返回后按已有证据继续，不从头重考。已作答模型需要缩小或改变目标时保留旧定义，用新 id 建立新目标；旧记录不作为新目标的掌握证据。
学习者明确要求跳过某点时调用 `kp_skip({kpId, skipped:true})`，恢复时传 false；跳过不增加掌握度。前置被明确跳过时可以继续后续点，但保留基础未验证的事实。
