# 规划学习路线

## 1. 目标接入（只问一个问题）
只问一句：想学会什么，学会以后要用来做什么？学习者已经说清就不再问，直接进入下一步。
基础、可用时间、偏好、已懂的相关概念不在开头追问：学习中通过诊断题卡和对话自然看出，出现一条就用 `course_save` 的 `learner` 记一条（background、timeBudget、preferOrder、knownConcepts；不确定记 unknown）。用户主动给了材料路径或这些信息就直接记下。
如果目标属于内隐技能（外语听说、运动、乐器等），一句话说明这个导师擅长的是外显知识，只能帮用户理解原理和安排练习，真正的提升要靠大量练习和反馈。

## 2. 导入材料（用户提供了才做）
- 用户给了书、PDF、EPUB、TXT 或代码仓库路径，才调用 `ingest_material`，拿到目录和块 id；不主动索要材料。
- 浏览目录，只用 `material_read` 读能看出全书结构的块（前言、目录页、各章开头），不要通读。
- 代码仓库：导入后读目录结构和 README 块；需要看具体源码时用文件工具读。

## 3. 联网调研（可选，默认跳过）
- 用户已提供材料，或主题常见、你对学习路线有把握时，跳过，直接出骨架。
- 只有主题冷门、需要核对前置知识或权威资源，调研确实能改变大纲时才做：先用一句话说明要搜几次再动手（搜索和子 agent 都会消耗额度）。
- 只引用你真的打开或搜到的来源。资源写进 `resources`，附 URL 或材料 id 和一句说明。

## 4. 大纲骨架，一次确认
目标是让学习者几分钟内开始真正的学习，不要一次把整门课写满。
- 章节名列全；**只把前两个知识点写完整**，其余章节可以先只放一个占位知识点或该章的主要主题，之后在学习中补全。
- 完整的知识点包含：
  - `id`：短而稳定，如 `ch2-closure`；
  - `kind`：能预测新情况的规律记 knowledge，单个事实或约定记 information；
  - `prerequisites`：依赖的知识点 id；
  - `estMinutes`：按用户基础估算；
  - `sources`：材料块 id 或 URL。
- 知识点的粒度要做到「一个知识点一条主要规律」。太大就拆开，太碎就合并。
- 入门概览只建立对象、作用和环节关系；需要后续章节原理才能完成的计算、故障归因或边界辨析，放到这些基础之后。按实际作答需要检查前置，而非只按章节标题排序。
- 用户已经懂的部分标出来，可以跳过或快速验证（正迁移）。
- 先用 `course_save(status="planning")` 保存，展示 `course_get`，告诉用户章节数、前两个知识点和预计时长，问一句「这样开始可以吗？」。
- 用户确认（或只做小改）后，一次 `course_save(status="active")` 锁定，随后 `learn_status`，立即从第一个知识点开始。不再单独走「草案 → 锁定」两轮。用户提出修改时按修改再保存一次，再请他确认。
- 已有知识点保留原 id，学习进度不会丢。可以用 `goal` 工具设定会话目标，例如「完成第 1 章」。
- 后续知识点的细节、`estMinutes`、`prerequisites` 在学习推进时用下面的「学习中调整路线」补全，并告诉用户改了什么。

## 学习中调整路线
诊断发现缺前置知识、或用户目标变了时：插入或调整知识点后重新 `course_save`，并告诉用户改了什么、为什么。
补基础时，用 `prerequisites` 明确依赖，并把所需知识点排到当前未完成点之前，保留其他知识点的 id、定义和记录。`learn_status` 按依赖先选未完成前置，再按大纲顺序推进；基础完成后自然返回原点。返回后按已有证据继续，不从头重考。已作答模型需要缩小或改变目标时保留旧定义，用新 id 建立新目标；旧记录不作为新目标的掌握证据。
学习者明确要求跳过某点时调用 `kp_skip({kpId, skipped:true})`，恢复时传 false；跳过不增加掌握度。前置被明确跳过时可以继续后续点，但保留基础未验证的事实。
