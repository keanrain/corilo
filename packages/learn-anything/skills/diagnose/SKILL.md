# 评估学况（第 ② 步）

原则：**每条诊断都要有证据**。证据是用户的原话或某次验证记录 id。没有证据时，先问一个能产生证据的问题。
面对用户，用不带引号的转述概括观点，证据不足时先问一个核对问题，动机或情绪不直接定性。诊断记录需要引语时，从用户消息直接复制连续片段，不把概括写成原话。

## 先补地基（任何阶段都可触发）
先区分：只是一个术语或起步动作不清楚，用下面的小块补讲；多个必要概念尚未建立、补讲后仍卡在同一处，或用户质疑反复练同一点时，走“重新检查任务”，不强制回原题。
收到「【学习补给】」或明确说概念陌生、从零讲、无法起步时，先执行这段。求助本身不判对错、不写 `verification_record`；正式诊断继续遵守下面的证据要求。
若消息标明“动手演示”，用户已选择在题卡里操作：用一句话邀请观察“正在执行”和“等待处理”的区别，然后等待用户回到原题，不另出题或重复讲完整解法。
1. 保留当前模型、原任务和题卡，不另开 `quiz_show` / `flashcard_show`，不要求用户先猜定义。术语未指明时只问“哪个词没看懂？”，收到后直接补讲；连续两轮卡住但原因不明时也先问一个具体卡点。
2. “这个词不懂”：只解释最必要的一个术语指什么，用一个小例子区分它与相邻概念。先讲各种实现的共同含义，再按题面或教材补充实现特性；例如队列先解释为等待区，不能默认所有队列都先进先出。类比只帮助认清对象，优先级、先后顺序等机制必须有依据。
3. “不知道从哪开始”：只指出第一步该读哪条已知条件，示范标出这一条或辨认其中的对象，到这里就停。原题的后续步骤和结论留给用户；小例子用更简单、结果不同的情况，不能把原题只换名字或数字完整解一遍。
4. 本轮用 2～4 句、约 150 字以内补这一小块，以概念区分或起步示范为止。结尾只邀请“回到原题，接着试试”，然后等待；原任务无题卡时，回到原任务。本题该选哪个案例、缺哪个条件及判断标准留给用户，不在结尾追加。用户能继续当前任务就完成本次补给，不重复原题、不追加定义复述或连环追问。
5. 本题后续作答记为有辅助练习。卡片提交的“提示：N 次”已包含按钮补讲；自然语言请求的补讲也计入 `hintsUsed`，与已包含的次数合并、不重复。之后另出新情况检验独立应用。

## 重新检查任务
先读 `kp_get` 的目标、已有作答及最近处方，检查当前任务实际需要哪些概念、这些概念是否已经教过；依据用户原话区分缺前置、题目/参考规律有问题，还是已具备基础但应用有误。明确说“不懂 X”足以先解释 X，不必先用新题凑齐正式诊断证据。
- 缺前置：说明先学什么、原任务留到何时。按 plan-course 的“学习中调整路线”把必要基础提前，随后用 `learn_status` 确认切换并从基础开始教学。保留原进度，不把暂缓当作掌握。
- 目标过重：把概览与深入应用拆开；基础之前只承担概览的要求。已作答模型改目标使用新 id。
- 题目或规律有问题：先核对条件和依据；证据不足的故障归因允许“不足以确定”。更正前暂缓判定。
- 基础具备：直接解释此前没有讲清的那一处，用一个简单对照帮助理解；有新的学习内容后再检验应用。已有回答只缺措辞时，核对具体含义即可，不把重打一整句当作理解进步。
完成条件是教学任务或讲解方式发生了有依据的改变，而非又换了一个场景。新题、重复复述和自动降难度本身不算补救。

## 1. 收集证据
- 第一次学这个课程的第一个知识点（或第一次学某个模型）：不先做多轮问答，开场只放**一张**理解练习题卡当探针：按 coach-statements 的「理解练习题卡」用 `quiz_show(purpose="practice")`，放一个具体案例（或一对 A/B），选项只写结论，并请用户写下判断依据。这张卡不计掌握度。等用户作答后，用选择与依据作为证据；基础、偏好等线索同时写进 course.learner。证据不够区分类型时，只追问一个问题，不再出第二张卡。
- 其他情况：问一个探底问题，比如「你听说过 X 吗？用你自己的话说说它是什么」，或给一个简单的判别题；具体案例判断同样优先用 `quiz_show(purpose="practice")`，简短核对留在正文。用户明确要解释定义或概念时，先按“先补地基”补一小块，再收集证据。
- 判别题的选项只写结论（「算」「不算」），不写理由；理由让用户自己打字说。选项里带理由，用户会照着选，证据就成了你自己的猜测。
- 已有验证记录：用 `kp_get` 看最近的验证题、答案和考官给的归因。验证中第一次答错不进入诊断（见 examine）；从验证回到这里，说明同一归因（都没有归因也算）连续答错或用户「稳」却答错，把这几次作答一起当证据。
- 留意用户的偏好表达：「先给我个例子」→ prefers-examples；「直接说规律吧」→ prefers-rules。

## 2. 诊断清单（逐条过一遍，记有证据的）
探针卡的作答（选择 + 用户写的依据）可直接作为一条证据，`diagnosis_record` 的 evidence 引用用户依据中的原话。第一个知识点可在探针卡与用户一轮回应后就记录诊断，随后在 build 步骤用新情况完成第二条证据。
下诊断前至少要有两条不同来源的证据：一条是用户用自己的话说的意思，一条是用户在一个新情况上的判断或应用。只有一条时，再问一个问题补上；能复述却不会换说法（记言代学），只有这样才分得出来。
用户的**提问**（「那 X 是不是也行？」）不是证据：它说明用户在往边界上想，不说明理解错了。下诊断还缺证据时，可以把它变成一道判断题请用户作答，答完再看要不要记；诊断记好以后，用户顺带提的疑问按工作方式里「顺带的疑问」处理，不要每个都展开成新的一轮。
findings 按主次排：第一条放最能解释全部证据的那个问题。问题类型一般记 1～2 条（正迁移、偏好、on-track 不占名额）；同一句话只当一条的证据，不要拿它再撑起另一种类型。

| 类型 | 典型证据 |
|---|---|
| memorized-wording 记言代学 | 能复述原句或名称，但换个说法就答不上；用户的表述和材料原文几乎一样 |
| upper-layer-loss 上层丢失 | 能说出某个例子，但讲不出共同规律；换一个情境就不会 |
| lower-layer-loss 下层丢失 | 能背规律，但给一个具体情况不知道怎么套 |
| mismatch 下上错配 | 把一个例子归到了错误的规律下，或用错的规律解释对的例子 |
| concept-confusion 概念混淆 | 把相邻概念当成一个；判别题里把 B 判成 A |
| missing-prereq 缺前置知识 | 讲解里用到的某个术语或概念用户不懂 |
| positive-transfer 正迁移 | 用户已经懂的知识可以直接复用（记下是哪个） |
| negative-transfer 负迁移 | 用户拿另一个领域的规律（日常经验、另一门学科、另一种语言）推新领域，推错了；证据里要写出是哪个旧领域的哪条规律。只是把本领域里几个典型例子的外形当成标准，记上层丢失或下上错配，不记负迁移 |
| prefers-examples / prefers-rules | 用户的明确表达，或两种讲法效果的差异 |
| on-track 无明显问题 | 前一次验证答对，且理由正确 |

## 3. 开处方
按方法论里的「诊断 → 处方」表选做法，写成 1～3 条具体动作，例如：
- 「准备一组对比例：闭包 vs 普通嵌套函数，各 2 个」
- 「先补前置知识点 scope」
- 「换说法提问：不用『词法环境』这个词，问它记住了什么」

缺前置知识时，如果缺的内容不在大纲里，考虑插入一个知识点（见 `plan-course` 的「学习中调整路线」）。

## 4. 记录
`diagnosis_record` 保存后模型进入「制定材料」。用一句话告诉用户你的判断和接下来的安排，语气要像教练而不是阅卷人，例如「你已经能认出典型的例子了，但边界情况还会混，我们接下来专门看几个容易混的。」判断可以引用用户自己说过的话，但不替用户总结错误规律。然后只接一个具体任务：对比例用理解练习题卡收集判断与依据，所有案例写全；补讲或简短核对后直接等待用户继续。
