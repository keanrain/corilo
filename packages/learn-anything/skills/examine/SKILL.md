# 验证模型（第 ⑤ 步）与复习

本技能处理正式验证和复习。收到「用途：理解练习（不计掌握度）」的作答时，按 coach-statements 的「理解练习题卡」反馈、追问和归纳，保留原阶段。

## 1. 请考官出题
`examiner` 看不到对话，任务说明里要写全：
- 知识点标题、模型（判别哪个概念 / 联结什么到什么）、参考规律（`kp_get` 里给导师看的那部分）；
- 用户的表述原话；
- 已有例子和做过的题（`kp_get` 的下层内容），要求考官避开它们；
- 要求的难度和题型。难度看 `verification_record` 上次返回的「下一题：难度 N 级」（或 `learn_status` 里的「下一道验证题」），第一题用 2 级。这个难度已经按用户的表现调整过，原样使用；只有紧跟在「【换题】」后面的那一道，才在当前难度上加一级或减一级（之后系统会从那道题的难度接着算，不要再重复加减）。把这一级的说明一起写给考官。题型也优先用它给的建议，此外：
  - 还没做过 discriminate-neg 或 rephrase 的，优先补上（熟练门槛需要）；
  - 诊断是概念混淆 → contrast；记言代学 → rephrase；上层丢失 → scenario / predict；
  - 已经熟练、冲精通 → transfer 或 own-examples；
- 用户的背景和兴趣（让情境贴近用户，但不要和已有例子重复）。
- 适合辨错时要求 `SpotError`，适合推演过程时要求 `OrderSteps`；它们和四种玩法都是作答形式，`questionType` 仍使用 scenario / predict 等原有题型。
- 四种玩法与题型分开，按目标选：
  - `Counterexample`（配 `discriminate-neg`）：选一个推翻说法的案例，并说出缺失条件；
  - `MinimalChange`（配 `scenario` / `contrast`）：给足机制，只改一个条件，其余原样，不做自动语义判分；
  - `DualPredict`（配 `predict`）：两场只变一个因素，用同一组选项分别预测；
  - `TransferTask`（配 `transfer`）：在实质陌生的新领域做实际决策，写清目标和约束，说明原规律为什么适用。
- 四种玩法已内含理由，不要再加 `Reason`；标准答案、应选案例、缺失条件、推荐改法和双局各自选项只留考官私有，题卡不出现；一次选对不自动算掌握。以上判分说明也不写进题面或 placeholder，让学习者直接完成任务。
- 排序任务说明只需给目标模型、完整输入和「排列 3～5 个输出事件」：例如 FIFO 给定入队过程和当前队列，让学习者排列接下来出队的事件；流程模型则排列本身有先后依赖的步骤。全部候选都要用到，通常按 predict / scenario 出题；若当前建议是 discriminate-neg，把反例辨认留给后续独立题。考官核对标准顺序后打乱候选，正确顺序或修正答案留在私有判分内容里。

`sources` 传本题参考规律实际依据的教材块 id 或已核对的 URL（从规律和例子的来源中选取），让考官读取原文核对。保存考官返回的【依据】，后续展示和判题沿用；没有教材依据时省略 `sources`。

## 心流节奏
出下一题前，先处理前置缺失、同一缺口反复出现或用户质疑重复练习的证据，按 diagnose 的“重新检查任务”处理；只有仍适合验证当前目标时才延续下述节奏。
验证阶段是一段连续的练习，目标是让用户沉浸进去：题目难度贴着能力走（系统按表现自动升降），每题之后立刻知道结果，始终知道离下一级还差什么，节奏由用户掌控。
- **答对或部分对，不停顿**：判题、记录之后，同一轮里马上给出下一题（见下面「并行预出题」）并 `quiz_show`。正文只用一两句话点评（指出这次对在哪里，或者部分对缺的那一步），不问「要不要继续」，不复述规律。
- **第一次答错，留在验证阶段，温和处理**：工具返回「留在验证阶段」时，先肯定答对的部分，只用一个反例或更小的追问让用户自己发现缺口（一两句，不展开诊断，不说教），然后按工具给的难度（已经降了一级，不要再降）继续出下一题，不要再重新诊断。答错是正常的。
- **回到评估学况的三种情况**：工具返回「回到评估学况」才按 `diagnose` 找原因——同一归因（都没有归因也算）连续两次答错、用户「稳」却答错（自信的误解），或在验证连续练习之外答错。诊断和补救后按工具给的难度重新验证（工具已经降过一级，不要再降）。
- **控制权在用户**：卡片上的按钮会发来这些消息——
  - 「【学习补给】」：按 diagnose 的“先补地基”补一个必要概念或起步例子，保留原题；收到求助时不判题、不记录验证、不重出题。自然语言说术语不懂或无法起步也走这条。
  - 「【求提示】」：按考官的【提示】给下一级提示（第一次给提示 1，第二次给提示 2，之后只能鼓励用户先试），只回这一两句，题目继续开着，不要重出题；
  - 「【换题】太简单了 / 太难了」：这题不判、不记录，难度加一级或减一级，请考官出新题；
  - 「【歇一会儿】」：用两三句话总结这次练到哪里（难度到了几级、离熟练还差什么），然后结束，不再出题。
- 作答消息里的「把握」记成 confidence（稳 sure / 有点把握 unsure / 蒙的 guess），hintsUsed 记这道题的提示和概念补讲次数：“提示：N 次”已包含卡片补讲，用户打字要的提示/补讲也要合并计入，不重复累计。有辅助的本题继续判题和反馈，之后用新情况检验独立应用；蒙对的不算稳定答对，系统会自动处理。

## 并行预出题
用户答完一道题后，同一步里同时发出两个调用，宿主并行执行，省下一次串行等待：
1. `verification_record`（照第 3 节）；
2. `examiner` 写下一题：难度用刚答的这道题的难度（即上次返回的「下一题：难度 N 级」），题型按上面的优先级，任务说明里把刚答的这道题也列进「避开」的已有题（它还没写入记录）。
两个结果都回来后：
- 判为答错：丢弃预出的题，不展示，按「第一次答错」或「回到评估学况」处理，之后按工具给的难度重新出题（这笔浪费是预期内的）；
- 答对或部分对，且返回的「下一题：难度」等于预出题所用难度：直接用这道题，`quiz_show`；
- 答对或部分对，但返回的难度与预出题所用的不同：丢弃，请考官按返回的难度重出；
- 模型已达标（不再有下一题）或进入下一个模型：丢弃预出的题，按下一个模型重新出题；
- 「【求提示】」「【学习补给】」「【换题】」「【歇一会儿】」和理解练习不判题，不要预出题。
预出的题在确认可用之前不展示、不提它；`verification_record` 失败（例如缺少真实作答）时同样丢弃。

## 2. 出题给用户
- 只把【题目】和作答方式给用户，标准答案和判分要点留在导师与考官之间。引题只说明在哪里作答；关键条件、选项取舍和结论留给用户判断，提示在求助后按级给。
- 考官给了【互动】时，调用 `quiz_show`：`ui` 原样传【互动】里的程序，`question` 传【题目】，`sources` 传【依据】中的引用。题卡会保留在右侧「学习」工作区，正文的练习入口可重新打开；正文里用一句话引出（「这道题在学习侧栏作答」），不要再把题目抄一遍，然后结束这一轮。用户作答后会发来以「【作答】」开头的消息，那就是回答原文。
- 以 `quiz_show` 成功返回作为“题卡已展示”的完成条件，每道后续题也一样；没有成功结果时，直接展示完整文字题面，再等用户作答。
- 本题涉及执行与等待、且有等待位置时，可加 `helpDemo: "execution-waiting"`，在补给入口挂载一个独立小演示；其他主题省略。该演示只认清两个区域，不代替原题的扩容、拒绝或直接交接规则。
- 错题重赛必须在这一步同时传 `quiz_show.retryOf`（`mistakes_get` 里的原验证 id），不能等到判题记录时才关联；否则题卡不会标为重赛，用户的作答也不会携带重赛记录。判题记录沿用同一个 id。
- `quiz_show` 报错，或者没有这个工具、考官没给【互动】时，把【题目】发给用户：选择题、判断题可以用 `ask_user_question`；需要解释理由的，请用户直接打字回答。
- 用户要提示时（包括打字说「给点提示」），按考官的【提示】逐级给，记下提示次数（hintsUsed，打字要的也算）。提示只给方向，不给结论。

## 3. 由宿主判题并记录
用户作答后直接调用 `verification_record`，传目标 kpId/modelId/factId、实际展示的完整 question、questionType、sources，重赛另传 retryOf。宿主从真实会话读取已展示题面与随后收到的学习者原文，独立调用考官核验题目、判题及新颖性。无需再调用一次 `examiner` 判题（同一步里调用的 `examiner` 只用来预出下一题，见「并行预出题」）；导师传入的 answer、verdict、hintsUsed、confidence、difficulty 不作为证据。
缺少真实题面/作答、考官不可用、输出不完整或暂缓判定时，工具拒绝写入。按错误说明补齐题面或依据，保留已有作答，再等用户继续；不把出题缺陷记成学习者的错。已经记录的同一条作答不能重复计分。

## 4. 记录
工具使用独立考官的结果和会话来源证据写入记录，重算掌握度和下一题难度；非新情境不计独立掌握，无来源证据的旧记录保留为历史、不计掌握。模型达标后开始安排间隔复习，并告诉你下一步：
- 达到熟练：肯定具体的进步，进入下一个模型或知识点；
- 答对或部分对、还没达标：按返回的难度和题型直接出下一题（见「心流节奏」和「并行预出题」）；
- 第一次答错：留在验证阶段，一个反例或追问，按降低后的难度继续；
- 同一归因连续答错，或「稳」却答错：把考官的反馈要点当作新证据，回到 `diagnose`。

给用户的反馈：先说对在哪里，错的地方用一个反例或追问让用户自己发现，最后才补充说明。
`verification_record.sources` 写入考官判题【依据】中的引用，反馈的关键说法旁保留对应来源。若考官发现原依据不支持标准答案，先核对并修正题目或答案，再判题记录；依据不足时明确说明，暂不记录判定。

`verification_record` 返回判题卡片引用；把 `[练习反馈](learn-card:...)` 原样独立成段，放在最终回答中具体反馈的合适位置，前后留空行，不放进思考或工具调用前的过渡文字。判题一返回，同一张卡片就会马上显示在判题那一步里，学习者不必等下一题；最终回答里的引用仍要写，它让卡片在这一轮收起后继续留在回答中。卡片包含对错、把握和结果对不对得上、心流位置、下一题难度、离下一级还差什么和归因示意；正文不用再念这些，专注在具体的对错和追问上。

## 复习（review_due）
- 知识类的卡：**不重复旧题**，按上面的流程请考官出一道新情况题。
- 信息类的卡：先从 `kp_get` 读取记忆卡 id，用记忆卡提问（questionType=recall），判题后在 `verification_record.factId` 写入本次考的卡 id。多张卡逐张检验，可以正反方向轮换着问；所有卡达标才算整个信息点熟练。
- 每天第一次会话先处理到期复习，再学新内容；复习项多时先做最久没复习的 5 项。

## 翻面自测与错题重赛
- 用户想先记一记信息类内容时，读取 `kp_get`，用 `flashcard_show({kpId, factId})` 展示已保存的事实。学习者先选把握、再翻面核对；闪卡是自测专用，可以揭晓这张卡的答案，正式互动验证题仍只含题面。
- 收到「【闪卡自评】」时，只按自测感受安排练习：选择「再练一次」的卡隔几题后再展示；选择「记住了」的卡进入后续独立回忆。自评不写 `verification_record`，不作掌握或用户亲自表述规律的证据。正式回忆另问一题，收集回答后按 recall 流程判题、记录 factId。
- 用户要巩固错题或当前练习需要补弱时，用 `mistakes_get({kpId, limit})` 读取仍有效的 wrong / partial 记录，选一条，请考官针对同一目标出新情境；把旧题和旧回答交给考官避开重复。`quiz_show.retryOf` 填旧记录 id（v-id），判题后的 `verification_record.retryOf` 沿用该 id，并保留原模型 id 或 factId。重赛沿用教材依据核对流程；反馈会展示旧、新回答，答对后该旧题不再推荐。
