# Corilo development constraints

[简体中文](AGENTS.zh-CN.md) | **English (maintained instructions)**

Updated 2026-11-15: notes, todos, and the learning tutor pin DSH 0.2.2-rc.3; validation is recorded at the top of docs/HANDOFF.md. The tutor is only a plugin for existing DSH users: no standalone launcher, dedicated profile initialization, or host default-preset/logging changes. It lives in packages/learn-anything with independent dependencies, lockfile, build, tests, and distribution, and is not part of the default notes + todos composition. Preserve root legacy-app scripts and dependencies; do not introduce npm workspaces. The Python prototype, its launcher, and dedicated CI were removed at the user's request. Preserve .local data and requirements-dev.txt, which other browser suites still use.

Current code: notes 0.7.0 and todos 0.6.4. New source instances enable both plugins and planner v2, including task dates, calendar events, time blocks, persistent reminders, and explicitly authorized browser notifications. Closing the page disables browser delivery. Preserve existing configurations and v1 compatibility. A v1 upgrade tool, recurrence, note-source links, and external push are not implemented. The current delivery scope in docs/PRODUCT-SPEC.md takes precedence over historical phases.

The architecture uses one Harness with notes and todos plugins, retaining the complete Files.md menus and native Harness Agent conversations. Read docs/README.md, PRODUCT.md, PRODUCT-SPEC.md, TECHNICAL_DESIGN.md, and DESIGN.md; English counterparts use .en.md. Commands are in docs/DEVELOPMENT.md. Original v0.34 phase plans are archived in docs/history/v0.34 and are not current delivery promises.

The default frontend is pinned upstream HTML/JS/CSS and CodeMirror 5/HyperMD under plugins/notes/vendor/filesmd, running in an independent iframe document. Authenticated Harness routes and workspace/ adapt it to host files. Preserve vendor sources, provenance, and all third-party licenses. Apply security, lifecycle, and storage differences through checked runtime transformations in workspace-api.mjs and the adapter layer. Do not connect Go sync, Telegram, or legacy Pi; upload materials externally; or relax host-wide CSP.

The older CodeMirror 6/Astryx page remains available as interface: classic. Its tests do not validate the default Files.md workspace. Earlier minimalist UI rules were superseded by the user's decision to preserve Files.md menus. UI and Agent Markdown tools share NotesStore and its queue. WorkspaceStore adds directory, attachment, and settings operations. Browsers do not access disk directly, and there is no second Agent loop.

New source instances load notes + todos planner. Existing single-plugin and v1 dual-plugin configurations retain their behavior without automatic rewrites, migrations, or deletion. corilo-import-todos previews by default; --apply explicitly imports into Later.md. Stop services and back up before applying. Read the source SQLite database without modifying it. Preserve cancelled records, links, and original fields in migration records; recoverable migration logs prevent duplicate appends. Preserve the original database and browser data. Never automatically replay old tasks or notifications.

Reuse Harness Web UI, model settings, sessions, default tools, and execution mechanisms. Do not build a separate Corilo Agent loop, model manager, permission system, or task-scheduling infrastructure. DeepSeek is the initial model provider. Prefer independent plugins and public extension points with pinned preview compatibility. Integration documentation and real runtime evidence must use the same version. Tool code alone does not prove Web/mobile integration. Harness execution-plan todos are not personal tasks; in-memory timers are not reliable reminders.

Content is ordinary Markdown and attachments. The first deployment target is local disk on an always-on Linux host, with NAS as a separate backup destination. Do not claim unverified SMB/NFS or bidirectional sync directories are supported workspaces. The personal edition does not require Supabase, a Corilo account, or GitHub binding. Existing Harness authentication, version protection, export, and notes/state backup tools each have limits; whole-instance consistent recovery and the target remote deployment need separate validation. Tailscale is a recommendation, not a completed deployment. Hardware, distribution, and access method remain unspecified; do not claim universal NAS or mobile compatibility.

plugins/notes is the current Files.md workspace; plugins/todos provides planner v2 and retains v1 compatibility. SQLite is authoritative for personal tasks, while Markdown checklists remain source text without automatic synchronization. Initialize planner in a new empty data directory; no old-database upgrade tool exists, and startup must not migrate schemas. Markdown checkboxes do not automatically generate tasks or reminders. Preserve old app/host, app/cloud, app/vendor, android, configurations, and data in place. Old Pi sessions, PostgreSQL tasks, and Harness sessions are different formats; do not replay historical tools. Preserve compatibility identifiers such as .personalos/, personalos fields, .local/xuye-prototype/, and .xuye-local/. Mark old documentation as historical rather than extending it as the current direction.

Use the existing checkout; do not create worktrees without authorization. Preserve unrelated changes. Commit and push authorized changes on a development branch, without force-push. Deployment, visibility changes, and destructive actions require their corresponding authorization. Keep the repository separate from the knowledge library. Test with synthetic data and credentials; never commit or print real secrets or user notes.

Repository boundaries: plugins/notes is the workspace package; plugins/todos has its own lockfile for tasks/calendar and existing instances. launcher/ is a source entry point and startup test suite, not a third distribution package. deploy/ contains manually reviewed deployment examples. scripts/ holds development and compatibility tools; scripts/corilo.mjs forwards to the current launcher. Root dependencies, lockfile, and npm start/test serve the legacy application, not plugin installation. Keep current documentation in docs/ and historical records in docs/history/. Preserve legacy implementation paths. Do not introduce workspaces, a shared runtime package, or automatic user-instance migrations for repository organization.

For legacy-app changes, run npm test. For plugin changes, run the applicable package tests and validate real Cordis/Harness loading and tool calls; a hand-written fake ctx does not establish integration. For file-interface or UI changes, also run python3 app/tests/browser_smoke.py, browser_review.py, and browser_sync.py. These protect the legacy app and do not replace actual Harness plugin browser tests. Preserve CSP and do not modify vendor code to hide failures. File tests must cover version conflicts, traversal/link rejection, and actual persistence.

For old cloud changes, run npm run test:cloud using only a disposable CORILO_TEST_DATABASE_URL. Worker/controller changes also require npm run test:worker with a real image and disposable PostgreSQL. Old cloud AI submissions remain disabled; personal-plugin integration does not authorize reopening them. Recovery controllers only clean up existing tasks; a missing journal is not proof a worker stopped. See app/cloud/CONTROLLER.md for detailed boundaries.

Record tests as passed only after execution. Distinguish plugin functions, real Cordis tools, Harness startup, browsers, real models, physical phones, and NAS evidence. Missing real credentials must not prevent independent development, but provider integration must not be fabricated. Reminder claims follow the implemented planner and its validation. External channels, automatic memory policies, retention, and payment services remain undecided; do not enable services or send email without authorization.
